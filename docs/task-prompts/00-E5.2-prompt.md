Task: Generalise the parser — drive `roadmap.py` from `paths.roadmap_dir` + `paths.roadmap_glob`, remove product assumptions from its docstrings, no configurable dialect (D15).

Requirements:
1. Change `load_tasks` to take the filename glob: `load_tasks(tasks_dir: Path, glob: str)`, selecting with `tasks_dir.glob(glob)` instead of `"*.md"`. `_FILENAME_RE` stays the phase authority — it still filters each selected file and extracts the phase from the filename prefix; the glob is only a pre-selection. (prompt-fixed: no default glob in `roadmap.py` — the single home for the default is `TOOLKIT_DEFAULTS.paths.roadmap_glob`, D17 — so the parser carries no product-specific pattern.)
2. Neutralise `roadmap.py`'s module docstring only: replace the hardcoded `docs/tasks/*.md` with "the configured roadmap directory", and drop the `03`/`02.5` phase-id examples for a generic "two-digit phase id, optionally `.` + digits". Do **not** touch `CITATION_RE` (`Design N`) — it is the documented citation channel (roadmap-format.md §8.1), not a product assumption.
3. Rewire every hardcoded `docs/tasks` consumer to the resolved `paths.roadmap_dir` (joined against the target root, absolute-wins per pathlib) and `paths.roadmap_glob`:
   - `aidw/workflows/prompt.py` `load_tasks` call (`repo.root / "docs" / "tasks"`) → resolve both leaves from the already-resolved `resolved_config`.
   - `aidw/workflows/prompt.py:_roadmap_lines` (`repo.root / "docs" / "tasks" / entry.file`) → join the resolved `roadmap_dir` instead. Thread the resolved value down through `_stage_evidence_pointer` → `_write_evidence_bundle` → `_render_evidence_bundle` as a **required** keyword-only parameter, matching the existing signatures (all four production call sites live inside `run()`, where `resolved_config` is in scope; the two direct test callers of `_write_evidence_bundle` are named under Tests). No default: a `docs/tasks` default would trip the Done-when `rg` gate, and re-resolving config inside the renderer is already ruled out. (prompt-fixed: pass the resolved value as a required parameter rather than re-resolving config inside the renderer.)
   - `aidw/cli.py` `tasks` command → resolve config with `load_target_config(target.root / "aidw" / "config.yaml")` + `resolve_config`, fail closed on ERROR issues (stderr + `EXIT_STAGE_FAILURE`, no output — mirror `config show`), then read the two `paths.` leaves.
4. Neutralise the remaining `docs/tasks` prose in `aidw/cli.py` `tasks`' docstring and `aidw/workflows/prompt.py`'s module docstring (the `docs/tasks/*.md` phrase). The D17 default `roadmap_dir="docs/tasks"` in `aidw/target_config.py` (and its `_target_path` docstring example) must **stay** — that is the single source of the default.
5. `aidw/cli.py` `tasks` must **not** run `validate_paths` or stage validation — it only needs the roadmap location; the E3.7 read-path existence check belongs to the workflow preflights.
