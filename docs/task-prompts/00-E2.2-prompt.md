Task: Target/layout guards — refuse to run when the target is the bare dir; fail when the workspace root is itself a registered worktree of the same repo (the clone-of-a-worktree trap, §3.2); warn when the state root falls inside a working tree.

Requirements:
1. New module `aidw/layout.py` (prompt-fixed location — §3.2/§3.10 fix the behaviours, not the module) with `check_layout(target: TargetRepo, workspace: WorkspacePaths) -> list[str]`: returns advisory warning strings, raises `LayoutError(RuntimeError)` for hard failures. Never writes and never runs mutating git — reuse the read-only `aidw/git.py:worktrees()` primitive.
2. Wire it into `cli.py:_roots` — the single `TargetRepo`/`WorkspacePaths` resolution site every command already calls — after `WorkspacePaths.resolve(target)`. Echo each returned warning to stderr; let `LayoutError` exit with `EXIT_REFUSED` and its message on stderr (mirror the existing `RepoNotFoundError` catch in `_roots`).
3. Bare-target refusal (keep, upgrade only): `TargetRepo.resolve` already raises `BareRepositoryError` (`aidw/paths.py:_resolve_worktree_root`) and `_roots` already maps it to `EXIT_REFUSED`. Do not re-check the bare dir in `check_layout`; only upgrade the message so it names the cause and carries the §3.2 corrective command (`git -C <bare> worktree add ../main main`) — the `-C` form works from any cwd, so the message adds no cwd instruction. The branch word is literally `main` (the §3.2 bootstrap example, matching `TargetRepo.base_branch`'s current default): no config-resolved `base_branch` exists at the raise site — E3 owns config resolution, and a bare dir has no working tree to read `aidw/config.yaml` from.
4. Clone-of-a-worktree trap (FAIL): raise `LayoutError` when `workspace.workspace_root` appears among the worktree paths of `git.worktrees(target.root)` AND that list has more than one entry — §3.2's literal detection rule ("if the resolved workspace root is itself a registered worktree of the same repository, fail"), so the FAIL fires from both positions of the rejected layout: from the plain clone itself (`workspace_root == target.root`, the clone's own entry plus its linked worktrees) and from a linked worktree hanging off that clone (`workspace_root` = the clone, `target.root` = the child, so `workspace_root != target.root` — the primary way users inhabit the layout, and exactly the position a `workspace_root == target.root` gate would silently pass). The more-than-one-entry gate exempts the blessed single-checkout plain clone (its sole `worktree` entry is itself), and the supported bare+worktree layout passes (its workspace root is the bare's parent, never listed). Both operands are already `.resolve()`d (`TargetRepo.resolve` resolves `target.root`, `WorkspacePaths.resolve` resolves `workspace.workspace_root`), so the comparison constructs no paths. The message names the cause and the §3.2 one-time re-bootstrap, retargeted at `<parent>` = the rejected clone's parent (`workspace.workspace_root.parent` — the clone is the trap dir in both positions; from the clone itself this equals `target.root.parent`) — a genuinely new location outside the rejected clone (never `<workspace>/bare.git`, which would nest the new layout inside it): `git clone --bare <origin> <parent>/bare.git` then `git -C <parent>/bare.git worktree add ../main main`, with `<origin>` from `aidw/paths.py:origin_remote()` — a public accessor this task adds to `aidw/paths.py`, exposing the existing private `_origin_remote` (same `repo_root -> str | None` contract: any git failure or missing `origin` returns `None`); `layout.py` must never import the underscore-private `_origin_remote` across a module boundary — no cross-module private import exists in `aidw/`, and this task does not introduce one. When `origin_remote()` returns `None` (no origin remote — a normal, supported configuration per the docstring), the clone source falls back to the detected rejected clone (`workspace.workspace_root`) (`git clone --bare <workspace_root> <parent>/bare.git`) so both bootstrap steps stay in the message with real values — never a `<remote>` placeholder, never an omitted clone step. The message also tells the user to abandon the plain clone and continue from the new control worktree (`<parent>/main`) — moving the old clone aside first if it already occupies `<parent>/main` (the §3.2 canonical trap names the clone `main`, in which case `<parent>/main` is taken until the old clone moves). Fail closed on the unverifiable list from every position: `git.worktrees()` returning `[]` after a successful resolve means git failed (a resolved non-bare working tree always lists at least itself), so raise `LayoutError` naming the unverifiable worktree list and the `git worktree list` failure — never treat `[]` as "no linked worktrees" and pass; no bootstrap command applies (nothing layout-side to correct). Membership detection consults `git.worktrees()` from every position, so each `_roots` invocation pays one `git worktree list` spawn — the same order as the git spawns `TargetRepo.resolve`/`WorkspacePaths.resolve` already make there; acknowledge the spawn in the diff (AGENTS.md Tests: no unmeasured git spawns on the `_roots` path) and do NOT reintroduce a short-circuit gated on `workspace_root == target.root` — that gate is what left the linked-child position silently unguarded.
5. State-inside-working-tree (WARN): return a warning when `workspace.state_root` is inside `target.root` (`target.root` is `state_root` or an ancestor — `Path.is_relative_to`), the §3.10 single-checkout case. Check against the working tree (`target.root`), never against `workspace.workspace_root`.
6. Ordering and path resolution: run the trap FAIL before the state WARN (the trap also places state inside a tree, but must fail, not warn); compare only `.resolve()`d paths — `git.worktrees()`, `TargetRepo.resolve` and `WorkspacePaths.resolve` already resolve, do not re-derive or compare raw strings.

Traps / prior review findings:
- Single-checkout false-positive: a plain clone with NO linked worktrees lists its own working tree as the sole `worktree` entry, so "`workspace_root` appears in the worktree list" alone would FAIL the legitimate single-checkout. Gate the FAIL on list membership (`workspace_root` appears in the `git.worktrees()` list) AND more than one worktree entry — the sole self-entry is the single-checkout's exemption — and never on `workspace_root == target.root`: a linked worktree hanging off a plain clone has `workspace_root` = the clone ≠ `target.root`, and is exactly the rejected-layout position that must FAIL.
- Warn against `target.root`, not `workspace.workspace_root`: in the supported layout state sits inside the workspace root by design (`<workspace>/.aidw/state/<slug>`) but outside every worktree — comparing `state_root` to `workspace.workspace_root` warns on the healthy layout.
- `workspace_root` comes only from `TargetRepo.common_dir.parent` (already resolved) — never `git_dir.parent` (wrong in a linked worktree) or `root.parent`; consume `workspace.workspace_root`, don't re-derive it.
- `git.worktrees()` returns `[]` on git failure, not "no worktrees" — for a repo that resolved successfully, an empty list means "couldn't verify"; fail closed rather than treating `[]` as proof the layout is clean.
- Don't add a second bare check: `BareRepositoryError` raises inside `TargetRepo.resolve`, before `_roots` ever reaches `check_layout` — a duplicate bare check there is dead code.
- Corrective commands must carry real values (detected `<bare>`, `<origin>`, parent-derived `<parent>`), never placeholders — the printed command must be copy-pasteable, including the no-origin case (Requirement 4: the clone source falls back to the detected `target.root`).

- E2.8 doctor checks (git ≥ 2.31, target-is-not-bare, control-worktree, workspace/state root) — separate task; E2.2's guards live in `_roots`, not `doctor`.
- E2.9 shared worktree fixture — keep E2.2's test fixtures local (mirror `tests/test_git.py`'s bare+control and `tests/test_workspace_paths.py`'s plain-clone helpers); don't extract the shared helper.
- No change to the state-root formula / `WorkspacePaths.resolve` (E1.3 owns it) — the warn only observes the already-resolved `state_root`.

Tests (what to prove, not the literal expects):
- Trap fail, both positions: plain clone `main` + one linked worktree hanging off it (the §3.2 rejected layout) → `check_layout` raises `LayoutError` in both cases: `target` = the clone (run from the clone) and `target` = the linked child (run from the child, where `workspace_root` = the clone ≠ `target.root`); the message contains the cause and the re-bootstrap `git clone --bare`/`worktree add` command.
- No-origin trap message: the same rejected layout with no `origin` remote configured → `LayoutError`; the re-bootstrap clone line uses the local `target.root` as its source, and no placeholder appears in the message.
- Corrective executes and re-resolves: run the printed re-bootstrap from the trap layout (moving the old plain clone aside first if it occupies `<parent>/main`), then re-invoke the CLI from the new control worktree (`<parent>/main`) → clean resolution: no `LayoutError`, no warnings.
- Unverifiable list fails closed: a repo where `git worktree list` fails (simulate the failure — e.g. monkeypatch `git.worktrees` to return `[]`) → `check_layout` raises `LayoutError` naming the unverifiable worktree list, never a clean pass — from the plain-clone position and from a linked-worktree target alike (membership detection consults the list from every position; no position's verdict is path-determined).
- Single-checkout warn, no fail: plain clone with no linked worktrees → `check_layout` returns a warning (state inside tree) and does not raise.
- Supported layout passes: bare + control worktree (+ optionally a task worktree) → no warnings, no raise.
- Bare refusal message: `TargetRepo.resolve(explicit=<bare>)` raises `BareRepositoryError` whose message now includes the `git -C <bare> worktree add` corrective command.
- Ordering: in the trap layout the outcome is a raise, never a warning.
- Purity/fail-closed: `check_layout` leaves the repo unchanged (worktree list and status identical before/after) and makes no writes.

Done when:

- The trap fails closed on the unverifiable list: `git.worktrees()` returning `[]` after a successful resolve raises `LayoutError` naming the unverifiable worktree list and the `git worktree list` failure (no bootstrap — nothing layout-side to correct); the CLI never proceeds on an unverified repo, from any position.
