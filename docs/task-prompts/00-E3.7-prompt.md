Task: Validate configured paths (fail closed) — classify every `paths:` entry as a read-path or write-target, fail closed on a missing read-path, and create write-targets on demand.

Requirements:
1. Classification lives in `aidw/target_config.py` (whose docstring already defers this: "`paths:` values are opaque strings; existence validation is E3.7's"). Add `READ_PATHS = ("build_results_template", "roadmap_dir", "task_prompts_dir", "implementation_results_dir")` and `WRITE_TARGETS = {"architecture_dir": "architecture"}` (field → writing stage id). `roadmap_glob` is a glob pattern, not a path — it belongs in neither list and must never be existence-checked.
2. `validate_paths(resolved, target_root) -> list[Issue]` — for each `READ_PATHS` field whose `ResolvedValue.is_set` is true, if `(target_root / value)` does not exist, emit an `ERROR` Issue whose message names `paths.<field>` AND the resolved path (the roadmap's "field and the path"). Read-only, no writes, no fallback; skip unset leaves defensively.
3. `ensure_write_targets(declared, resolved, target_root) -> list[Issue]` — for each `WRITE_TARGETS` field whose writing stage is enabled and whose path is absent or not a directory, `mkdir(parents=True, exist_ok=True)`; on failure emit an `ERROR` naming the stage. A disabled stage's write-target is skipped (no create, no issue). The directory value comes from `resolved["paths.<field>"].value` (skip when unset, as in Requirement 2) — `declared` supplies enablement only: every `PathsConfig` field is `str | None`, so the declared view is `None` on any config that does not set `architecture_dir`. Catch `OSError` (not broad `Exception`) around the `mkdir`.
4. Write-target enablement (prompt-fixed): a write-target's stage is disabled iff the declared config's `workflows.*.stages` contains a stage with `id == "architecture"` and `enabled is False`; otherwise enabled (matches the six-stage implement chain E4.1 preserves). Read `declared.workflows` (`StageConfig.id`/`.enabled`) directly — the resolved stage list omits undeclared stages and cannot carry the default.
5. Doctor: extend `_check_target_config` (`aidw/doctor.py`) so that after the loader + `check_compatibility` issues pass, it resolves once and unions `validate_paths(resolved, root)` into the same issues list before the FAIL/OK decision; reuse `resolved` for the schema-version line. Doctor stays read-only — never call `ensure_write_targets` or create a directory (§3.1).
6. Prompt preflight: in `aidw/workflows/prompt.py:run`, between the existing `check_compatibility` refusal and the `max_revisions` extraction, resolve once (`ConfigOverrides(max_revisions=max_revisions)`), run `validate_paths(resolved, repo.root)`, and refuse (exit 2, stderr via `format_issues`) on any issue — the same contract as the two config refusals already there. Then read `max_revisions` from that same `resolved`.
7. Gate impact: this tightens `uv run aidw doctor`. This toolkit repo already carries all four read-paths (`docs/tasks`, `docs/task-prompts`, `docs/implementation-results`, `docs/implementation-results/TEMPLATE.md`), so the gate stays exit 0; the doctor/prompt test fixtures do not (see Traps).

Traps / prior review findings:
- Two taxonomies share the word "write-target": §3.4's "four configured write-targets" is the gate-scope declaration (`implementation_results_dir`, `architecture_dir`, `roadmap_dir`, `task_prompts_dir` — R18), NOT this task's existence classification. The roadmap E3.7 classifies `implementation_results_dir`/`roadmap_dir`/`task_prompts_dir` as READ-paths; follow the roadmap list and never merge the two meanings.
- Missing config is valid: `load_target_config` returns an empty `TargetConfig` (no issues) when `<target>/aidw/config.yaml` is absent. Read-paths still resolve to D17 defaults, so a config-less repo's defaults ARE validated — don't fail on `source_path is None`, and don't skip default-sourced paths.
- `_check_target_config` currently resolves only after the early-FAIL return. Restructure to resolve once after loader+compat pass, then union path issues; adding a second check name breaks `tests/test_doctor.py::_named`'s uniqueness assertion.
- Existing fixtures are the blast radius: `_init_committed_repo`/`_make_supported`/`_make_plain_clone` (tests/test_doctor.py) and `_patch_prompt_repo` (tests/test_prompt_workflow.py) build repos without the four read-paths — every `run_doctor(...) == 0` and prompt-preflight test goes red after wiring. Add the read-paths to the shared fixtures (committed, so worktrees inherit them; `docs/implementation-results/TEMPLATE.md` satisfies both `implementation_results_dir` and `build_results_template`; a placeholder file makes `docs/task-prompts/` exist — git tracks no empty dirs). Never weaken the check to skip defaults (defeats D17/R7).
- Two config modules: `aidw/config.py` is agent config, `aidw/target_config.py` is target config. The new functions belong in `target_config.py`, which must not import `aidw.paths` (a test pins that boundary).
- Relative-vs-absolute: resolve with `target_root / value` — pathlib makes an absolute second operand win, so `docs/tasks` and `/abs/path` both resolve without special-casing.
