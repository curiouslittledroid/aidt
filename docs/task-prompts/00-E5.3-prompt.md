Task: Format validation with actionable errors — report the file, line and rule when an entry is malformed (a task with no `Done when`, a duplicate id, an entry outside an epic).

Requirements:
1. Add a pure validator to `aidw/roadmap.py`: `validate_tasks(tasks: list[RoadmapTask]) -> list[RoadmapIssue]`, plus a frozen `RoadmapIssue` dataclass (`file: str`, `line: int`, `rule: str`, `message: str`). It reports **exactly** three rules, whose tokens mirror the roadmap entry's wording: `missing Done when`, `duplicate id`, `entry outside an epic`. (prompt-fixed: the type/signature and the rule vocabulary — the spec names the three malformations but no API or token spelling.)
2. Detection per rule, from the parsed list only (no re-reading files):
   - `missing Done when` — `RoadmapTask.done_when == ""` (roadmap-format.md §6/§11).
   - `duplicate id` — two entries with the same `(phase, task)`; report the **later** entry's `file`+`line` and name the earlier `file:line` in the message. (prompt-fixed: keying on `(phase, task)` because `find_task` matches phase+task and the branch is `{phase}-{task}`; a task id may legally recur in another phase file.)
   - `entry outside an epic` — `RoadmapTask.epic_title is None` (roadmap-format.md §4).
3. `validate_tasks` is pure: no I/O, no mutation of the input list, deterministic and repeatable — it operates on `load_tasks` output, so the report path is `load_tasks(dir, glob)` → `validate_tasks(...)`. `RoadmapTask.line` is already 1-based; `file` is already the basename — use both as-is (matches `aidw tasks --show`'s existing `File: {file}:{line}`).
4. Surface it through `aidw tasks --validate` (new boolean option): run the same fail-closed config resolution the existing `tasks` body already does (`load_target_config` + `resolve_config`; ERROR issues → stderr + `EXIT_STAGE_FAILURE`), load entries, validate, and print **every** issue on **stdout** — one per line as `{file}:{line}: {rule} — {message}` — then exit `EXIT_USAGE` when any issue exists, `0` when clean. `--validate` runs inside the existing `tasks` body, so the existing `if not entries:` guard applies unchanged: a roadmap with zero parsed entries (missing dir or a glob selecting nothing — `load_tasks` returns `[]`) keeps the current behaviour (stderr `no roadmap tasks found` + `EXIT_USAGE`), it is **not** a clean pass; "clean" means a non-empty, issue-free list. (prompt-fixed: `aidw tasks --validate` is the surface; the roadmap entry names no command, and `aidw tasks` is the existing inspection command per design §11. Also prompt-fixed: keeping the empty-roadmap guard — an empty list is empty-not-error per `load_tasks`, and treating it as clean would be the same silent-pass hazard the fail-closed config trap above guards against. Also prompt-fixed: validation runs over the **full** `load_tasks` output irrespective of `--todo/--phase/--epic` — filters never narrow it (`filter_tasks` is not applied to validation), so `aidw tasks --validate --phase 07` still reports an issue in phase 00; when `--validate` is given it takes precedence — validate, print, exit — and the `show`/`next`/listing branches do not run. Also prompt-fixed: issue lines go to **stdout** — the repo's report convention (`agents validate`/`prompts check` print issue listings to stdout with a nonzero exit; stderr is the refusal channel for the config errors above and `no roadmap tasks found`), so redirection (`--validate > report.txt`) captures the report.)
5. `--validate` is additive: invoked without `--validate` the existing `--todo/--phase/--epic/--show/--next` paths behave exactly as before (with `--validate` the full-list validation in requirement 4 takes precedence), and on a clean roadmap it prints nothing and exits `0`. Do not wire validation into `aidw doctor`, the `aidw prompt` preflight, or `parse_file`/`load_tasks`' skip behaviour — the parser keeps "never reporting" (roadmap-format.md §10).
6. Update `aidw/roadmap.py`'s module docstring to state that it now also validates (design §11), and keep `from __future__ import annotations` (AGENTS.md). No change to `TASK_RE`/`DONE_RE`/`derive_epic`/`find_task`/`parse_file`/`load_tasks`.

Gate impact: no checker, status-vocabulary, or CI-gate change — the new flag and function are additive and covered by `uv run --frozen pytest`. The five AGENTS.md gates (`uv sync --frozen`, `uv run --frozen pytest`, `uv run aidw doctor`, `uv run aidw agents validate --strict`, `uv run aidw prompts check`) still apply and are the record stage's to run and report.

Traps / prior review findings:
- "Outside an epic" means `epic_title is None`, **not** `epic` — `epic` is always derived from the id (`derive_epic`) and is never `None`, so keying on `epic` flags nothing (roadmap-format.md §4/§11).
- Duplicate detection must key on `(phase, task)`, not `task` alone — `00-E5.3` and `01-E5.3` are distinct branches (`{phase}-{task}`); a task-id-only key false-positives across phase files (`find_task` matches phase+task).
- Don't fold validation into `parse_file`/`load_tasks` — §10 says the parser "never reports"; making it raise/warn would change `aidw tasks`, the `aidw prompt` preflight and `find_task` behaviour for existing callers.
- Report **every** issue, not the first — the Done-when is "each malformed case names the file, line and rule"; an early `return` fails it.
- `--validate` must reuse the existing `tasks` command's fail-closed config resolution, or a broken `aidw/config.yaml` silently validates the wrong (or empty) roadmap instead of failing closed (E3.2/E3.3).
- Don't apply `filter_tasks` before `validate_tasks` — validating the filtered subset silently misses issues outside the filter (a duplicate whose earlier entry is in another phase becomes unverifiable); validation reads the full `entries` list (requirement 4).
- The collapsed-id trap (`**E0.1 Create …**` → id `E0`) is **not** a fourth rule — E0.7's one-line guard and `tests/test_roadmap_format.py::test_example_has_no_collapsed_id` already cover it; do not add a rule the spec does not enumerate.

Explicit non-goals — do NOT do these in this task:
- E5.4 (promote `tests/test_roadmap.py`'s FIXTURE into `docs/roadmap-format.md` as the single source) — separate; do not move the fixture.
- Heading/epic *pairing* mismatch (`derive_epic` ≠ the `## Epic` heading) — roadmap-format.md §4 says "nothing enforces the pairing"; only the three named malformations are validated.
- Wiring validation into `aidw doctor` or the `aidw prompt` preflight — E5.3 is the reporting surface (`aidw tasks --validate`), not a new gate or refusal.
- The collapsed-id trap as a validation rule (see Traps).
