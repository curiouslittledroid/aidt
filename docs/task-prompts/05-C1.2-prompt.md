Task: Resolve gate commands from the target's actual gates heading, and diagnose misses

Requirements:
1. `_gates_section` (aidw/workflows/prompt.py) recognises **two** headings, not one: the canonical `## Gates` plus the alias `## Gate commands`, matching the existing `startswith` semantics (so `## Gates — run exactly these` still matches) and still ending the section at the next `## ` heading. `_GATES_HEADING` becomes a tuple — the shared constant requirement 4 defines in `aidw/prompts.py`, imported into `aidw/workflows/prompt.py` under that name; there is no second literal set of recognised headings anywhere. (design §7.3 step 4)
2. `_gate_block` passes each conventions source's text through `_gates_section` unchanged in D16 order (`AGENTS.md`, then `aidw/conventions.md`); a repo whose conventions use `## Gate commands` now contributes its commands instead of degrading. (design §7.3 step 4)
3. Config-declared heading (prompt-fixed — see ask-if-ambiguous): add an optional top-level `config.yaml` key `gates_heading` (string, default unset), accepted by `aidw/target_config.py` (`TOP_LEVEL_KEYS`, a field on `TargetConfig`, parse via the existing string helpers, `to_dict` round-trip). The value is the **full heading line including its `## ` prefix** (e.g. `gates_heading: "## Verification gates"`): when set it is recognised as an additional `## `-level heading, matched verbatim by the same `startswith` rule — never a bare title the code prefixes — and both the docs field table's Effect cell and the JSON-schema description show a `## `-prefixed example. An empty value is one loader ERROR naming `gates_heading` with the value dropped (the `model`/`paths.roadmap_glob` non-empty-string precedent): `_read_str` passes `""` through for optional keys, and `line.startswith("")` matches every line. `_gates_section` stays pure (the extra heading is passed in); `_gate_block` loads it via `load_target_config(repo.root / "aidw" / "config.yaml")` — the target root, never the toolkit root.
4. The recognised-heading set is a single shared constant plus pure helpers in `aidw/prompts.py` — their only definitions: the "gates-like heading" heuristic (contains "gate", case-insensitive) and the "recognised heading" predicate (one `startswith` test of a line against the constant plus a passed-in extra heading; never `==`), which both readers route their recognition through; `aidw/workflows/prompt.py` imports the constant as `_GATES_HEADING` and `aidw/doctor.py` imports the same objects directly, so the two readers cannot drift on the heading set or the comparison, and no second literal set of recognised headings exists in either reader. Update the `read_conventions_sources`/`CONVENTIONS_SOURCES` comments that still say `## Gates`.
5. `aidw/doctor.py` gains a `gates heading` check (WARN, never FAIL; shape mirrors `_check_architecture_trigger`) that reads the target's conventions sources and, for each `## `-level heading that looks gates-like (contains "gate", case-insensitive) but is **not** recognised, reports a WARN naming the source file and heading, and the two fixes: rename to `## Gates`/`## Gate commands`, or declare `gates_heading`. "Recognised" is decided by the shared predicate with the same `startswith` prefix rule as `_gates_section` — the shared tuple plus the configured `gates_heading`, never `==` — so a suffixed canonical heading such as the toolkit's own `AGENTS.md` `## Gates — run exactly these, and only these` stays silent. A missing/unreadable config or source degrades to "nothing to report", never a crash. (design §8.1)

Traps / prior review findings:
- Keep `startswith`, don't switch to `==` — in the bundle reader *and* the doctor's recognised test: the existing fixture `## Gates — run exactly these, and only these` must keep matching, and `==` in the doctor would WARN on the toolkit's own `AGENTS.md` heading (the same suffixed shape) while every bare-heading test stays green (tests/test_prompt_workflow.py `AGENTS_EVIDENCE_FIXTURE`).
- Case is deliberate: `## Gate Commands` (capital C) is **not** `## Gate commands`; it must degrade in the bundle *and* trigger the doctor WARN — do not silently lowercase headings (the spec fixes the two literal strings).
- The doctor check must load the configured `gates_heading` before deciding something is unrecognised, or a repo that declares its heading still gets warned (aidw/doctor.py `_check_architecture_trigger` shows the config-load pattern).
- Two roots: `_gate_block` reads `repo.root`, and the `gates_heading` load must also be `repo.root`-relative; reading the toolkit's own config would pass every self-hosted test and break only after extraction.
- Config key wiring is fail-closed: `gates_heading` must enter `TOP_LEVEL_KEYS` or a config using it is refused as an unknown key, and `docs/schema/aidw-config.schema.json` has `additionalProperties: false`, so it must gain the key too.
- The doctor WARN is advisory: a repo using a non-standard heading still works (degrade is a normal state), so this is WARN, never FAIL, and never blocks `run_doctor`'s exit code.
