Task: Port consumers and delete the old helpers (`aidt_root()`/`runs_dir()`).

Requirements:
1. Delete `aidt_root()` and `runs_dir()` from `aidw/paths.py`, and drop the "transitional
   aliases until E1.4" note in its module docstring. `toolkit_root()`, `TargetRepo`,
   `ToolkitPaths`, `WorkspacePaths` already exist (E1.1–E1.3) — reuse them; add no new root type.
2. The Done-when `rg "aidt_root|runs_dir" aidw/` is **literal**: after this task it must match
   nothing under `aidw/`, including surviving parameter/local names — not just the two deleted
   functions. Rename `aidt_root` → `toolkit_root` and `runs_dir` → `runs_root` wherever they
   remain as identifiers (`runner.py` `resolve_prompt`/`run_stage`, `config.py`, `inventory.py`,
   `state.py`, the workflows, `cli.py`).
3. Run artifacts move to the state root: every site that today computes `aidt / "runs"` or
   `toolkit_root() / "runs"` resolves `WorkspacePaths.resolve(TargetRepo.resolve(repo)).state_root
   / "runs"` instead (§3.10 + E1.3's per-repo `state_root` field). Sites: the five workflow run
   bodies, `cli.py` `_run_dir`/`exec`/`runs`, and `runner.py` `run_stage`. Also fix the `exec`
   command's `rendered: aidt/runs/…` echo to print the state-root-relative path.
4. `run_stage`'s silent `aidt_root / "runs"` fallback must go: the runs directory becomes an
   explicit argument, and every caller (the five workflows + `cli.py` `exec`) passes the same
   `runs_root` it used for `create_run`/`run_dir`. No toolkit-root default remains.
5. `repo_root()` semantics, the `TargetRepo`/`ToolkitPaths`/`WorkspacePaths` fields, and the
   `(repo: Path, aidt: Path)` workflow/CLI signatures are unchanged this task (typed threading is
   E1.5). `aidt` still locates toolkit assets (prompts, agent-configs, scripts); only the *runs*
   location changes.
6. Tests: rewrite `tests/test_paths.py` (remove the `runs_dir` import and
   `test_runs_dir_is_under_the_toolkit_root`; keep the other four); repoint tests importing
   `aidt_root` → `toolkit_root` (`tests/test_runner.py`, `tests/test_prompt_workflow.py`,
   `tests/test_inventory.py`, `tests/test_prompts.py`).
7. Repoint the workflow tests' run-location assertions and their `_Recorder` doubles
   (`tests/test_{implement,review,fix,approve}_workflow.py`) from `tmp_path / "aidt" / "runs"` to
   the state root. `_init_repo` sets no `origin`, so `repo_slug == tmp_path.name` and runs land at
   `tmp_path/.aidw/state/<tmp_path.name>/runs` — derive it via
   `WorkspacePaths.resolve(TargetRepo.resolve(tmp_path)).state_root / "runs"` rather than
   hardcoding an unpredictable basename.

Traps / prior review findings:
- `run_stage` re-derives its own write directory from a `runs_dir` default (`runner.py:121`) while
  the workflows separately compute `runs_dir = aidt / "runs"` and never pass it to `run_stage` —
  they only agree today because `aidt == aidt_root`. After the move, pass the SAME `runs_root` to
  `create_run`, the logger's `run_dir`, and `run_stage`, or `state.json`/rendered prompts land in
  two different directories.
- The literal `rg` gate trips on parameter names, not just the deleted functions: `state.py`'s five
  `runs_dir` params and `config.py`/`inventory.py`/`runner.py`'s `aidt_root` params must be renamed
  too. A "delete the two functions" reading leaves the gate red.
- Single-checkout tests are §3.10-correct: with no `origin` remote, `state_root` lands *inside* the
  working tree (`tmp_path/.aidw/state/<name>`). That is expected (E2.2 warns on it later) — don't
  "fix" the test to a sibling dir.
- Don't re-run git inside `WorkspacePaths.resolve` or derive `workspace_root` from `git_dir.parent`
  — E1.3 already resolves from `repo.common_dir`; E1.4 only resolves `TargetRepo` once at the
  workflow/CLI boundary (E1.5 hoists it). Per-stage re-resolution wastes calls and can diverge.
- `aidw/github.py:repo_slug` (slash form, `gh`-based, may be `None`) is unrelated; E1.4 uses
  `WorkspacePaths.repo_slug` only.
- `tests/conftest.py` cleans `toolkit_root() / "runs"`; after E1.4 nothing writes there. Keep or
  repoint it as a stale-artifact sweep — but that is a tests/ concern, not `aidw/`.
