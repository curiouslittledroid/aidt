Task: Port consumers and delete the old helpers (`aidt_root()`/`runs_dir()`).

Requirements:
1. Delete `aidt_root()` and `runs_dir()` from `aidw/paths.py`, and drop the "transitional
   aliases until E1.4" note in its module docstring. `toolkit_root()`, `TargetRepo`,
   `ToolkitPaths`, `WorkspacePaths` already exist (E1.1–E1.3) — reuse them; add no new root type.
2. The Done-when `rg "aidt_root|runs_dir" aidw/` is **literal**: after this task it must match
   nothing under `aidw/`, including surviving parameter/local names — not just the two deleted
   functions. Rename `aidt_root` → `toolkit_root` and `runs_dir` → `runs_root` wherever they
   remain as identifiers (`runner.py` `resolve_prompt`/`run_stage`, `config.py`, `inventory.py`,
   `state.py`, the workflows, `cli.py`) — parameter/local names **and** call-site keywords
   alike: every `run_stage(..., aidt_root=…)` call (the five workflows, `cli.py` `exec`)
   switches to `toolkit_root=` and gains the new required `runs_root=` (Requirement 4).
   That includes `doctor.py`: its `aidt_root` import and
   the `aidt = aidt_root()` call backing `_check_prompts`/`_check_agent_configs` switch to
   `toolkit_root()` — runs-independent toolkit-asset checks under the Requirement 5 rule
   (`aidt` still locates toolkit assets; only the *runs* location moves), so no state-root
   threading there.
3. Run artifacts move to the state root — resolve-once-and-thread, not per-site
   re-resolution: each entry point that today computes `aidt / "runs"` or
   `toolkit_root() / "runs"` — the five workflow `run()` bodies (prompt.py's fallback line
   included) and the CLI's `exec`/`runs` commands, right after `_roots()` — resolves
   `TargetRepo` → `WorkspacePaths` ONCE per invocation, binds ONE `runs_root =
   WorkspacePaths.resolve(TargetRepo.resolve(repo)).state_root / "runs"` (§3.10 + E1.3's
   per-repo `state_root` field), and threads that SAME value to `create_run`, the
   `RunLogger`/`state_mod.save` run dir, `run_stage`, `list_runs`/`find_run`, and the
   workflows' `_latest_*_run`. `runner.py` `run_stage` and `cli.py` `_run_dir` never resolve
   `TargetRepo` themselves — they receive the threaded `runs_root` (Requirement 4);
   re-resolving per site costs extra git calls and can split the run. `_run_dir(run_id)`
   cannot stay as-is (its `toolkit_root()` body would
   split the run): give it the runs root — `_run_dir(runs_root, run_id)` → `runs_root / run_id` —
   or drop it for `state_mod`'s `run_dir(runs_root, run_id)`; that delta is in scope (Requirement
   5 freezes only the `(repo, aidt)` command/workflow signatures). Also fix the `exec` command's
   `rendered: aidt/runs/…` echo to print the state-root-relative path.
4. `run_stage`'s silent `aidt_root / "runs"` fallback must go: the runs directory becomes an
   explicit argument, and every caller (the five workflows + `cli.py` `exec`) passes the same
   `runs_root` it used for `create_run`/`run_dir`. No toolkit-root default remains. The new
   signature, literally: `run_stage(spec, *, repo_root, toolkit_root, state, logger,
   agents=None, dry_run=False, retry_transient=None, show_progress=None, runs_root)` —
   `aidt_root` → `toolkit_root`, and `runs_dir: Path | None = None` becomes the required
   `runs_root: Path` (delete the `runs_root = runs_dir if runs_dir is not None else …`
   fallback line). `resolve_prompt` renames in lockstep: `resolve_prompt(toolkit_root, value)`
   (its test/CLI call sites are positional, so only the parameter moves).
5. `repo_root()` semantics, the `TargetRepo`/`ToolkitPaths`/`WorkspacePaths` fields, and the
   `(repo: Path, aidt: Path)` workflow/CLI signatures are unchanged this task (typed threading is
   E1.5). `aidt` still locates toolkit assets (prompts, agent-configs, scripts); only the *runs*
   location changes. The freeze covers those public command/workflow signatures only — the
   runs-dir deltas Requirements 3–4 state (`run_stage`'s explicit `runs_root`, `_run_dir`'s
   runs-root parameter or removal) belong to this task, not E1.5 — and so does `prompt.py
   run()`'s optional test-injection parameter `runs_dir: Path | None = None`, which renames to
   `runs_root: Path | None = None` (still optional; `repo`/`aidt` untouched): the literal
   Requirement 2 gate bans the old name under `aidw/`, so the rename is this task's, not
   frozen and not E1.5's.
6. Tests: rewrite `tests/test_paths.py` (remove the `runs_dir` import and
   `test_runs_dir_is_under_the_toolkit_root`; keep the remaining tests:
   `test_toolkit_root_holds_the_shipped_assets`, `test_toolkit_root_is_the_package_parent`,
   `test_toolkit_root_matches_repo_root_in_this_checkout`, `test_toolkit_root_is_independent_of_cwd`,
   and `test_repo_root_from_explicit_start`); repoint tests importing
   `aidt_root` → `toolkit_root` (`tests/test_runner.py`, `tests/test_prompt_workflow.py`,
   `tests/test_inventory.py`, `tests/test_prompts.py`, `tests/test_agents.py`,
   `tests/test_config.py`) — the complete set of tests importing/calling the deleted helper
   (`repo_root` imports stay). Then rename the test-side keyword call sites to match the new
   signatures, not just the imports: in `tests/test_runner.py`, every `run_stage(...)` call
   switches `aidt_root=` → `toolkit_root=` and `runs_dir=` → `runs_root=`; in
   `tests/test_prompt_workflow.py`, every `prompt_workflow.run(..., runs_dir=…)` kwarg
   (about fifteen calls) switches to `runs_root=` per the renamed Requirement 5 parameter.
   No other test passes these kwargs, and the positional helpers (`create_run`,
   `state.run_dir`/`list_runs`/`find_run`) need no call-site change. A missed kwarg fails the
   suite as `TypeError: unexpected keyword argument`, so this is part of the same task.
7. Repoint the workflow tests' run-location assertions and their `_Recorder` doubles
   (`tests/test_{implement,review,fix,approve}_workflow.py`) from `tmp_path / "aidt" / "runs"` to
   the state root. `_init_repo` sets no `origin`, so `repo_slug == tmp_path.name` and runs land at
   `tmp_path/.aidw/state/<tmp_path.name>/runs` — derive it via
   `WorkspacePaths.resolve(TargetRepo.resolve(tmp_path)).state_root / "runs"` rather than
   hardcoding an unpredictable basename.

Traps / prior review findings:
- `run_stage` re-derives its own write directory from a `runs_dir` default (`runner.py:121`) while
  the workflows separately compute `runs_dir = aidt / "runs"` and never pass it to `run_stage` —
  they only agree today because `aidt == aidt_root`. After the move, pass the SAME `runs_root` to
  `create_run`, the logger's `run_dir`, and `run_stage`, or `state.json`/rendered prompts land in
  two different directories.
- The literal `rg` gate trips on parameter names, not just the deleted functions: `state.py`'s five
  `runs_dir` params and `config.py`/`inventory.py`/`runner.py`'s `aidt_root` params must be renamed
  too. A "delete the two functions" reading leaves the gate red.
- Single-checkout tests are §3.10-correct: with no `origin` remote, `state_root` lands *inside* the
  working tree (`tmp_path/.aidw/state/<name>`). That is expected (E2.2 warns on it later) — don't
  "fix" the test to a sibling dir.
- Don't re-run git inside `WorkspacePaths.resolve` or derive `workspace_root` from `git_dir.parent`
  — E1.3 already resolves from `repo.common_dir`; E1.4 only resolves `TargetRepo` once at the
  workflow/CLI boundary (E1.5 hoists it). Per-stage re-resolution wastes calls and can diverge.
- `aidw/github.py:repo_slug` (slash form, `gh`-based, may be `None`) is unrelated; E1.4 uses
  `WorkspacePaths.repo_slug` only.
- `tests/conftest.py` cleans `toolkit_root() / "runs"`; after E1.4 nothing writes there. Keep or
  repoint it as a stale-artifact sweep — but that is a tests/ concern, not `aidw/`.

Explicit non-goals — do NOT do these in this task:

  `(repo, aidt)` tuple, add `AIDW_REPO`, re-point `_run_dir` to typed resolution) — separate task;
  keep `(repo, aidt)` here. E1.5's re-point is *typed* (derive from threaded `WorkspacePaths`);
  E1.4's untyped `_run_dir(runs_root, run_id)` stopgap (Requirement 3) is what it replaces.

- E2.7 run lock into the state root (`locks/<branch>.lock` in §3.10) — later task.
- E3.x config-driven `paths.state_root` (D17) — E1.4 keeps the hardcoded three-tier formula.
- Migrating historical `aidt/runs/` (EXTRACTION.md §3.10 "not migrated; gitignored and historical").
