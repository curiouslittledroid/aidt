## Decisions already taken (owner, task 05-P1.1) — implement these, do not re-open them

The prompt review that preceded this revision blocked on ambiguity, not on a defect. Each
choice below was put to the owner and decided; the requirements then make it executable.
Where a decision names a primitive, key or tuple, that value is **fixed** — do not
substitute a different one.

- **D1 — F5 is a core post-loop stage.** id `F5`, runtime name `commit-and-push`, agent
  `pr-publisher`, prompt `fix-commit.md`, `variables=("{pr}",)`, placed in `_FIX.post_loop`
  **after** `_ROADMAP_TICK_STAGE`. `STAGE_IDS` gains `"F5"`; `REPO_OPTIONAL_IDS` stays
  `{I3, I4}` (F5 is core: removal, disable and reorder rules apply). F5 carries **no `when=`
  token**: it is not `WHEN_EVIDENCE_GREEN` and it is not conditioned on I7's outcome.
- **D2 — F5's trigger is loop convergence, not green evidence.** `fix`'s `WHEN_EVIDENCE_GREEN`
  (`tick_evidence`: converged **and** every `iter{N}-test` `SUCCEEDED` **and**
  `latest_verdict == Approve`) stays I7's *completion claim* only. A converged run whose tick
  was withheld by Z7's unmet-conclusion check, an empty run (`latest_verdict is None`), and a
  run whose roadmap target could not be resolved are **all** non-green — and their fix edits
  must still land, or this task reproduces the defect it exists to fix. So F5 runs whenever
  the loop converges, after I7 has succeeded **or** been recorded as skipped, for any skip
  reason.
- **D3 — the four-case execution table.** `closed_issues` is the run's own accumulated list
  (`fix.py`), never a `gh` query and never a count of `Status: fixed` comments.

  | tree at F5 | `closed_issues` | F5 behaviour |
  |---|---|---|
  | dirty | ≥ 1 | commit the accumulated change set (the fix edits plus the tick if I7 flipped) and push; verify; record `head_sha`; run continues, exit 0 |
  | dirty | 0 | **skip** — reason "this run closed no issue; the working-tree changes are not this run's". Never commit: unowned dirt is not F5's to publish (§13 preserves unrelated user changes) |
  | clean | 0 | **skip** — the roadmap's successful no-op. No empty commit, no push, exit 0 |
  | clean | ≥ 1 | **fail closed** (exit non-zero): issues were closed but there is nothing to push, which is exactly the untruthful state this epic removes. Message names the PR number and the branch; `head_sha` absent. P1.2 (close only after the push) makes this case unrepresentable later; until then it must be loud |

- **D4 — a stopped loop never commits and never pushes.** Every stop path (max-iterations, a
  denied gate, an ambiguous or `Blocked` verdict, an unparseable manifest, a failed stage)
  returns before the post-loop. `stop()` is the **one** helper that already records I7's skip
  for all of them: extend that single call site so it records F5's skip too, with the same
  stop reason — do not add a `record_skipped` call at each `return`. A failed I7 **stage** (or
  a failed `settle_roadmap_tick` postcondition) keeps today's behaviour: the run fails with
  exit 1 and F5 is neither planned nor recorded, because committing a half-applied tick is
  worse than leaving the tree for a human.
- **D5 — the agent executes commit and push; Python verifies.** The agent runs
  `git add -A` and `git commit` (conventional-commit subject with the task id when known,
  matching `prompts/pr.md`'s `## Commit`) and `git push origin <branch>`. No `-u`, no
  `--force`, no `--force-with-lease`, never a merge. `<branch>` is the PR head the run already
  resolved (`pr_info["headRefName"]`, decision K1, the located PR-head worktree) — never
  `git.current_branch` of the control root, which is on `main`. **Refuse before pushing when
  `<branch>` equals `repo.base_branch`**, so a misresolved ref can never push `main`.
- **D6 — the pushed proof is pinned.** After the stage, the workflow compares
  `git.rev_parse(worktree, "HEAD")` with `git.rev_parse(worktree, "origin/<branch>")` — **no
  fetch**: a successful `git push` updates the remote-tracking ref, `rev_parse` already exists
  in `aidw/git.py`, and this stays offline in the test fixtures. Never `git ls-remote` (the
  toolkit has avoided it: `tests/test_implement_workflow.py` asserts it is absent from the
  implement prompt), never a `status`/`log` heuristic. Unequal, missing, or a
  non-`SUCCEEDED` F5 record all fail the run (exit 1) with a message naming the PR number and
  the branch — never a silent success (the O1 precedent).
- **D7 — `state.pr` keys are fixed.** `state.pr["head_sha"]` is the **verified remote** SHA
  (`origin/<branch>` at verification time), written **only** when the equality in D6 holds.
  A skip writes `state.pr["commit_skip_reason"]` (mirroring Z2's
  `roadmap_tick_skip_reason`), and the skipped `StageRecord` carries the existing
  `SKIP_REASON_KEY` in `artifacts`. No third key: `head_sha`'s presence *is* the boolean, so
  do not add a `committed`/`pushed` flag.
- **D8 — `variables=("{pr}",)` and nothing new is threaded.** The branch and the task id are
  read inside the worktree (`git branch --show-current`, `state.task`), exactly as
  `prompts/pr.md` does. `_tick_spec`, `_planned_iteration` and the dry run gain no new field,
  and `{task_id}` keeps its I6-only meaning (the branch form `03-H3.1`) — do not reuse it here.
- **D9 — the agent contradiction is fixed at the source.** Edit
  `agents/pr-publisher/AGENTS.md` so its hard rules are scoped by prompt: `/pr` commits,
  pushes, opens the PR and backfills the build-results line; `/fix-commit` commits and pushes
  **only** — no `gh pr create`, no body sections, no build-results edit — and the stage prompt
  decides which set applies. This is a **content** edit of an existing agent file, not the
  `agent-configs/pr-publisher.yaml` / allowlist change the non-goals forbid. Prompt text alone
  does not reliably override an agent file's hard rules; the file is the thing to change.
- **D10 — the dry run is unconditional.** `--dry-run` plans `commit-and-push [planned]`
  exactly once, after `update-roadmap`, and evaluates **no** evidence: it does not inspect the
  tree, does not commit, does not push, does not verify, and does not withhold F5 even where a
  real run would fail D3's fourth case — the same "a dry run never withholds" rule I7 already
  follows.
- **D11 — the docs move in this change.** design.md §8.4's diagram gains
  `→ F5 commit-and-push` and its "The edit stays uncommitted: no stage of `fix` commits"
  sentence is reversed; §13's commit-ownership bullet names **both** `I6` `pr` and `F5` as
  owners of the documented `git add -A` executed by the `pr-publisher` agent; §17 gains exactly
  **one** row `Z9` recording (a) the reversal, (b) P1.2's close-after-push ordering, and
  (c) these prompt-fixed decisions D1–D10 as a clause (Z2's "Prompt-fixed decisions" is the
  precedent); and the §18 row "The fix-loop prompts leave their changes uncommitted" is
  updated **in this task** to a resolved status whose notes state the F5 boundary — leaving it
