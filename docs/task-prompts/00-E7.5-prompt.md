Task: `inventory.py`: separate the toolkit's default prompts/scripts from the prompts resolved for a target repo. Keep the `.pi/prompts` sentinel.

Requirements:
1. Split `aidw/inventory.py`: rename today's `check` to `check_defaults(toolkit_root)` with behaviour unchanged — `REQUIRED_PROMPTS` + `REQUIRED_SCRIPTS` present under `<toolkit>/prompts/`, the `.pi/prompts` sentinel (`FOREIGN_PREFIX`) over every `.md`/`.py`/`.json` there, `AIDW_SCRIPTS_DIR` in each `PROMPT_INVOKED_SCRIPTS` prompt, and the `LEGACY_MANIFEST` (`VENDOR.md`) warning. Keep all five constants and their semantics exactly (§7.2 "keep the sentinel").
2. Add `check_resolved(toolkit_root, target_root)`: for each name in `REQUIRED_PROMPTS`, resolve via the §3.6 precedence by **reusing `runner.resolve_prompt`** (never reimplement the shadow/default order), record shadow-vs-default provenance, and apply the sentinel sweep to the target override files (`<target>/aidw/prompts/*.md`) that `check_defaults` never sees. An unresolvable required prompt (no shadow, no default) is an ERROR naming the searched locations. Scripts are **not** in the resolved half (§3.6: they stay toolkit-side).
3. Make `aidw prompts check` target-aware: call `_roots()` (like `agents validate`) instead of `ToolkitPaths.resolve().root`, run `check_defaults` and `check_resolved` independently, and print each group under a distinct heading naming "toolkit defaults" vs "resolved repo prompts" (with the target path). The resolved group must name each required prompt's source (target shadow path vs toolkit default path). Report to stdout, following the `agents validate`/`prompts check` convention; exit non-zero if either group has an ERROR.
4. `aidw prompts list` distinguishes the two groups too (§7.2 "prints the inventory"): toolkit files vs target `aidw/prompts/` overrides, and which required prompts are shadowed vs default.
5. Sentinel parity + no double-counting: a target override containing `.pi/prompts` is an ERROR labelled with the target-relative `aidw/prompts/…` path; a shadowed script-invoking prompt (e.g. `approve-review-followups.md`) must satisfy `AIDW_SCRIPTS_DIR` in the shadow file — but never re-check a file that resolved to the toolkit default (the defaults check already owns it).
6. Fail-closed independence: a failure in one group never suppresses the other — a missing toolkit default and a target shadow with a `.pi/prompts` reference must both surface, one per group.
7. Update the remaining callers: `doctor._check_prompts` uses the renamed `check_defaults` (doctor does not gain the resolved check); no `inventory.check` call site may remain in `aidw/` or tests.
8. Gate impact: `aidw prompts check` and `aidw doctor` are both gate commands (AGENTS.md) and gate the same inventory. Self-hosted — run from the toolkit repo, which has no `aidw/prompts/` — the target-aware command must still exit 0 and report every required prompt as a default. Confirm `uv run aidw prompts check` and `uv run aidw doctor` stay green before finishing.

Traps / prior review findings:

- Relative-path collision: a target shadow `aidw/prompts/code-review.md` and the toolkit default share the basename `code-review.md`; `Issue.source` alone is ambiguous — label target-side issues with the target-relative `aidw/prompts/…` path so "which is which" is readable.

- Scripts are toolkit-side (§3.6) — adding them to the resolved half invents phantom "target script shadows"; `REQUIRED_SCRIPTS` stays in the defaults check only.
