Task: `pyproject.toml`: name `aidt` (D7-settled; the roadmap's "or `aidw` — pick one" is superseded), version, console script `aidw`, and `uv tool install git+…@<tag>` (D9's primary form; no tag exists yet — Requirement 6 fixes the pre-tag verification) verified from a clean machine or clean tool venv.

Requirements:
1. name/version/script already exist and stay correct: `[project] name = "aidt"`, `[project.scripts] aidw = "aidw.cli:main"`, `version = "0.1.0"` equal to `aidw/__init__.py:__version__`. D7 settles the "pick one": repo/package `aidt`, import package + CLI `aidw`. Do not rename, and do not add a second version source or dynamic versioning here (E8.3 owns `aidw --version`).
2. Bundle the three runtime asset dirs into the wheel: `prompts/` (incl. `prompts/scripts/review-followup/`), `agent-configs/`, `agents/` — the §3.12 repo-root siblings of `aidw/`. Add a `[tool.hatch.build.targets.wheel.force-include]` table mapping each dir to itself (`"prompts" = "prompts"`, `"agent-configs" = "agent-configs"`, `"agents" = "agents"`), so they land at the wheel root (site-packages). This keeps `aidw/paths.py:toolkit_root()` = `Path(__file__).parent.parent` correct in both the checkout and the installed layout — **no `paths.py` change**.
3. Bundle only the runtime assets: do NOT force-include `tests/`, `docs/`, `design.md`, `uv.lock`, `.github/`. `README.md` stays wheel metadata via `readme = "README.md"`.
4. The sdist already carries every git-tracked file (hatchling default), so the wheel — built *from* the sdist — can find the force-included dirs. Confirm `prompts/scripts/review-followup/` survives into the wheel (doctor's `scripts` check depends on it).
5. Gate impact: `aidw doctor`'s `toolkit root` check (aidw/doctor.py `_check_toolkit_root`) is the observable proof of bundling — it FAILs with `missing: prompts, scripts, agent-configs, agents` when the wheel omits them. The checkout gates stay green because the repo-root layout is unchanged and no `paths.py` edit is made; `tests/test_toolkit_paths.py::test_dirs_point_at_the_real_shipped_assets` must stay green.
6. Install verification is one **required** check plus one conditional extra; the required check alone satisfies the roadmap Done-when (`uv tool install` then `aidw doctor` from an unrelated directory). Required: from a clean tool venv, `uv tool install <this-worktree-path>`, then `aidw doctor` from a directory outside any git repo (the Done-when predicate). Conditional extra — only when the task branch is already on `origin`, e.g. a re-run after `/pr` pushed it: `uv tool install "git+<origin-url>@<ref>"`, with `<origin-url>` = `git remote get-url origin` and `<ref>` = the pushed branch's head SHA or the branch name. Never done in this task: creating or pushing a tag (E8.5 owns the first), or pushing the branch or any ref to enable the `git+` form — `/pr` (`pr-publisher`) is the single owner of the delivery step.

Traps / prior review findings:
- `uv build` prints "Building wheel from source distribution" — the wheel is assembled from the sdist, so a force-include of a *gitignored/untracked* dir would fail; all three dirs are tracked, so they are present. Omitting force-include entirely is the exact bug this task exists to prevent: installed `aidw doctor` reports `toolkit root: FAIL (missing: prompts, scripts, agent-configs, agents)`.
- Do NOT switch `toolkit_root()` to `importlib.resources` + move assets inside `aidw/`: that contradicts §3.12 (assets are repo-root siblings) and breaks the checkout layout and `tests/test_toolkit_paths.py`. §3.1 lists `importlib.resources` as the *alternative* resolution mechanism, not a mandate to relocate.
- `uv tool install` creates a fresh tool venv and resolves `packaging`/`pyyaml`/`typer` from PyPI — verify on a clean venv with network, not by re-using the dev `.venv`, or the "clean machine" claim is fake.
- No release tag exists yet (E8.5 creates the first tag): the `git+…@<ref>` form is Requirement 6's conditional extra — a pushed commit SHA or branch ref, runnable only when the branch is already on `origin`; do **not** create/push a tag, and do **not** push the branch to make it runnable.
- The new packaging test must not add network to CI (`uv run --frozen pytest` runs offline): there is no "locked hatchling" — `uv.lock` contains zero hatchling entries and the dev group does not declare it, so both a default-isolation build (network fetch) and a bare `--no-build-isolation` build (backend missing from the env) fail today. This task owns the fix: add `hatchling` to the `[dependency-groups] dev` list and re-sync `uv.lock` in the same change (frozen-lock convention), so `uv sync --frozen` provisions it; the test then builds with `uv build --no-build-isolation`, which runs against the locked env and needs no network. Do not rely on default build isolation in the test; confirm the pytest gate stays green offline.
