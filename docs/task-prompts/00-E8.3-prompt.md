Task: `aidw --version`, and doctor reporting toolkit version, git version, and compat status.

Requirements:
1. `aidw --version` — a top-level `--version` flag on the `aidw` app callback that prints the toolkit version and exits 0 **without resolving a target repo** (no `_roots()`, no git spawn — the roadmap's "without a target repo"). Output is prompt-fixed to the same string the existing `version` subcommand prints, `aidt {__version__}` (`aidw/cli.py:version`), so `--version` and `version` share one format and one source: `aidw.__version__`, never a `git`/`uv` shell-out or a `pyproject.toml` parse (E1.6 / design §17 P1). Keep the existing `version` subcommand — do not remove or reword it.
2. `aidw/doctor.py`: add `_check_toolkit_version()` → `Check("toolkit version", OK, …)` reporting `aidw.__version__`, placed in the environment-check group **before** the `TargetRepo.resolve` try/except (alongside `_check_git_version`), so it reports outside any repository. Informational and always OK; the version comes from `from aidw import __version__`, never hardcoded.
3. "git version" is already reported by `_check_git_version` (E2.8) — keep it; do not add a second git-version check.
4. `aidw/doctor.py`: add `_check_compat()` → `Check("compat status", …)` in the resolved-target block, after `_check_target_config`. It loads the declared config (`load_target_config(root / "aidw" / "config.yaml")`) and reports `check_compatibility(declared, toolkit_version=__version__)` (D10/§3.11, `aidw/target_config.py:check_compatibility`): OK when it returns no issues, FAIL rendered via `format_issues` when it does — the messages already name `schema_version`/`requires_toolkit`, so surface them verbatim. prompt-fixed: the compat verdict moves **out** of `_check_target_config` (which keeps loader-`ERROR` issues + `validate_paths` + the resolved schema-version line) so the roadmap's three items become three named checks and `check_compatibility` is evaluated once, never twice. Update `_check_target_config`'s docstring, and the two existing tests that assert the union (`tests/test_doctor.py::test_incompatible_target_config_fails_naming_the_field`, `::test_malformed_and_incompatible_errors_are_both_reported`). A bare/non-repo target skips `compat status` exactly as it skips `target config` (early return).
5. Gate impact: `uv run aidw doctor` (AGENTS.md gate) gains two checks ("toolkit version", "compat status"); both are OK on this toolkit repo (no `<target>/aidw/config.yaml` → `check_compatibility` returns `[]`), so the gate stays exit 0. Confirm by running it.

Traps / prior review findings:
- click/Typer's default `--version` rendering prints a `<prog>, version <v>` shape that does not match the existing `aidt {__version__}`; wire the flag to the existing format, and never hardcode `"0.1.0"` (E8.1: single version source).
- `--version` must be eager and target-free: routing it through `_roots()` makes it fail with `RepoNotFoundError` outside a repo — the exact predicate "without a target repo".
- `_check_target_config` currently unions `check_compatibility` (its docstring says so); leaving that union in place while also adding `_check_compat` double-reports the same FAIL on two lines. Move it, don't copy it.
- Don't `Path.exists()`/`is_file()` the config before `load_target_config`: the loader's `source_path is None` + no-issues IS the valid defaults case (§3.4) — a pre-check that fails on "missing file" turns every config-less repo red.
- Check-name uniqueness: `tests/test_doctor.py::_named` asserts exactly one check per name; "toolkit version" and "compat status" are free, but keep the existing order assertion (`git version` before `repo root`) and the `NEW_CHECKS` loop passing.
