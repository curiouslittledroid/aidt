Task: Doctor: worktree and git checks — add git ≥ 2.31, workspace root, state root, target-is-not-bare, and control-worktree checks.

Requirements:
1. git ≥ 2.31 version check. New `_check_git_version()` in `aidw/doctor.py`, in the environment-check group (runs outside any repo), mirroring `_check_gh_version()`: parse `git version X.Y.Z`, FAIL below `GIT_MIN_VERSION = (2, 31, 0)` (§3.2), WARN when the version is unreadable, FAIL when git is absent. prompt-fixed: absent → FAIL (git is fundamental, unlike `gh`, which is workflow-optional and WARNs on absence).
2. Target selection. Doctor resolves the target via `TargetRepo.resolve(explicit=…)`, threaded from `cli.doctor()` (reuse `_resolve_target_selection()`, which reads the app-level `--repo` option — it precedes the subcommand, so no per-command flag is added), replacing the legacy `repo_root()` walk-up — so `aidw --repo <path> doctor` and `AIDW_REPO` are honoured (§3.1/§3.3) and a bare dir is reachable.
3. target-is-not-bare. Catch `BareRepositoryError` **before** `RepoNotFoundError` (it subclasses it) and emit a named FAIL check ("target repo", detail "bare repository" + the §3.2 `git -C <bare> worktree add ../main main` bootstrap). A generic non-repo stays the existing "repo root" FAIL; a resolved target keeps "repo root" OK with the worktree path.
4. workspace root + state root. Resolve `WorkspacePaths.resolve(target)`; report both paths as named OK checks ("workspace root", "state root").
5. control-worktree. Reuse `aidw.layout.check_layout` as the single classification source (prompt-fixed — prevents doctor drifting from the `_roots` guard). Its `LayoutError` (clone-of-a-worktree trap, or unverifiable worktree list) → FAIL on "control worktree"; success → OK.
6. state-inside-tree advisory. Map `check_layout`'s returned warnings to a WARN on the "state root" check (§3.10 single-checkout), never a FAIL. Mirror `check_layout`'s fixed ordering: trap FAIL is decided before the inside-tree WARN, so a trap layout never reports a WARN and exits 0.
7. Read-only. The new checks must not create the state root or write under the target (§3.1 "nothing generated is ever written into a target repo"). Keep `_check_toolkit_root()` before the bare/repo early-return so it still reports outside any repo.
Gate impact: `uv run aidw doctor` (the AGENTS.md gate) gains five checks; they are OK in the supported bare + worktree layout and at worst WARN (exit 0) in a single-checkout dev clone — the gate stays green. Confirm by running it.

Traps / prior review findings:
- Reimplementing `check_layout`'s membership/more-than-one rule in doctor → doctor says OK while `_roots` refuses the same layout. Import `aidw.layout.check_layout` and map its outcomes; do not copy the condition.
- Using the legacy `repo_root()` → it neither detects a bare repo nor honours `--repo`/`AIDW_REPO`, so the bare and trap checks are unreachable from a terminal. Resolve via `TargetRepo.resolve(explicit=…)`.
- Placing `--repo` after the subcommand (`aidw doctor --repo …`) — `--repo` is an app-callback option (`cli._main` stores it in `_state`); Typer rejects it per-command with "No such option: --repo". Invoke as `aidw --repo <path> doctor`.
- Catching `RepoNotFoundError` before `BareRepositoryError` → `BareRepositoryError` is its subclass, so the §3.2 bootstrap message collapses into "not a git repository". Catch the bare type first.
- Emitting the state-root WARN alongside/before the trap FAIL → a clone-of-a-worktree layout also has state inside a tree; if the WARN wins, doctor exits 0 on a rejected layout. Fail before warn, as `check_layout` already does.
- Copying `_check_gh`'s absent→WARN for git → git is required for every command, so an absent git must FAIL like `pi`, while an unreadable `--version` stays WARN.
- Letting a check or test `mkdir` the state root to "verify" it → violates §3.1 and leaves state behind; assert no `.aidw/state` exists under the worktree after the checks run.

Explicit non-goals — do NOT do these in this task:
- E3.5 `aidw/config.yaml` validation in doctor — §3.3 names it, but the E2.8 roadmap entry does not; that's a separate task.
- E8.3 toolkit-version reporting (`aidw --version`, doctor version/compat status) — separate.
- A doctor check for lock health/leftovers — E2.7 explicitly deferred it.
- A "main control worktree must exist" check — a missing `main` worktree is not a rejected layout in §3.2 and is created by `add_worktree`/`worktree add`; don't invent it.
- E2.9 shared worktree fixture — use local real-repo fixtures mirroring `tests/test_layout.py`'s `_make_bare`/`_make_supported`/`_make_trap`/`_make_plain_clone`.
