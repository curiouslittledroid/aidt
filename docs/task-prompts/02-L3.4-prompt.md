Task: Reconcile after each fix batch (Design 8.1)

Requirements:
1. One reconcile stage per round, after the fix batch: add a `task-review-reconcile-{review_index}` stage (the same N as `task-review-N`) placed after the fix if/else and before the `if revisions >= MAX_REVISIONS: break` check, so it runs exactly once per review round that produced a fix batch — never per finding, and covering all three fix paths (the per-finding `else` loop, the `could-fix`-only loop, and the whole-review `if not findings or problems` fallback).
2. Reuse the fixer: the stage runs the `task-fixer` agent with the existing `prompts/task-review-fixes.md` — no new prompt file and no `aidw/inventory.py:REQUIRED_PROMPTS` change. The reconcile-specific instruction travels in `extra=`, exactly as L2.3's `_DELTA_BRIEF_INSTRUCTION` lives in `prompt.py` rather than in a shipped prompt.
3. `extra=` carries the evidence pointer plus three parts: a new reconcile instruction (compare the fixed prompt against the full review text and the combined diff; repair cross-section contradictions and any finding the batch left unaddressed — keep the roadmap's own wording), the full review text verbatim (`review_text`), and the combined diff `_prompt_diff(baseline_prompt, _capture_prompt(prompt_path), name=Path(rel).name)` where `baseline_prompt` is the in-memory capture already taken before the fix stages. Degrade to `_DIFF_UNAVAILABLE` when baseline/current cannot be read, mirroring L2.3.
4. Evidence pointer: prepend `_stage_evidence_pointer(...)` via `_with_evidence`, same as every fix and review stage (L2.4).
5. Failure contract: a reconcile stage whose `status != SUCCEEDED` stops the run (`return 1`), identical to a fix-stage failure. No new status vocabulary.
6. Approve/Blocked short-circuit unchanged: `verdict == APPROVE` breaks and `VERDICT_BLOCKED` returns before any fix or reconcile stage; both exits already precede the insertion point — do not move them.
7. Prompt-fixed — final round: reconcile also runs after the final (`MAX_REVISIONS`) round's fix batch, before the acceptance break, because pre-L4.1 the last round's fixes are otherwise never reviewed and reconcile is the cheapest available check; L4.1 later removes the final-round fix batch, after which every reconcile sits "before the next review". Do not change `MAX_REVISIONS` or the terminal acceptance path here.

Traps / prior review findings:
- Placing the reconcile stage after the `if revisions >= MAX_REVISIONS: break` → the final round would accept unreconciled (and unreviewed) fixes; it belongs after the fix if/else and before that check.
- Putting the reconcile instruction inside `prompts/task-review-fixes.md` → that file is bucket (i) generic and ships as-is (EXTRACTION.md §4.2); round-specific assembly belongs in a `prompt.py` module constant, mirroring `_DELTA_BRIEF_INSTRUCTION`.
- Reusing `_DELTA_BRIEF_INSTRUCTION` verbatim → it orders the *reviewer* to emit `resolved`/`not resolved`/`newly contradicted` per prior finding; the fixer must reconcile, not review — a new instruction constant is required.
- Naming the stage so it matches `task-review-fixes-*` (e.g. `task-review-fixes-reconcile-*`) → the L3.3 snapshot writer, the `_fix_round` regex and the harness's `fix_status` branch would mis-handle it. `task-review-reconcile-N` is safe: `_review_index`'s `re.fullmatch(r"task-review-(\d+)")` does not match it because "reconcile" intervenes.
- Capturing the diff at the wrong moment → the combined diff must be the fix batch's net effect: `baseline_prompt` (captured before the fix stages) against `_capture_prompt(prompt_path)` after them, taken before the reconcile stage edits anything.
- The fake harness `_fake_stages` has no branch for the reconcile name — it falls through to `else: body = "prompt body\n"` with `SUCCEEDED` (fine for the happy path), so the failure test needs a knob; extend `_fake_stages` (e.g. a `reconcile_status` param) instead of special-casing the name in the workflow.

Explicit non-goals — do NOT do these in this task:

- L4.2 (per-round recording in `state.json`/`run.log`) — do not add a reconcile count or any new recorded field.
- L3.3 (snapshots) is done — do not extend `.prompt.md` snapshots to the reconcile stage (its scope is `task-review-fixes-*`).
- E4.1/E4.3 re-baselining and the design.md §17 decision entry — L6.2 owns them (phase-preamble gate row; the roadmap Notes line flags that this changes the `prompt` chain).
- Do not add a prompt file or agent config, and do not edit `prompts/task-review-fixes.md` or `agents/task-fixer/AGENTS.md` (L3.1/L3.2 own their text).

Tests (what to prove, not the literal expects):
- One reconcile after a blocking round: a `Request changes` round with blocking + could-fix findings runs exactly one `task-review-reconcile-1` after the last `task-review-fixes-1-*` and before `task-review-2` (update the existing exact-sequence assertions in `test_review_fix_loop_fixes_blocking_individually_and_batches_could_fix`, `test_multiple_could_fix_findings_share_one_stage`, `test_could_fix_only_review_still_runs_one_combined_stage`, `test_review_fix_loop_falls_back_to_one_combined_stage`, `test_bold_review_drives_per_finding_fixes`).
- Approve runs none: `approve_review=1` keeps the same two-stage sequence as today, with no reconcile.
- Fallback runs one: an unparseable review (`TASK_REVIEW_UNPARSEABLE`) still runs exactly one `task-review-reconcile-1`.
- Reconcile extra: the reconcile stage's `extra` contains the reconcile instruction, the full review verbatim, the combined diff (baseline→current carrying the whole batch's fix markers, not one finding's), and the evidence pointer.
- Failure stops the run: a reconcile stage returning non-`SUCCEEDED` ends the run (code 1) with no subsequent stage.
- Final round: a 3-round run (`approve_review=None`, extend `test_three_review_rounds_then_accept_without_another_review`) runs `task-review-reconcile-3` after the last fix batch and before acceptance, then still accepts with `assumed_ok=True`.
