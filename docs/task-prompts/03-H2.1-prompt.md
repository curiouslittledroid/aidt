Task: Give the delta brief a size budget.

Requirements:
1. Document a size contract in `aidw/stage_registry.py:render_delta_brief` — docstring plus a named module constant — that budgets the previous review and the diff **separately** (roadmap Deliverable). `render_delta_brief` stays pure: no I/O, no mutation of its inputs (its existing "Pure" docstring, design §15).
2. Previous review — smaller representation wins (spec-fixed): when `aidw/findings.py:parse_review_findings(previous_review)` parses cleanly into findings, render one structured block per finding and use it **only when the structured rendering is strictly smaller than the raw review prose, measured with `len(s)` chars on the exact strings compared — the raw prose string vs the block rendering that would replace it (the same char metric as req 3's diff cap, never UTF-8 bytes or lines)**; on equality, as on any non-win, keep the raw prose verbatim (trailing whitespace included). Never drop a finding. Keep `aidw/stage_registry.py:DELTA_BRIEF_INSTRUCTION` — the per-finding `resolved` / `not resolved` / `newly contradicted` verdict instruction — intact in every rendering.
3. Diff — hard cap + explicit elision: cap the diff section at `DELTA_BRIEF_DIFF_BUDGET_CHARS`; an over-budget diff is replaced by an explicit note in `aidw/stage_registry.py:DIFF_UNAVAILABLE`'s style, naming that the diff was elided for size — never a silently shortened or empty section (roadmap Deliverable + Notes: "a reviewer that cannot see a fix cannot verify it"). Prompt-fixed tokens, so the note cannot degrade into a placeholder a reviewer cannot act on: it must contain the word `elided`, name size as the reason, and state the numeric budget value (`4000`) — the roadmap's "must name what it dropped" made assertable, and distinguishable from `DIFF_UNAVAILABLE`'s could-not-produce case. Prompt-fixed value: `DELTA_BRIEF_DIFF_BUDGET_CHARS = 4000` chars, measured with `len(s)` (the roadmap counts chars: 12,317 / 55,636), anchored to round-1's ~12k prompt so the diff stays a small fraction of it. The roadmap's reduced-context lever (Notes) is not taken here: `--unified` context width lives in the shared producer `_brief_diff`/`_prompt_diff`, which also feeds the out-of-scope reconcile brief (Traps), so the registry-side cap is this task's only diff lever.
4. Round 1 and `--dry-run` are invariant: round 1 is deliberately unprimed (design §8.1), so `render_delta_brief` only runs for rounds ≥ 2 (`BRIEF_DELTA`). Do not change round-1 rendering, the `BRIEF_DELTA`/`BRIEF_RECONCILE` markers, or any plan output — E4.3's Done-when keeps `--dry-run` for `prompt` byte-identical.
5. Record the rendered size per review stage — review stages only, and only on the real-run path: in `aidw/runner.py:run_stage`, store the full rendered prompt's char count (`len(rendered)` — the same string written to `<run>/prompts/<stage>.rendered.md`) as an additive `aidw/state.py:StageRecord` field defaulting to `None` (the additive-field precedent already documented there), and print one `run.log` line naming the stage and the rendered size. `run_stage` renders and records **every** stage and also serves the `--dry-run` path (it saves `state.json` before the dry-run split), so scope the recording explicitly: only review stages (the registry's review-loop heads, e.g. `task-review-N`; signal them to `run_stage` however is cleanest) set the field and print the line; author and fix stages record neither. The `--dry-run` path records neither as well — the field stays at its `None` default and no line is printed — so req 4's byte-identical `--dry-run` holds (a record that never set the field serialises `rendered_chars: null`; that is the additive-field precedent, not a dry-run output change). Confirm the review stage's `usage.input_tokens` (already recorded) sits beside it in `state.json`. Prompt-fixed field name: `rendered_chars`.
6. Record the prompt-fixed budget decision in design §17 (next free decision row), per AGENTS.md §17 — the constant, its value and rationale, and the prompt-fixed round-2 acceptance bound (24,000 chars, see Tests).

Traps / prior review findings:
- `aidw/findings.py:render_finding_block` wraps each block in the **fixer's** "Fix exactly this finding. Do not address the other findings in this run." — the wrong voice for a reviewer, which must *resolve*, not fix. Emit the structured block itself (`aidw/findings.py:_finding_text_block`) with a delta-brief-appropriate heading. The roadmap names `render_finding_block` for its block text, not its fixer instruction. The heading text is unpinned: `_finding_text_block` emits no heading of its own, so any heading is acceptable provided the fixer instruction is absent — do not reuse `render_finding_block`'s "Review finding N of M to address" heading, which carries the fixer voice.
- `aidw/workflows/prompt.py:_brief_diff` feeds **both** the delta brief and L3.4's reconcile brief. The budget must live in `render_delta_brief` (the registry), not in `_brief_diff`/`_prompt_diff`, or the reconcile brief — explicitly out of scope here — changes too.
- A silently shortened or empty diff section fails the whole point of the budget: it must be a named note in the `DIFF_UNAVAILABLE` style, never a truncated diff or `""`, carrying req 3's pinned tokens (`elided`, the size reason, the `4000` value).
- Unparseable reviews stay verbatim, trailing whitespace included — `tests/test_prompt_workflow.py:test_delta_brief_preserves_previous_review_verbatim` and `test_unparseable_previous_review_still_primes_the_next_round` pin the fallback. Substitute only when parsing is clean **and** the blocks are strictly smaller (req 2 — equality keeps prose).
- Units: the roadmap counts chars. `aidw/workflows/prompt.py:_budget_counts` is the *author* prompt's conciseness budget (UTF-8 bytes + lines, L5.3) — do not conflate the two budgets or reuse that helper for the delta brief.
- The structured substitution changes what a later round is told (roadmap phase gate table, L2.3): every prior finding and the per-finding resolution verdict must survive — a finding dropped by the substitution is a silent re-review regression, not a size win.
- `aidw/runner.py:run_stage` renders and records **every** stage and also serves the `--dry-run` path. Recording the rendered size there unscoped would put `rendered_chars` and a `run.log` line on author/fix stages and on the dry-run path — exactly the E4.3 baseline req 4 keeps byte-identical. Scope it: review stages only, real runs only (req 5).

Explicit non-goals — do NOT do these in this task:
- H3.1 (roadmap tick stage) is the next task in this epic — do not start it.
- L3.4's reconcile brief (`aidw/stage_registry.py:render_reconcile`) is not budgeted here — leave it verbatim.
- Model routing / buying a larger context window is E4.6's (roadmap H2.1 Notes) — this task shrinks the prompt.
- The author-prompt conciseness budget (`_check_conciseness` / `PROMPT_BYTE_BUDGET`, L5.3) is unrelated — do not touch it.

Tests (what to prove, not the literal expects):
- tests/test_stage_registry.py: a multi-finding previous review whose structured blocks are strictly smaller renders blocks (not prose) — with no fixer instruction (`Fix exactly this finding`) anywhere in the rendering, whatever heading heads the blocks — and still contains the `resolved`/`not resolved`/`newly contradicted` instruction; a prose review not-strictly-smaller than its blocks — including a `len`-equal boundary case — stays verbatim; an unparseable review stays verbatim with trailing whitespace intact; an over-budget diff (e.g. a synthetic 8000-char diff) renders the elision note — asserted by its pinned tokens (`elided`, the size reason, the `4000` budget value) — and no `diff --git` lines; an in-budget diff renders unchanged; purity (caller strings unmutated).
- tests/test_prompt_workflow.py: re-baseline `test_delta_brief_preserves_previous_review_verbatim` to the new promise — findings plus the resolution instruction survive the substitution — and keep a verbatim fallback case (its name is the old promise, per the roadmap).
- Hand-calculated size check: six-finding structured blocks (~2k chars) plus a ≤4000-char capped diff keep the delta brief well under round-1's 12,317-char prompt — assert the rendered size is recorded on the review stage and left `None` on non-review stages and on the `--dry-run` path (req 5's scope); that an E4.5-shape round-2 prompt (a ~12,317-char round-1 prompt plus the budgeted brief) renders under the prompt-fixed 24,000-char acceptance bound (the failure run's 55,636 is the "before", the measured round-2 size the "after"); and that the over-budget-diff fixture's elided rendering is smaller than the same fixture rendered with the diff left uncapped. The before/after sizes are recorded in `docs/implementation-results/03-H2.1/build-results.md`.

Done when:
- The `tests/test_stage_registry.py` renderer units and the re-baselined `tests/test_prompt_workflow.py` delta-brief test pass.
- A round whose fix-batch diff exceeds `DELTA_BRIEF_DIFF_BUDGET_CHARS` still renders a review prompt under the budget: the delta brief's diff section is the explicit elision note (req 3's pinned tokens: `elided`, size reason, `4000`) in the rendered prompt text — never a silent empty/shortened section — and the elided rendering is measurably smaller than the same fixture with the diff left uncapped.
- Round 1 rendering is byte-identical and `aidw prompt --dry-run` output is unchanged from before this task.
- The E4.5 shape (six findings) renders a round-2 prompt under the prompt-fixed 24,000-char acceptance bound — materially smaller than the failure run's 55,636 — with the before/after sizes recorded in `docs/implementation-results/03-H2.1/build-results.md`.
- A review stage's `state.json` record carries the rendered char count alongside `usage.input_tokens`, and `run.log` names the rendered size; non-review stages and the `--dry-run` path record neither.
- design §17 carries the decision row naming `DELTA_BRIEF_DIFF_BUDGET_CHARS`, its value and rationale, and the round-2 acceptance bound.

If anything in the cited spec is ambiguous or underspecified for this task, decide it as the requirements already direct rather than asking: the diff budget value (`DELTA_BRIEF_DIFF_BUDGET_CHARS = 4000`) is prompt-fixed, not spec-fixed — the spec fixes the strategy (structured blocks, a named hard cap; its reduced-context note is not taken, req 3) but no number; the previous-review budget is realized as smaller-of-two-representations (`len(s)` chars on the exact strings compared, strictly smaller wins, equality keeps prose) with no hard numeric cap; the `StageRecord` field name is prompt-fixed as `rendered_chars` (its recording is scoped review-stage-only and skipped on the `--dry-run` path, req 5); and the E4.5-shape round-2 acceptance bound is prompt-fixed at 24,000 chars — the spec fixes no total number, and 24,000 clears the budgeted ceiling (round-1's 12,317 + ~2k of blocks + the 4,000-char diff cap ≈ under ~19k) while sitting under half of the failure run's 55,636.
