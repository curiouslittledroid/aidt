Task: Config-driven plans — port `build_plan` and the other workflows to build their stage lists from the registry.

Requirements:
1. `plan_stages` in `aidw/runner.py`: `plan_stages(workflow, *, config, toolkit_root, target_root, **expand_fields) -> list[StageSpec]` is the only run-path plan builder for all five workflows — every stage on every run path (the dynamic loops included, per round/iteration) derives from the registry expansion through the same `expand` + `resolve_prompt` mapping, never a hand-built list, so the loop consulting the registry is that builder at work (the loops' runtime-extra seam: Requirement 5). It expands the registry default (`aidw/stage_registry.py:expand`) with `**expand_fields` — exactly `expand`'s documented per-workflow field set (implement: `prompt_rel`/`branch`/`task_id`/`base_branch`; prompt: `phase`/`epic`/`task`/`rel`/`max_revisions`/`rounds`; review: `pr`/`manifest_rel`/`findings`; fix: `pr`/`round_index`/`iteration`/`manifest_rel`; approve: `pr`) — then builds one `StageSpec` per `PlannedStage`, resolving each prompt with the existing `resolve_prompt(toolkit_root, target_root, name=planned.prompt_file, explicit_path=...)` and setting `variables=list(planned.variables)`, `workflow=workflow`, `extra=planned.extra`. `config` is the `ResolvedConfig` from `resolve_config`.
2. explicit_prompt overlay (D14): for each entry in the resolved `workflows.<workflow>.stages` list that declares a `prompt:`, find the same-`id` planned stage and set its `StageSpec.explicit_prompt` to the declared string and its `StageSpec.prompt` to `resolve_prompt(..., explicit_path=declared)`. Only `source == SOURCE_CONFIG` entries (repo-declared) are overlaid. prompt-fixed: the `ConfigDefaults.workflows` slot stays empty — `resolve_config` already carries `workflows.<name>.stages` with `source=config` when the repo declares stages, and seeding a default list is not needed for the overlay and would change `resolve_config`/`aidw config show` output.
3. Deferred-field warnings (E4.5/E4.6 are separate): exactly one `warning:` line on stderr per declared-but-ignored entry, naming the workflow, the stage id, and every deferred reason on that one line. Reasons: `agent` declared (E4.6), `enabled: false` declared (E4.5), and an `id` with no matching registry stage (repo-added, E4.5). One entry carrying `agent` + `enabled: false` draws one line naming both. `prompt:` is not deferred. Count by entry, not by field.
4. `build_plan` in `aidw/workflows/implement.py` becomes a thin compat wrapper returning `list[PlannedStage]` (`list(stage_registry.expand("implement", ...))`); it is not on the `implement` run path (config overrides must apply). Delete the now-unused `PlanStage` dataclass and its `.spec()` if nothing else references them; update `tests/test_implement_workflow.py::test_build_plan_order_and_agents` / `test_build_plan_uses_the_configured_base_branch` to assert tuple `variables` (PlannedStage). prompt-fixed: `StageSpec` gains a trailing `id: str = ""` (default, so existing positional constructions are untouched), set by `plan_stages` from `PlannedStage.id`, so implement's dry-run `I1 impliment-task …` prefix stays byte-identical.
5. Rewire all five workflows to build their stage lists from `plan_stages`. `implement`/`review`/`fix`/`approve` must now load + resolve the target config so `plan_stages` receives a real `ResolvedConfig`; a repo with no `aidw/config.yaml` resolves pure defaults and the dry-run output is unchanged. The dry-run calls pass what the planned run would render — review `findings=True` with `manifest_rel="artifacts/review-manifest.json"` (today's real-run value and the dry-run's manifest path), fix `round_index=1`/`iteration=1` with `manifest_rel="artifacts/iter1-review-manifest.json"` (the planned iteration's real-run value; both field sets already pin `expand` in `tests/test_stage_registry.py`) — so dry-run R2/F4 carry the registry-rendered manifest extra where today's hand-built dry-run stages carry `extra=""`: the planned stdout lines never print `extra`, so the dry-run output stays unchanged while the rendered dry-run prompt gains the manifest pointer, and no run path clears or post-edits a registry-rendered extra. Their preflight replicates exactly two of `prompt.py`'s three refusals (the `run()` preflight in `aidw/workflows/prompt.py`; same stderr + exit-2 contract, before any run record/worktree, `--dry-run` included): the config-ERROR refusal and `check_compatibility` (D10, EXTRACTION.md §3.11 — toolkit-wide, and a no-op on pure defaults), then `resolve_config`. `validate_paths` stays prompt-only (E3.7's read-path preflight): its `READ_PATHS` defaults (`roadmap_dir`, `implementation_results_dir`, `build_results_template`) need not exist in these four workflows' trees — replicating it would exit 2 in the existing dry-run fixtures (they create only `docs/task-prompts/<file>`) and break the unchanged-dry-run gate; a missing path surfaces fail-closed at the stage that reads it (e.g. record's build-results template). Runtime extras are a seam the registry half-owns (`aidw/stage_registry.py`, E4.1): `expand` itself renders the fix stages' finding-block `extra` (`render_finding_block`/`render_could_fix_block`/`render_whole_review_extra`) and carries the brief markers `BRIEF_DELTA`/`BRIEF_RECONCILE` on `PlannedStage.brief`, zeroed on the unprimed round 1 (L2.3 — the registry owns the unpriming). `StageSpec` has no `brief` field, so the `plan_stages` mapping drops the marker by design: the loop reads it off the registry's planned stages and renders the brief text with the registry's pure `render_delta_brief`/`render_reconcile`, feeding them the payload only the loop has (the previous review text, the batch's diff from its two prompt snapshots); this task deletes `prompt.py`'s `_render_delta_brief`/`_render_reconcile` copies and their now-orphaned `_DELTA_BRIEF_INSTRUCTION`/`_RECONCILE_INSTRUCTION`/`_DIFF_UNAVAILABLE` constants (the registry docstring marks E4.3 as the deletion point; only the deleted renderers use them). The L2.4 evidence pointer composes workflow-side, in front of the rendered brief / planned `extra`, via `_with_evidence`; `fix`/`approve`'s `verify` postcondition (`StageSpec.verify`) likewise stays workflow-side — pointer, payload and postcondition are never stage data.
6. The prompt loop stays a loop driven by real verdicts (it cannot pre-plan the whole chain in a real run). Its dry-run keeps planning `task-prompt` + `task-review-1` (pinned by `tests/test_prompt_workflow.py::test_prompt_workflow_dry_run`), which is `plan_stages("prompt", ..., rounds=())`; the full post-phase-02 chain (reconcile-per-batch + review-only terminal review) is the registry's `expand("prompt", rounds=<batches>)` output already pinned by `tests/test_stage_registry.py` — do not regress either. prompt-fixed reading of the roadmap's "dry-run baseline … includes reconcile + terminal review": that phrase describes the real-run chain the plan builder must reproduce, not a change to the current 2-stage dry-run, since "unchanged" is the governing acceptance and the only executable dry-run baseline is the existing test's `["task-prompt", "task-review-1"]`.

Traps / prior review findings:
- Import cycle: `runner.py` may import `aidw.stage_registry` (leaf → `aidw.findings`) and `aidw.target_config`, but never a workflow module; `target_config` must never import `runner` or a workflow (E4.1's trap). `plan_stages` takes the resolved config as an argument — it never loads it.
- `PlannedStage.variables` is a tuple; `StageSpec.variables` is a list — convert with `list(...)`, and `build_plan`'s tests must compare tuples.
- `PlanStage.id` (`"I1"`) vs `name` (`"impliment-task"`) are different fields; implement's dry-run prints the id prefix — without the carried `StageSpec.id`, "unchanged" breaks.
- Whole-list config: `workflows.<name>.stages` is a whole-list override (`resolve_config` never merges per-element), so `plan_stages` must iterate the config list as an overlay and never assume it mirrors the registry order or size.
- `resolve_prompt` already fails closed on a declared-but-missing `prompt:` — `plan_stages` must let that `FileNotFoundError` propagate (never fall back to shadow/toolkit for a declared path).
- The prompt dry-run is 2-stage; wiring it to a full-loop `expand(rounds=<batches>)` changes the output and contradicts "unchanged" — use `rounds=()`.
