Task: Close a follow-up issue only after its fix is pushed (Design 8.4, Design 7.2)

Requirements:
1. Defer the close: in a `fix` run an issue's exact `Status: fixed` comment and its close happen only after the P1.1 `F5 commit-and-push` stage has pushed a tree containing that fix (roadmap P1.2 "Done when"; §8.4's D3 table + D6 equality). `F1` no longer posts `Status: fixed` or closes in-stage; it leaves the issue `OPEN` with the existing `Status: in progress` comment from `start`.
2. Add deferred-close support to `review_followup.py`: a `close` subcommand (`--pr`, `--issue`, `--body-file`, `--dry-run`) that posts the exact `Status: fixed` comment if absent (idempotent) then closes with the body, reusing `cmd_fixed`'s guards (§7.2 strict equality; the `review-follow-up`/`approve-fix` label guard; refuse-to-reopen; `closing_body_repeats_status`; post-close verification returning `EXIT_VERIFY_FAILED` on a label/state mismatch). `fixed` keeps its in-stage contract by sharing the same close tail. The CLI `--help` text and the `README.md` command list gain `close` alongside the existing commands. *(prompt-fixed: command name/signature — the roadmap fixes only "supports that deferred close".)*
3. Run the close in Python, not the agent: `aidw/workflows/fix.py` runs `close` for each recorded `closed_issues` entry only after `run_commit` verifies the push (`HEAD` moved, `HEAD == origin/<branch>`, clean tree, `state.pr["head_sha"]` written). A non-zero `close` exit fails the run (exit 1) naming the PR, branch and issue. *(prompt-fixed — rationale: Z9 D9 fixes `/fix-commit` as commit+push only, and the roadmap deliverable omits `prompts/fix-commit.md`.)*
4. Preserve the closing body across the deferral: the fixer writes its closing body to a per-iteration file the workflow supplies, and each `closed_issues` entry carries that path so the workflow can pass it back as `close --body-file`. *(prompt-fixed keying: `<run_dir>/artifacts/iter{N}-closing-body.md`, threaded as F1's new `{closing_body}` variable — today's body is a transient `mktemp` file.)* The rendered `{closing_body}` value — and the path each `closed_issues` entry records — is **absolute**: F1 runs with the target repo as its cwd, the same hazard that forces `fix.py`'s `_planned_iteration` to pass F4 an absolute `manifest_path`; a relative path would write the body into the repo tree and pollute the pushed diff. A missing, empty, or `Status: fixed`-prefixed body file at close time fails the `close` before any close action (it reuses `cmd_fixed`'s `read_closing_body` guards), and that non-zero exit fails the run per requirement 3 — the issue is never closed on a bad body.
5. Fail closed only where a close is pending: when this run recorded at least one `closed_issues` entry and the push fails or the commit stage is absent/skipped/failed, no `close` runs, the issue stays open, and the run exits non-zero — never "reported fixed" (§8.4 D3/D6; roadmap P1.2 "Done when"). A run that recorded no entry keeps D3's skip contract: the dirty+0 and clean+0 cases attempt no close and exit 0, and an empty run (first `select` returns `EXIT_NONE_AVAILABLE`) has no close to run.
6. Keep one issue closed per fix: the close loop closes exactly the entries this run's loop recorded, never a batch and never a re-derived count (§8.4 "One fix per iteration"; roadmap P1.2 Notes).
7. Update the design record: design.md §8.4 (the `F1` prose and the D3 four-case-table note, which still says P1.2 "later" makes case 4 unrepresentable) and §17 row Z9 (append P1.2's prompt-fixed decisions to the existing row). Also `agents/fixer/AGENTS.md`, whose hard rule "record it as fixed, and close it" contradicts the deferral (Z9 D9: prompt text alone does not override an agent file).
8. Gate impact: F1's variables grow to `("{pr}", "{closing_body}")`, so re-baseline `tests/test_plan_stages.py`'s fix-plan variables pin (`test_fix_plan_is_the_approval_plus_one_iteration`) and `docs/workflow-stages.md`'s F1 variables cell (drift-checked by `tests/test_workflow_stages_doc.py`). Keep all five repo gates green: `uv sync --frozen`, `uv run --frozen pytest`, `uv run aidw doctor`, `uv run aidw agents validate --strict`, `uv run aidw prompts check`.
