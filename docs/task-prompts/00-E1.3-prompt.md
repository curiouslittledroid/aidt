Task: Resolve `workspace_root` = `dirname(git rev-parse --path-format=absolute --git-common-dir)`; `state_root` = `AIDW_STATE_DIR` | `<workspace_root>/.aidw/state` | `~/.aidw/state` (with `<repo_slug>` appended per §3.10/R1); `repo_slug` from `git remote get-url origin`, else the workspace-root basename. Resolution helpers + tests only — consumer porting is E1.4/E1.5, layout guards E2.2.

Requirements:
1. Add a frozen dataclass in `aidw/paths.py` following the `TargetRepo`/`ToolkitPaths` pattern (frozen, sole construction via a `resolve()` classmethod). Expose exactly `workspace_root`, `state_root`, `repo_slug` — the two paths absolute `.resolve()`d, `repo_slug` a `str`. Distinct type from `TargetRepo`/`ToolkitPaths` (§3.1).
2. `workspace_root = common_dir.parent` — the `dirname` of the absolute `--git-common-dir` the spec's formula already yields. Derive it from the passed-in `TargetRepo.common_dir` (already absolute), never re-run git: `resolve(repo: TargetRepo, ...)`.
3. `repo_slug`: `owner-name` from `git remote get-url origin` (run in `repo.root`), else the `workspace_root` basename; always present (never `None`/empty). Prompt-fixed parsing: strip a trailing `.git`, accept `https://host/<owner>/<name>.git` and `git@host:<owner>/<name>.git`, join the two segments with `-`; fewer than two path segments or a missing/failed remote → basename. (§3.10 names only "owner-name"; see ask-if-ambiguous.)
4. `state_root` = `<base>/<repo_slug>` where `base` = `AIDW_STATE_DIR` (env) else `<workspace_root>/.aidw/state` else `Path.home()/.aidw/state`. The slug is appended in **all three** tiers (§3.10 layout `<state root>/<repo-slug>/`, R1 "always present"). Prompt-fixed: the exposed `state_root` field is the per-repo directory (`base + slug`), not the pre-slug base — the roadmap line lists the base tier separately, but the Done-when's "differs between repos sharing a parent" only holds with the slug in it.
5. Fail-closed, never raise: when `<workspace_root>/.aidw/state` is unusable (unwritable workspace root / creation fails), resolve `base` to `Path.home()/.aidw/state`. The probe is an implementation detail (access check vs guarded `mkdir`); the test asserts the fallback, not the mechanism.
6. `AIDW_STATE_DIR` and `home` must be injectable (e.g. `resolve(repo, state_dir_override: Path | None = None, home: Path | None = None)`), `None` reading the real env / `Path.home()`, so tests set them per-case without touching the real environment.
7. Additive only: no `aidw/cli.py`, `aidw/doctor.py`, workflow, or config changes here (consumers port in E1.4/E1.5, doctor checks in E2.8).

Traps / prior review findings:
- `workspace_root` must be `common_dir.parent` — never `git_dir.parent` (a linked worktree's `git_dir` = `<bare>/worktrees/<name>`, whose dirname is `<bare>/worktrees`), and never `root.parent` (coincidentally right only in the §3.2 layout).
- In a plain clone `common_dir == <root>/.git`, so `workspace_root == repo.root` (the working tree itself) and `state_root` lands **inside** the working tree — that is the §3.10 "single-checkout" case E2.2 later warns on. Assert that; don't assume workspace_root is always a non-git parent.
- Build a real bare repo + two linked worktrees (reuse the `tests/test_target_repo.py:_make_bare_with_worktree` pattern, add a second `git -C bare worktree add`) — `git init` cannot distinguish `git_dir`/`common_dir`.
- `aidw/github.py:repo_slug` already exists and means `owner/name` via `gh repo view` (slash form, network, may return `None`). E1.3's slug is git-remote-derived, hyphenated, offline, never `None`. Don't reuse or "fix" the gh one.
- The SSH remote form uses `:` before the path (`git@host:owner/name.git`), not `/` — parsing only `/` breaks SSH remotes; handle both.
- The "differs between repos sharing a parent" proof needs two bare repos under one parent **with distinct origin remotes**: without remotes both fall back to the shared parent's basename and collide (the spec accepts this; don't try to fix it here).

Tests (what to prove, not the literal expects):
- One bare repo, two linked worktrees: both resolve to the same `workspace_root` (= `dirname(bare)`) and the same `state_root`; `state_root == workspace_root / ".aidw" / "state" / <slug>` with the slug derived from the origin remote.
- Two bare repos under one parent, each with a worktree and a distinct `origin`: same `workspace_root` (the shared parent), different `state_root` (slug differs) — the Done-when "differs" proof.
- Single checkout (plain clone): `workspace_root == repo.root`; `state_root == repo.root / ".aidw" / "state" / <slug>`.
- No `origin` remote: `repo_slug == workspace_root.name` (basename fallback) and `state_root` uses it.
- `AIDW_STATE_DIR` override (injected): `state_root == override / <slug>` — the slug is still appended.
- Unwritable workspace root (chmod `0o500`, restore in a `finally` so tmp cleanup works), home injected to a tmp dir: resolves to `<tmp home>/.aidw/state/<slug>` and does not raise.
- Purity/shape: `resolve()` does not mutate the passed `TargetRepo`; fields are exactly the three named; the dataclass is frozen; every path is absolute and `.resolve()`d.
