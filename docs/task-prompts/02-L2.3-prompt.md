Task: Rounds after the first get a delta brief (Design 8.1)

Requirements:
1. Delta brief via `extra=` — in `aidw/workflows/prompt.py`, the `task-review-N` `StageSpec` gains an `extra=` block for `review_index >= 2`; round 1 keeps `extra=""` (the `StageSpec` default, `aidw/runner.py:StageSpec.extra`). Assemble it in `prompt.py` (a module constant/helper) — no new prompt file and no `aidw/inventory.py:REQUIRED_PROMPTS` change; `run_stage` already appends `spec.extra` to the rendered prompt (`aidw/runner.py`).
2. Block contents — the `extra` carries, in order: (a) an instruction requiring, for each finding in the previous review, a per-finding resolution verdict of exactly `resolved` / `not resolved` / `newly contradicted` before raising any new finding, and that new findings must be genuinely new (never re-litigate a resolved finding); (b) the previous review's full text verbatim; (c) the prompt diff since that review.
3. Diff baseline (prompt-fixed) — capture the prompt file's content in-memory after each review's verdict is read and its `Blocked`/`MAX_REVISIONS` breaks are handled, and *before* that round's fix stages run. For the next review, diff the captured content against the current prompt content. Rationale: `_commit_reviewed_prompt` runs once after the loop, so there are no per-round commits and a bare `git diff -- <path>` would be cumulative across rounds; capture-then-diff makes round N's diff exactly the previous fix batch's net effect.
4. Genuine git diff — produce the diff with `git diff --no-index` against a temporary copy of the captured content (a tempfile, not the run directory — L3.3 owns run-dir snapshots), or an equivalent real git-diff invocation — never a hand-built summary. `git diff` exits 1 when files differ: treat 0 and 1 as success, anything else as failure (do not reuse `aidw/git.py:diff_stat`'s `code == 0` guard, which silently drops the diff).
5. Round 1 and `--dry-run` unchanged — no stage is added, removed, or renamed, and the round-1 StageSpec args stay exactly `[rel]`; the dry-run path (which plans only `task-review-1`) is untouched, so the existing stage-list tests pass as-is.
6. No shipped-prompt edit — do not touch `prompts/task-review.md`: the instruction is toolkit runtime text in `prompt.py` (it may name `git diff` and the prompt path), so L2.1/L2.2's additions and the bucket-(i) split (EXTRACTION.md §4.2) stay intact. Update the `prompt.py` module docstring's stage-2 line to mention the delta brief.

Traps / prior review findings:
- `git diff --no-index` exits 1 on differences: if you reuse the `diff_stat`/`changed_files` "`code == 0` else empty" pattern (`aidw/git.py:199`), the diff is silently dropped whenever the prompt actually changed — the exact case the brief exists for.
- The existing `_fake_stages` fake never mutates the prompt during fix stages (only `task-prompt` writes it) — a naive per-round `extra` assertion would read an empty diff and prove nothing. The L2.3 fake must write a round-distinct marker to the prompt in each fix stage so round 2 vs round 3 diffs are distinguishable.
- Capture the baseline after the `Blocked`/`revisions >= MAX_REVISIONS` breaks and before `revisions += 1`/the fix loop; capture after the fix loop and the diff is empty.
- Key the delta brief off `review_index >= 2`, not `revisions > 0`: both coincide at round 2, but `revisions` increments later in the same iteration and the discriminator must be the stage counter.
- Carry the previous review forward in a separate variable (e.g. `previous_review_text`) set only when the round is followed by fixes — the loop reassigns `review_text` on the next iteration, so reusing it after the next `run_stage` overwrites it.
- The unparseable-review fallback still loops: produce the delta brief for every round ≥2 even when the previous review parsed no findings (the fix stage carried the whole review text); the instruction must read against that case without crashing on an empty `findings`.

Explicit non-goals — do NOT do these in this task:
- L2.4 (evidence bundle — the D16 mechanism) and the rest of epic L2; L3.x (fixer verify/sweep/snapshot/reconcile) and L4.x (terminal-review budget honesty, recording, config).
- Do not implement per-round prompt snapshots to the run directory — L3.3 owns `stages/<stage>.prompt.md`; L2.3's baseline is an in-memory capture only.
- Do not add a second independent review at the end (the roadmap's future fallback if anchoring shows up) — that's a later decision, not this task.
- Do not amend `design.md` §8.1 or open a §17 decision entry — L6.2 consolidates phase-02 decisions and amends §8.1 provisionally.
- Do not touch `prompts/task-review.md` or `prompts/task-review-fixes.md` (L2.1/L2.2 own the former, L3.1/L3.2 the latter); the delta-brief assembly belongs in `prompt.py`.

Deliverables:
- aidw/workflows/prompt.py
- tests/test_prompt_workflow.py

Tests (what to prove, not the literal expects):
- Round 1 is unprimed: the `task-review-1` `StageSpec` has `extra == ""` and variables `[rel]`; a single-round approve still has no delta brief (existing approve tests pass unchanged).
- Round 2: `spec.extra` contains all three tokens (`resolved`, `not resolved`, `newly contradicted`), the previous (round-1) review text, and a git-diff hunk (a `+`-line) for the marker the fake fixer wrote — use `_fake_stages`' `seen` list, which already records `(name, variables, extra)`.
- Round 3: `spec.extra` carries round 2's review text and a diff reflecting only round 2's marker, not round 1's — proving the baseline is captured per round, not cumulative (the fake fixer must write a distinct marker per round).
- Diff authenticity: assert the diff section has unified-diff shape (`diff --git`/`@@`/`+`/`-`), not just the new file content.

Done when:

- Rounds ≥2 receive an `extra` with the three resolution tokens, the previous review text, and a git diff; round 1's `extra` is empty (asserted).
- The round-3 diff reflects only round 2's changes, proving per-round (not cumulative) baselining.
- No new prompt file and no `aidw/inventory.py` change; `uv run aidw prompts check` is clean.
- The diff touches only `aidw/workflows/prompt.py` and `tests/test_prompt_workflow.py`.

If anything in the cited spec section is ambiguous or underspecified for this task, stop and ask rather than guessing — especially:
- the diff baseline is prompt-fixed (capture-after-review → diff-to-current, requirement 3): the roadmap says "a `git diff` of the prompt since it" but there are no per-round commits, so if you read the intent as a cumulative `git diff` instead, stop and ask;
- whether the resolution instruction must re-render prior findings structurally (via `aidw/findings.py:_finding_text_block`) or may pass the previous review text verbatim — the roadmap says "Pass them the previous review", so verbatim + instruction is the reading here; re-rendering is a separate choice;
- whether the diff needs a length cap for very large fix batches — the roadmap is silent; do not truncate unless asked.
And the generic guard: security-sensitive, cost-committing, or hard-to-reverse changes (cross-account trust, schema changes, billing logic, data deletion).
