Task: Preserve matching semantics exactly — no change to strict equality, no whitespace normalisation, no case folding, no regex reinterpretation of markers; the label "ensure existing" path still never overwrites an existing label.

Requirements:
1. Tests-only task: the matching code paths are frozen, not edited. `logic.py:has_exact_comment` keeps `body == exact`; the label checks in `logic.py` (`availability`, `priority_label`, `approval_plan`, `is_approved`) keep case-sensitive `in`; `gh.py:find_parent_issues` keeps `marker not in str(issue.get("body") or "")`; `publish_review_followups.py:find_marked_issues` keeps `marker not in issue["body"]`; `ensure_labels` keeps `if name in existing: continue`. No `re.search`, no `.casefold()`/`.lower()`, no whitespace `.strip()`/normalisation enters any of these paths.
2. Comment-body strict equality (§3.9): `has_exact_comment` matches `STATUS_IN_PROGRESS`/`STATUS_FIXED`/`DECISION_APPROVE_FIX` only byte-for-byte — trailing whitespace, a case change, or extra text all fail. Already asserted in `tests/test_logic.py` (`test_has_exact_comment_matches_only_the_exact_body`, `test_status_flags_never_treat_a_mention_as_a_status`); do not weaken or edit those tests.
3. Markers match literally, never as regex (§3.9 "exact string match"): pin `find_parent_issues` and `find_marked_issues` — the rendered marker's URL `.` (and any other metacharacter) is literal. A body that substitutes any single character for a `.` in the URL returns no match; the byte-exact marker returns the issue.
4. Label names are case-sensitive: pin that `Approve-fix`, `Review-follow-up`, `Decision-pending` (wrong case) never satisfy the `in` checks — availability stays blocked (`MISSING_APPROVE_FIX`), `priority_label` returns `None`, `approval_plan` still adds `approve-fix`, a wrong-case `Decision-pending` neither blocks availability nor enters `approval_plan.remove_labels`, `is_approved` stays False.
5. "ensure existing" never overwrites: pin `ensure_labels` — a name already returned by `label_list` hits `continue`, so `create_label` is never called for it and its colour/description are untouched (there is no label-edit call anywhere in the scripts). Only missing names are created from `LABEL_DEFINITIONS`.

- The marker *template* contains `{pr_url}` (a `.format` placeholder) but the *rendered* marker is what's matched; its URL dots are regex metacharacters. - "Never overwrite" is structural: there is no `gh label edit` anywhere. Assert `create_label` is not called for existing names — not a no-op edit, which would be vacuously true and could invite adding an edit call.
- Importing `publish_review_followups` imports `gh`, which runs `_load_config()` at import (reads `AIDW_REVIEW_FOLLOWUP_CONFIG`). Keep these tests env-var-free so they pin the *frozen* semantics; do not reuse `test_github_config.py`'s reload fixture here.
- GitHub label names are case-sensitive: a wrong-case existing label must not suppress creation in `ensure_labels` (it is a different label), and a wrong-case label on a child must not satisfy availability — pin both, or a case-folding "improvement" slips through.
- `test_logic.py`/`test_publish_logic.py` must remain byte-identical (the roadmap's "unmodified" is provable only if the diff touches no pre-existing test) — put every new vector in the new file.
