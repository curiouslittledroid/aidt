Task: Implement target resolution: cwd walk-up, then `--repo <path>`, then `AIDW_REPO`. Expose `root`, `git_dir`, `common_dir`, `base_branch` (from config, E3).

Requirements:
1. Add a `TargetRepo` dataclass exposing exactly `root`, `git_dir`, `common_dir`, `base_branch` — `root`/`git_dir`/`common_dir` are absolute `.resolve()`d `Path`s, `base_branch` a `str`. Per §3.1 it is a distinct type from the toolkit root, never a bare `root: Path` alias.
2. Default resolution walks up from cwd preserving `repo_root()` semantics (`aidw/paths.py:repo_root`): `git rev-parse --show-toplevel`, then the `.git`-file/dir walk-up fallback, `.resolve()`d absolute result, `RepoNotFoundError` when nothing is found.
3. An explicit override (the path `--repo`/`AIDW_REPO` will later supply) wins over cwd walk-up: resolve it absolutely and validate it is a working tree (a bare override is rejected the same as a bare cwd). Do not read env vars or touch the CLI in this task (that is E1.5).
4. Derive `git_dir` from `git rev-parse --absolute-git-dir` and `common_dir` from `git rev-parse --path-format=absolute --git-common-dir` (prompt-fixed: plain `--git-dir` prints a relative `.git`; §3.2 pins `common_dir`).
5. Reject the bare dir with a distinct, actionable error: when `--show-toplevel` fails, check `git rev-parse --is-bare-repository` and refuse with a message naming "bare repository" and telling the user to run from a worktree. Do not let the walk-up fallback swallow it into the generic `RepoNotFoundError`.
6. `base_branch` defaults to `"main"` (the §3.4 `repo.base_branch: main` value). It is a field only — no YAML/config loading here; E3.1 supplies it from config later and may change only its source, not the field.
7. This task is additive: keep `repo_root()`'s public behaviour unchanged (signature, `.resolve()`d absolute result, `RepoNotFoundError` for a non-repo path) so existing call sites (`cli.py:_roots`, `doctor.py:266`, config's `repo_root` param) keep working. Consumer porting is E1.4/E1.5.

Traps / prior review findings:
- In a linked worktree `git_dir` != `common_dir`; in a plain clone they are equal. Tests must build a real bare repo + `git worktree add` linked worktree, not `git init`, or the two fields can't be told apart. (E2.9 later shares a fixture; don't block on it.)
- `git rev-parse --show-toplevel` exits 128 in a bare repo ("this operation must be run in a work tree") and a bare dir has no `.git` entry, so the current `repo_root()` fallback would raise the generic "Not inside a git repository". Detect bareness before that path.
- `doctor.py:262` catches only `RepoNotFoundError`; if the bare-repo refusal raises a new exception type, `aidw doctor` run from a bare dir crashes instead of reporting FAIL — subclass `RepoNotFoundError` (or reuse it) so the existing handler still catches it.
- `git rev-parse --git-dir` prints a relative `.git`; `--absolute-git-dir` is the field value. Mixing them yields a `git_dir` wrong relative to cwd.
- Keep `.resolve()` on every returned path: downstream (`report.rel_to`, config `_resolve`) assumes absolute resolved paths.

Explicit non-goals — do NOT do these in this task:
- E1.2 `ToolkitPaths`; E1.3 workspace/state root; E1.4 port consumers & delete `aidt_root()`/`runs_dir()`; E1.5 CLI plumbing (reading `AIDW_REPO`, threading `TargetRepo` through workflows) — separate tasks, don't start them here.
- Config loading/validation (E3.1): `base_branch` is a defaulted field, not a YAML read.
- Worktree primitives/creation (E2.x): this task only *resolves* an existing target; it never creates worktrees or branches.

Deliverables:

Tests (what to prove, not the literal expects):
- From a linked worktree of a bare repo: `root` == the worktree path, `git_dir` == `<bare>/worktrees/<name>`, `common_dir` == the bare repo path.
- From a subdirectory of that worktree: resolution walks up to the same `root`.
- Explicit override pointing at a repo while cwd is elsewhere: `root` == the override path.
- A non-repo path raises `RepoNotFoundError` (message includes the start path).
- The bare dir raises the bare-specific refusal (not the generic `RepoNotFoundError`), message names "bare" and the corrective action.
- Equivalence in a plain clone: the resolver's default result from cwd has `root == repo_root(cwd)` and `git_dir == common_dir == <root>/.git`.
