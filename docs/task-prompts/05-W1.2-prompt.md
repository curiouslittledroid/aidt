Task: `--dry-run` must not create a run or become a `--resume` target

Requirements:
1. Decide the rule once (roadmap Notes offer two options; the Done-when's "no new run directory, no `state.json`" forces one): a **dry run creates no run at all** — no run directory, no `state.json`, no `run.log`, no `prompts/<stage>.rendered.md`. Apply it uniformly to all five workflows, `implement`/`prompt`/`approve`/`review`/`fix`, because the roadmap Notes state each reaches `create_run` before its dry-run split and the rule is decided once (prompt-fixed: uniform, not resume-pairing-only).
2. The dry-run plan output is unchanged: every workflow still prints the full stage plan with each stage's id/name, resolved agent and model, plus the planned gate (and, for `implement`/`prompt`, the planned worktree and branch-setup command). §19 items 8–9's "prints stages with agents, prompts and models" must still hold, byte-for-byte where tests pin it.
3. `aidw/runner.py:run_stage` with `dry_run=True` must perform no filesystem writes — no `prompts/<name>.rendered.md` file, no `save()` of the PLANNED or SUCCEEDED record — while still resolving the agent/model and returning the `StageRecord` the workflows print (`name`, `status=SUCCEEDED`, `agent`, `model`). Today those writes happen before the `dry_run` branch, so the `prompts_dir.mkdir`/`rendered_path.write_text` and both `_STATE_LOCK`+`save` calls must move behind a `not dry_run` guard.
4. The one-run-per-worktree lock is still acquired in dry-run and refuses exit 4 naming the lock when a peer holds it (§19 item 8, §9.1) — then no run state is written after. Do not drop the lock acquisition or its comment contract.
5. `aidw implement <prompt> --dry-run` and `--dry-run --resume` both leave the runs tree byte-identical, so no later `--resume` can attach to a run that never invoked Pi: `_latest_implement_run`/`_latest_prompt_run` need no change because no phantom is ever recorded. Record the decision that a never-invoked-Pi run is **not resumable**, enforced structurally (no such run exists post-fix); no legacy-phantom detector or `state.json` marker is added (`runs/` is machine-local per AGENTS.md).
6. `aidw exec --dry-run` follows the same rule: it calls `create_run` before its own dry-run split, so the dry-run path skips **every** exec write — `create_run`, the `RunLogger(directory)` construction (`aidw/log.py:25` mkdirs on construction; the write-free substitute stays closing (c)'s open choice), and the post-`run_stage` conditional `save(directory, run)` — and **drops the `rendered:` echo entirely** (prompt-fixed, not either/or: the rendered file is never written, and a planned path would fabricate the run id the traps forbid; the real-run echo is unchanged). The prior help claim was wrong for exec — its `--dry-run` help says "Plan only; do not invoke Pi." (`aidw/cli.py:944`), not "Plan only; no writes." — so update it to "Plan only; no writes." (`prompt`'s string, `aidw/cli.py:325`), advertising the no-writes contract this task keeps; no test or design.md §14 pin covers the string.
7. Update design.md: §9 (and the `--dry-run` sentences in §8.2) state the rule ("a dry run creates no run state / leaves the runs tree unchanged"); a **new §17 row** records the rule and the prompt-fixed decisions with rationale; §19 items 8–10 reworded to "creates no run state" (item 10 covering `review`/`fix`/`approve` too). - `run_stage` writes the rendered prompt and calls `save` before the `dry_run` check (`aidw/runner.py:run_stage`) — the first planned stage would recreate the run directory unless those writes move behind `not dry_run`.
