**(c1) Write-free planning substitute: a null logger plus a never-saved `RunState`, with `run_stage`'s signature unchanged.** Two additive helpers. `aidw/log.py:NullLogger(stream=...)` exposes the same `info`/`warn`/`error`/`section` methods and the same `<ts> [LEVEL] <msg>` line format as `RunLogger`, echoes to stderr exactly when `RunLogger(stream=True)` would, and performs **no** `mkdir` and **no** file write — so the trap at `aidw/log.py:25` is unreachable on a dry-run path because `RunLogger` is never constructed there. `aidw/state.py:planned_run(...)` takes `create_run`'s exact keyword arguments and returns the same `RunState` with `run_id=PLANNED_RUN_ID` and **no** `save()`; factor the shared construction into one private builder so the two cannot drift, and keep `create_run`'s signature and its `save` unchanged. Every workflow's dry-run branch uses those two. A `None`-tolerant `run_stage` (the roadmap's third option) is rejected: it pushes `is not None` branches into the shared seam and every call site to avoid a state `planned_run` already produces for free. `run_stage(dry_run=True)` keeps its signature and moves `prompts_dir.mkdir` + `rendered_path.write_text` **and both** `save()` calls behind `not dry_run`; `record.rendered_prompt` keeps its existing **relative** string (`prompts/<name>.rendered.md`), which fabricates no run id, and `rendered_chars` stays `None` (already dry-run-gated). `runner.record_skipped` gains the additive `dry_run: bool = False` and skips its `save` when set, because `fix`'s `withhold_tick` reaches it on a dry-run path — a write req 6 does not enumerate; `state.record_stage` stays, because it is in-memory. Each workflow's dry-run tail also drops its own `save(directory, state)` (`approve.py:298`, `fix.py:1506`, `implement.py:1289`, `prompt.py:2421`, `review.py:415`) and `fix.py:1043`'s `(directory / "artifacts").mkdir` is guarded, so a dry run's filesystem effect is exactly zero plus the §19 item 8 lock.

**(c2) No run id at plan time: a dry run prints no `run:` line.** All five workflows and `aidw exec` (which prints one today at `aidw/cli.py:1024`) drop it. With no run created the printed id identifies nothing — the same fabricated-identity argument req 6 already uses to drop `exec`'s `rendered:` echo — and req 2's must-keep list names the full stage plan, the resolved agents and models, the planned gate and (implement/prompt) the planned worktree and branch-setup command, never the run id. The in-memory state's id is the literal `aidw/state.py:PLANNED_RUN_ID = "<planned>"`, **not** a minted timestamp: the planned `StageRecord.session_id` is then deterministic (`aidw-<planned>-<agent>-<stage>`), two dry runs print byte-identical output, and a test can pin it without stubbing the clock. Nothing persists under that id, so `run_dir(runs_root, PLANNED_RUN_ID)` is a path no code creates. Rejected: `run:    (planned; --dry-run creates no run)` — it is a new line every dry-run test must pin and one an operator can copy, while `exec`'s echo is dropped outright.

**(c3) Planned paths are named, never fabricated.** Dry-run paths share one literal root, `aidw/state.py:PLANNED_RUN_DIR_TEXT = "<run dir>"`, and the three expansion fields keep their names, shapes and rendering sites: the dry-run branch passes `directory=Path(PLANNED_RUN_DIR_TEXT)` exactly where a real run passes `run_dir(runs_root, state.run_id)`. So `review`'s `manifest:` line, its `publisher argv:` (which embeds the same value) and R2's rendered extra all read `<run dir>/artifacts/review-manifest.json`, and `fix`'s F4 manifest pointer and F1's `{closing_body}` read `<run dir>/artifacts/iter{N}-review-manifest.json` and `<run dir>/artifacts/iter{N}-closing-body.md`. Real runs are untouched: `run_dir(...)` still supplies the **absolute** path E7.3's PR 110 requires. Tests pin the literal `<run dir>/...` strings, assert the runs tree is unchanged, **and** assert no `<run dir>` directory appeared in the working tree — `Path("<run dir>")` is a relative path, so a stray write would land in the repo rather than under `runs/`, and a runs-tree-only assertion would miss it.
