Task: Hand the agents an evidence bundle (Design 8.1, EXTRACTION.md D16)

Requirements:
1. Evidence writer in `aidw/workflows/prompt.py` — a module-level helper that renders the six-element bundle below and writes it to `<run_dir>/stages/<stage>.evidence.md`, once per review stage and once per fix stage, returning the **absolute** path. It must `mkdir(parents=True, exist_ok=True)` on `stages/` itself: the real `run_stage` creates that dir lazily *inside* `run_stage`, but the writer runs *before* it.
2. Bundle contents — six elements, from sources already in scope:
   - prompt path (`rel`, repo-relative, already computed);
   - roadmap entry: `entry.task` + `entry.title` + `entry.file`/`entry.line` (`aidw/roadmap.py:RoadmapTask`) plus the **full** `Done when:` block, taken from the same re-read of `repo.root/docs/tasks/<entry.file>` starting at `entry.line`: the `Done when:` line and every continuation line up to the first blank line, the next `  - <Word>:` field bullet (e.g. `  - Tests:`), the next task line, or an epic/phase heading — whichever comes first — NOT `entry.done_when`, which `parse_file` fills from the first physical line only (multi-line Done-whens, e.g. L2.4's own four-line block, truncate to a fragment);
   - cited spec headings: `entry.citations` (`Design N` → `design.md §N`) plus the non-`Design` doc references, which `RoadmapTask` does not carry (`CITATION_RE` drops them): re-read the entry's own lines — `repo.root/docs/tasks/<entry.file>`, the task line at `entry.line` (its parenthesised detail) plus the same block's `Done when:` line, the lines `parse_file` reads `citations` from — collect the `<NAME>.md` tokens and map each to file+section: basename → the unique `<NAME>.md` under the repo root, `§n` → that section, `D<nn>` → the section heading naming it (this repo: `EXTRACTION.md D16` → `docs/migration/EXTRACTION.md` §3.8); list each with file+section so the reviewer opens the right section without re-deriving it;
   - prerequisite tick state: every task in `entry.file` at a line before `entry.line` (the same ordering `_incomplete_predecessors(entries, entry)` uses), each shown with its `[x]`/`[ ]` state — not only the unticked subset;
   - gate commands: the gate-command block read from the **target repo root only** — `repo.root / "AGENTS.md"` (`TargetRepo.root`, `aidw/paths.py`), never the toolkit root (`ToolkitPaths`) or a cwd-relative path (AGENTS.md "Two roots": the roots coincide in self-hosted runs, so a wrong-root read passes every test here and breaks only after extraction). Copy the `## Gates` section verbatim — the `## Gates` heading line through the line before the next `## ` heading (or EOF); in this repo that block is `uv sync --frozen`, `uv run --frozen pytest`, `uv run aidw doctor`, `uv run aidw agents validate --strict`, `uv run aidw prompts check`. Per D16/§3.8 the eventual source is root `AGENTS.md` + optional `aidw/conventions.md`, but since E7.3 has not landed, ignore (do not read) `aidw/conventions.md` and read `AGENTS.md` directly — do not add a second channel;
   - base-branch revisions: `git.rev_parse` of `repo.base_branch` and `origin/<base>`, each shown as its sha or an explicit "absent/unverifiable" note (mirror `_verify_base_branch`'s warn-and-continue).
3. Pointer in `extra` — every review AND fix stage's `extra` names its own evidence path. Prepend the pointer at every `task-review-*` and `task-review-fixes-*` `StageSpec`: the review loop (round 1 `""`, rounds 2+ `_render_delta_brief`), the fallback whole-review fix, and the per-finding / `render_could_fix_block` stages. Round 1's `extra` becomes the pointer only — L2.3's "unprimed" guarantee is about *prior findings*, not the gathered context the reviewer already reads via its Scope step.
4. Degrade, never error — every source read is wrapped; a missing `AGENTS.md`, missing gate section, unreadable prompt, or failed `rev_parse` yields an explicit "unavailable" note in that bundle section (still written where possible). If the file cannot be written at all, omit the pointer and warn on stderr. No exception escapes; the run continues exactly as today (model on `_render_delta_brief`'s unavailable-note path).
5. No shipped-prompt edit — do not touch `prompts/task-review.md` or `prompts/task-review-fixes.md`: the pointer is runtime `extra` text in `prompt.py` (L2.3's precedent). No new prompt file, no `aidw/inventory.py:REQUIRED_PROMPTS` change. Update `prompt.py`'s module docstring stage-2/3 lines to mention the evidence bundle.
6. `--dry-run` unchanged — the writer lives in the real-run review/fix loop; the dry-run path (plans only `task-review-1`, returns before the loop) writes no evidence file and adds no pointer.
