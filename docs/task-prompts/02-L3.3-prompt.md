Task: Snapshot the prompt at every fix stage (Design 9.1)

Requirements:
1. Snapshot writer in `aidw/workflows/prompt.py`: before **each** fix stage's `run_stage(...)` call, write the prompt's on-disk content to `<run_dir>/stages/<stage>.prompt.md`, where `<stage>` is the exact fix-stage name — `task-review-fixes-<revisions>` for the whole-review fallback and `task-review-fixes-<revisions>-<index>` for the per-finding/combined stages. Cover **both** call sites (the `if not findings or problems:` fallback and the `for index, (kind, group) in enumerate(steps)` loop).
2. Capture-before-run: take the snapshot *before* `run_stage`, so `snapshot(i)` equals the input to fix stage `i` — it already contains every earlier fix stage's mutations but not this stage's. Reuse `_capture_prompt(prompt_path)` (returns `str | None`); on `None`/`OSError`, warn on stderr and skip, never raise.
3. Degrade, never gate: follow the existing `_write_evidence_bundle` pattern — `stages.mkdir(parents=True, exist_ok=True)` before `run_stage` creates the dir lazily, and any write failure is a stderr warning that lets the stage run (the snapshot is recoverability, not a gate). Prompt-fixed decision: the roadmap does not specify the failure mode; the L2.4 bundle's warn-and-continue is the repo precedent.
4. Persist, don't temp: write under the run directory, never the `_DIFF_TMP_PREFIX` temp dir (`_prompt_diff` removes it in a `finally`) — a snapshot that is deleted is not recoverable.
5. Distinct name, no collision: `.prompt.md` must not collide with the L2.4 `.evidence.md` bundle, the `.jsonl`/`.out.txt`/`.meta.json` stage files, or the `_prompt_diff` `baseline/`/`current/` names. No `state.json` schema change — the snapshot is a plain run-dir artifact like the evidence bundle.
6. Keep the single final commit: `_commit_reviewed_prompt(repo.root, rel, phase, task)` commits only `[rel]` after the loop (design.md §18 risk row "Review-fix loop leaves the prompt uncommitted"; the roadmap calls this "§17's resolved decision"). Do not add the snapshot to that commit and do not add any per-stage commit.

Traps / prior review findings:
- Capture after `run_stage`, not before → the snapshot records the stage's output, so "the stage's input is recoverable" is false; `_fake_stages` in `tests/test_prompt_workflow.py` appends a round marker inside the fix stage, so ordering is observable in tests.
- Writing to `_DIFF_TMP_PREFIX` (L2.3) → `_prompt_diff`'s `finally: shutil.rmtree(...)` deletes it; a run ends with zero snapshots. L3.3 files belong under `directory / "stages"`, never a temp dir.
- Reusing `.evidence.md` (or a bare `.md`) → overwrites/clashes with L2.4's artifact, which also writes `stages/<stage>.*`. Use the `.prompt.md` suffix.
- Adding the snapshot path to `_commit_reviewed_prompt` → violates "not tracked by git" and "single final commit"; `_commit_reviewed_prompt` must keep committing exactly `[rel]` (`git.py:commit_paths`).
- Failing the run when the snapshot write fails → a read-only/odd run dir would kill the whole prompt run for a nicety; mirror `_write_evidence_bundle`'s warn-and-continue.
- Missing the fallback branch (`task-review-fixes-<revisions>`) → an unparseable review takes the single-stage path and would leave no snapshot; "every fix stage" means both branches.

Explicit non-goals — do NOT do these in this task:
- L3.4 (reconcile stage after each fix batch) is the next task in the same epic — do not add any new stage to the loop here.
- L4.1 (terminal review / revision-budget semantics) — do not touch `MAX_REVISIONS` or the last-round acceptance path.
- Do not change commit behaviour: no per-stage commits, no committing the run directory (AGENTS.md "Run state is machine-local and never committed"; design §13).
- Do not edit `design.md` §9.1's layout diagram — it is illustrative (L2.4's `.evidence.md` artifacts are not listed there either); L6.2 consolidates phase-02 decisions.
- Do not add a `state.json` field or a findings-manifest field — this is a run-dir artifact only.

Deliverables:
- aidw/workflows/prompt.py
- tests/test_prompt_workflow.py

Tests (what to prove, not the literal expects):
- Two-fix-stage run: using the existing `_fake_stages` harness, a run whose review yields exactly two fix stages leaves `stages/task-review-fixes-1-1.prompt.md` and `stages/task-review-fixes-1-2.prompt.md` under the run dir, in stage order.
- Input-of-stage property: snapshot `1-1` equals the prompt before any fix marker; snapshot `1-2` equals the prompt after stage `1-1`'s mutation — i.e. the diff between consecutive snapshots is exactly the immediately-preceding fix stage's net change (proves "every stage's input is recoverable").
- Fallback path: an unparseable review (`TASK_REVIEW_UNPARSEABLE`) still writes `stages/task-review-fixes-1.prompt.md`.
- Not tracked: `git.status_short(repo, paths=[...])` / `git.untracked_paths(repo)` shows the snapshots untracked (or under the gitignored `runs/`), and the single final commit contains no `stages/*.prompt.md` path.
- Degrade: monkeypatch the snapshot write to raise → the fix stage still runs and the run still succeeds (warn-only), matching the L2.4 bundle test.

Done when:
- `uv run --frozen pytest` is green with the new `test_prompt_workflow.py` cases above (two snapshots in stage order, per-stage-input content, fallback snapshot, untracked/not-committed, warn-only degrade).
- A run with two fix stages leaves exactly two `stages/*.prompt.md` files, and the final prompt is still a single commit of the prompt path — no per-stage commits and no snapshot in the commit.
- The diff touches only `aidw/workflows/prompt.py` and `tests/test_prompt_workflow.py`.

If anything in the cited spec section is ambiguous or underspecified for this task, stop and ask rather than guessing — especially:
- snapshot-write failure semantics: the roadmap does not say whether a failed snapshot blocks the run; this prompt fixes it to warn-and-continue per the L2.4 bundle precedent — if the snapshot is meant to be a hard gate, stop and reconcile before building;
- whether "every fix stage" includes the whole-review fallback path — this prompt reads it as yes (both fix call sites must snapshot);
- whether the snapshot must appear in `state.json` — this prompt fixes it to no (plain run-dir artifact, like the evidence bundle);
- the generic guard: security-sensitive, cost-committing, or hard-to-reverse changes (cross-account trust, schema changes, billing logic, data deletion).
