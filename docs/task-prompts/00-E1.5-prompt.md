Task: CLI plumbing — add `AIDW_REPO` and thread the resolved `TargetRepo`/`ToolkitPaths`/`WorkspacePaths` through every workflow, replacing the `(repo, aidt)` tuple.

Requirements:
1. Wire `AIDW_REPO` into target selection with the owner-confirmed precedence `--repo` > `AIDW_REPO` > cwd (recorded in the E1.1 prompt's "Resolved decisions"; mirrors `aidw/gates.py` `--gate-default` > `$AIDW_GATE_DEFAULT`). `--repo` keeps its typer validation (`exists=True, dir_okay=True, resolve_path=True` in `cli.py:_main`); `AIDW_REPO` is raw env and is passed through `TargetRepo.resolve(explicit=…)`, which already rejects a nonexistent/non-directory override by naming it and never falls back to cwd (`aidw/paths.py:TargetRepo.resolve` — E1.1 built `explicit=` for exactly this). A bad `AIDW_REPO` must raise/refuse, not operate on cwd. Update the `--repo` help and `_main` docstring to mention `AIDW_REPO`.
2. `_roots()` (`cli.py`) resolves ONCE and returns typed roots, not two `Path`s: prompt-fixed — return a 3-tuple `(TargetRepo, ToolkitPaths, WorkspacePaths)`, built as `TargetRepo.resolve(explicit=<--repo else AIDW_REPO else None>)` → `ToolkitPaths.resolve()` → `WorkspacePaths.resolve(target)`. It stops calling `repo_root()`/`toolkit_root()`. No command or workflow may re-resolve `TargetRepo`/`WorkspacePaths` inline afterwards (the `exec`/`runs` command bodies currently do `WorkspacePaths.resolve(TargetRepo.resolve(repo))` — that goes away).
3. Replace the `(repo: Path, aidt: Path)` workflow signature with typed roots (prompt-fixed naming — keep `repo`/`aidt`, add `workspace`): every `run()` in `aidw/workflows/{prompt,implement,review,fix,approve}.py` becomes `repo: TargetRepo, aidt: ToolkitPaths, workspace: WorkspacePaths`, and `runs_root = workspace.state_root / "runs"` replaces the per-site `WorkspacePaths.resolve(TargetRepo.resolve(repo)).state_root / "runs"`. `prompt.py`'s optional `runs_root: Path | None = None` test-injection parameter is replaced by the required `workspace` (tests inject a `WorkspacePaths` via `WorkspacePaths.resolve(..., state_dir_override=...)`). `run.py`'s `task_to_pr`/`review_and_fix` take the same three types and pass the SAME objects to the sub-workflows.
4. Below the workflow layer, primitives keep their `Path` parameters (prompt-fixed boundary): `run_stage(repo_root=…, toolkit_root=…)`, `resolve_prompt(toolkit_root, …)`, `load_all(toolkit_root, repo_root)`, `create_run(runs_root, repo_root, …)`, `run_dir`, `build_plan`/`PlanStage.spec(aidt)`, and `find_task_prompt(repo, …)` are unchanged; workflows pass `repo.root` / `aidt.root` / `aidt.prompts_dir` / `runs_root`. Every workflow/CLI call site that today passes `repo` or `aidt` as a `Path` (`repo / "docs"`, `git.current_branch(repo)`, `create_run(runs_root, repo, …)`, `load_all(aidt, repo)`, `aidt / "prompts" / …`) switches to the `.root`/`.prompts_dir` form.
5. Update the remaining CLI command bodies to the 3-tuple: `tasks` (`repo.root / "docs" / "tasks"`), `agents` (`load_all(aidt.root, repo.root)`), `exec` and `runs` (`workspace.state_root / "runs"`; `create_run(runs_root, repo.root, …)`; `run_stage(repo_root=repo.root, toolkit_root=aidt.root, …)`; `resolve_prompt(aidt.root, …)`; `stage_lines(..., repo_root=repo.root)`). The `prompts` command stays toolkit-only and must NOT resolve a target: use `ToolkitPaths.resolve().root` for `inventory.*` (works with no repo).
6. No behavioural change to the frozen surface (§3.3): commands, exit codes, stdout keys (`run:`, `rendered: runs/…`, `workflow:`) and the `state.json` shape are unchanged. Run locations already moved to the state root in E1.4 — do not move them again. The only observable deltas are target selection (now honours `AIDW_REPO` and `explicit=` validation) and the internal typing.
7. Keep `aidw/paths.py` and `aidw/runner.py` untouched (`TargetRepo.resolve(explicit=…)`, `ToolkitPaths.resolve()`, `WorkspacePaths.resolve()` and the primitive signatures already exist). `repo_root()`/`toolkit_root()` remain defined in `paths.py` for `doctor.py` and `ToolkitPaths.resolve`'s delegation — this task only removes their use in `cli.py`.

Traps / prior review findings:
- `repo` is now a `TargetRepo`, not a `Path`: `repo / "docs"` and `git.current_branch(repo)` raise `TypeError`. Grep every `repo / `, `current_branch(repo)`, `create_run(runs_root, repo,`, `load_all(aidt, repo)` and `aidt / "prompts"` across `aidw/workflows/` and `aidw/cli.py` and switch each to `.root`/`.prompts_dir`.
- Don't pass `AIDW_REPO` as `start=` — only `explicit=`. `start=` walks up from a bad path and falls back to cwd; `explicit=` is the E1.1 validation path that raises and never falls back. A `--repo`/`AIDW_REPO` pointing at a non-repo dir must refuse, not silently operate on cwd.
- Precedence backwards is a real bug: `--repo` must beat `$AIDW_REPO`. Mirror `aidw/gates.py` (`--gate-default` > `$AIDW_GATE_DEFAULT`), don't invent `env beats flag`.
- Re-resolving `TargetRepo`/`WorkspacePaths` per workflow or inside a chain (`run.py`) wastes git calls and can diverge — E1.4's "resolve-once-and-thread" rule carries over: `_roots()`/`task_to_pr` are the only resolution sites; the workflows receive the objects.
- The ~15 `tests/test_prompt_workflow.py` call sites pass `runs_root=tmp_path / RUNS_DIRNAME`; after the signature change they must construct a `WorkspacePaths` (via `state_dir_override=`) — a missed kwarg fails as `TypeError: unexpected keyword argument`, and keeping a fallback `runs_root=None` param would quietly reintroduce per-site resolution.
- `tests/test_implement_workflow.py` etc. pass `aidt=tmp_path / "aidt"` as a placeholder; with `aidt: ToolkitPaths` they should pass `ToolkitPaths.resolve()` (safe because `run_stage` is `_Recorder`-patched) or a hand-built `ToolkitPaths` — don't smuggle the old `Path` through with a cast.

Explicit non-goals — do NOT do these in this task:
- E1.6 `aidw config show` — the next task in Epic E1; keep it out.
- E2.2 layout guards (warn state root inside a working tree / fail workspace-root-is-a-worktree), E2.7 run lock into the state root, E2.8 doctor workspace/state-root/git checks — separate tasks; `doctor.py` keeps using `repo_root()`/`toolkit_root()` this task.
- E3.x config-driven `paths.state_root` / `repo.base_branch` from YAML (D17/D3) — `TargetRepo.base_branch` stays `"main"` and the hardcoded three-tier state formula stays.
- No new root type (no `Roots` dataclass, no bundling object) — a plain 3-tuple is the threading shape; the spec (§3.1) mandates distinct `ToolkitPaths`/`TargetRepo`/`WorkspacePaths` types, nothing more.
