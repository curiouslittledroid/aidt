Task: CLI plumbing — add `AIDW_REPO` and thread the resolved `TargetRepo`/`ToolkitPaths`/`WorkspacePaths` through every workflow, replacing the `(repo, aidt)` tuple.

Requirements:
1. Wire `AIDW_REPO` into target selection with the owner-confirmed precedence `--repo` > `AIDW_REPO` > cwd (recorded in the E1.1 prompt's "Resolved decisions"; mirrors `aidw/gates.py` `--gate-default` > `$AIDW_GATE_DEFAULT`). `--repo` keeps its typer validation (`exists=True, dir_okay=True, resolve_path=True` in `cli.py:_main`); `AIDW_REPO` is raw env, normalized in `cli.py` before it reaches `TargetRepo.resolve`: `os.environ.get("AIDW_REPO")` is `.strip()`ed, an empty/whitespace-only value is treated as unset (precedence falls through to cwd, never to `Path("")`), and a non-empty value is wrapped `Path(value)` before `TargetRepo.resolve(explicit=…)` — `explicit` is typed `Path | None` and `Path("").resolve()` is cwd, so passing the raw env text through would silently operate on cwd. `TargetRepo.resolve(explicit=…)` already rejects a nonexistent/non-directory override by naming it and never falls back to cwd (`aidw/paths.py:TargetRepo.resolve` — E1.1 built `explicit=` for exactly this). A bad `AIDW_REPO` must refuse at the CLI — not operate on cwd, not traceback: `_roots()` (the single resolution site, Requirement 2 — `prompts` never calls it, Requirement 5) wraps its `TargetRepo.resolve` call in `except RepoNotFoundError`, which also catches the `BareRepositoryError` subclass (`aidw/paths.py`), does `typer.echo(str(exc), err=True)` — the E1.1 messages already name the bad path, and the bare case keeps its distinct bare-specific message — and raises `typer.Exit(EXIT_REFUSED)` (4 — design.md §14 "preflight/safety refusal"; the constant already exists unused in `cli.py`, this is its first use). That one catch site covers every `explicit=` failure: a bad `AIDW_REPO`, or a `--repo` that passes Typer's `exists=True` but is not a repo or is bare. Update the `--repo` help and `_main` docstring to mention `AIDW_REPO`.
2. `_roots()` (`cli.py`) resolves ONCE and returns typed roots, not two `Path`s: prompt-fixed — return a 3-tuple `(TargetRepo, ToolkitPaths, WorkspacePaths)`, built as `TargetRepo.resolve(explicit=<--repo else AIDW_REPO else None>)` → `ToolkitPaths.resolve()` → `WorkspacePaths.resolve(target)`. It stops calling `repo_root()`/`toolkit_root()`. No command or workflow may re-resolve `TargetRepo`/`WorkspacePaths` inline afterwards (the `exec`/`runs` command bodies currently do `WorkspacePaths.resolve(TargetRepo.resolve(repo))` — that goes away).
3. Replace the `(repo: Path, aidt: Path)` workflow signature with typed roots (prompt-fixed naming — keep `repo`/`aidt`, add `workspace`): every `run()` in `aidw/workflows/{prompt,implement,review,fix,approve}.py` becomes `repo: TargetRepo, aidt: ToolkitPaths, workspace: WorkspacePaths`, and `runs_root = workspace.state_root / "runs"` replaces the per-site `WorkspacePaths.resolve(TargetRepo.resolve(repo)).state_root / "runs"`. `prompt.py`'s optional `runs_root: Path | None = None` test-injection parameter is replaced by the required `workspace` (tests inject a `WorkspacePaths` via `WorkspacePaths.resolve(<target>, state_dir_override=<isolated tmp dir>)` — `resolve` appends the repo slug, so the injected runs root is `workspace.state_root / "runs"`, under the override, never at it). `run.py`'s `task_to_pr`/`review_and_fix` take the same three types, pass the SAME objects to the sub-workflows, and unwrap `repo` for their own direct uses — the dry-run `prompt_path` is built as `repo.root / "docs" / "task-prompts" / f"{phase}-{task}-prompt.md"` and the post-`prompt` lookup calls `find_task_prompt(repo.root, phase, task)` (the primitive keeps its `repo: Path` parameter, so passing the `TargetRepo` itself would `TypeError`).
4. Below the workflow layer, primitives keep their `Path` parameters (prompt-fixed boundary): `run_stage(repo_root=…, toolkit_root=…)`, `resolve_prompt(toolkit_root, …)`, `load_all(toolkit_root, repo_root)`, `create_run(runs_root, repo_root, …)`, `run_dir`, `build_plan`/`PlanStage.spec(aidt)`, and `find_task_prompt(repo, …)` are unchanged, and so do all `aidw/git.py` helpers (`current_branch`/`status_short`/`is_clean`/`commit_paths`/`changed_files` — each takes `repo: Path`), all `aidw/github.py` helpers (`pr_view(repo)`, `script_path(aidt)`, `select_followups`/`verify_approvals(aidt, repo)`), `load_tasks(tasks_dir)` (`aidw/roadmap.py`), and `print_stage`/`stage_lines` (`repo_root: Path`, `aidw/report.py`) — none of those modules is a deliverable. The private sub-`run()` helpers inside the workflow modules — `prompt.py`'s `_resolve_prompt_path(repo)`/`_commit_reviewed_prompt(repo)`, `implement.py`'s `_gate_summary(state, repo)`/`_record_pr(state, repo)` — keep `Path` params like `build_plan`/`spec`, so only their `run()` call sites unwrap. Workflows pass `repo.root` / `aidt.root` / `aidt.prompts_dir` / `runs_root`. Every workflow/CLI call site that today passes `repo` or `aidt` as a `Path` — `repo / "docs"`, `repo / raw_path`, every `git.*(repo)`, `github.pr_view(repo)`, `github.script_path(aidt)`, `github.select_followups`/`verify_approvals(aidt, repo)`, `create_run(runs_root, repo, …)`, `load_all(aidt, repo)`, `load_tasks(repo / "docs" / "tasks")`, `aidt / "prompts" / …`, `prompt_path`/`manifest_path` `.relative_to(repo)`, `print_stage(…, repo_root=repo)`, `build_plan(aidt=aidt)`, `entry.spec(aidt)`, and the `_`-helper calls — switches to the `.root`/`.prompts_dir` form.
5. Update the remaining CLI command bodies to the 3-tuple — all ten `_roots()` call sites in `cli.py` unpack `repo, aidt, workspace = _roots()`, none keeps the 2-tuple. The six workflow bodies `prompt`, `implement`, `review`, `fix`, `approve-followups` (`approve_followups`) and `run` (`run_chain`) forward the typed `repo`/`aidt` unchanged plus `workspace=` to their Requirement-3 entries (`*_workflow.run`; `run` passes the same three objects to both `run_workflow.task_to_pr` and `run_workflow.review_and_fix` — these bodies touch no paths themselves, so they need no `.root` unwraps, but an untouched 2-tuple unpack breaks the command). `tasks` (`repo.root / "docs" / "tasks"`), `agents` (`load_all(aidt.root, repo.root)`), `exec` and `runs` (`workspace.state_root / "runs"`; `create_run(runs_root, repo.root, …)`; `run_stage(repo_root=repo.root, toolkit_root=aidt.root, …)`; `resolve_prompt(aidt.root, …)`; `stage_lines(..., repo_root=repo.root)`) unpack the same 3-tuple. The `prompts` command stays toolkit-only and must NOT resolve a target: use `ToolkitPaths.resolve().root` for `inventory.*` (works with no repo).
6. No behavioural change to the frozen surface (§3.3): commands, exit codes, stdout keys (`run:`, `rendered: runs/…`, `workflow:`) and the `state.json` shape are unchanged. Run locations already moved to the state root in E1.4 — do not move them again. The only observable deltas are target selection (now honours `AIDW_REPO` and `explicit=` validation, including the Requirement-1 `EXIT_REFUSED` refusal for a bad override) and the internal typing.
7. Keep `aidw/paths.py` and `aidw/runner.py` untouched (`TargetRepo.resolve(explicit=…)`, `ToolkitPaths.resolve()`, `WorkspacePaths.resolve()` and the primitive signatures already exist). `repo_root()`/`toolkit_root()` remain defined in `paths.py` for `doctor.py` and `ToolkitPaths.resolve`'s delegation — this task only removes their use in `cli.py`.

Traps / prior review findings:
- `repo` is now a `TargetRepo`, not a `Path`: `repo / "docs"`, `git.is_clean(repo)` and `print_stage(…, repo_root=repo)` raise `TypeError`. Grep every `repo / `, `git.current_branch(`/`git.status_short(`/`git.is_clean(`/`git.commit_paths(`/`git.changed_files(`, `github.pr_view(`/`github.script_path(`/`github.select_followups(`/`github.verify_approvals(`, `load_tasks(`, `relative_to(repo)`, `repo_root=repo`, `build_plan(aidt`, `entry.spec(aidt)`, `create_run(runs_root, repo,`, `load_all(aidt, repo)` and `aidt / "prompts"` across `aidw/workflows/` and `aidw/cli.py` and switch each to `.root`/`.prompts_dir` — the same matches inside the `Path`-typed `_`-helper bodies (`_resolve_prompt_path`, `_commit_reviewed_prompt`, `_gate_summary`, `_record_pr`) stay as-is; only their call sites in `run()` unwrap.
- Don't pass `AIDW_REPO` as `start=` — only `explicit=`. `start=` walks up from a bad path and falls back to cwd; `explicit=` is the E1.1 validation path that raises and never falls back. A `--repo`/`AIDW_REPO` pointing at a non-repo dir must refuse, not silently operate on cwd.
- Precedence backwards is a real bug: `--repo` must beat `$AIDW_REPO`. Mirror `aidw/gates.py` (`--gate-default` > `$AIDW_GATE_DEFAULT`), don't invent `env beats flag`.
- Re-resolving `TargetRepo`/`WorkspacePaths` per workflow or inside a chain (`run.py`) wastes git calls and can diverge — E1.4's "resolve-once-and-thread" rule carries over: `_roots()` is the sole `TargetRepo`/`WorkspacePaths` resolution site (the `prompts` command resolves only `ToolkitPaths`, for its toolkit-only path); `run.py`'s `task_to_pr`/`review_and_fix` and the workflows receive the typed objects and pass those SAME objects to the sub-workflows — resolve nowhere else.
- The ~15 `tests/test_prompt_workflow.py` call sites pass `runs_root=tmp_path / RUNS_DIRNAME`; after the signature change they must construct a `WorkspacePaths` (via `state_dir_override=`) — a missed kwarg fails as `TypeError: unexpected keyword argument`, and keeping a fallback `runs_root=None` param would quietly reintroduce per-site resolution.
- `tests/test_implement_workflow.py` etc. pass `aidt=tmp_path / "aidt"` as a placeholder; with `aidt: ToolkitPaths` they should pass `ToolkitPaths.resolve()` (safe because `run_stage` is `_Recorder`-patched) or a hand-built `ToolkitPaths` — don't smuggle the old `Path` through with a cast.
