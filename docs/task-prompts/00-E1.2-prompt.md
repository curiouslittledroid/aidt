Task: Formalise the toolkit-root resolution into a `ToolkitPaths` type exposing `prompts_dir`, `agent_configs_dir`, `agents_dir`, `scripts_dir`; make `aidw doctor` report the toolkit root from `/tmp`.

Requirements:
1. Add a frozen `ToolkitPaths` dataclass in `aidw/paths.py`, mirroring the existing `TargetRepo` shape. It is a distinct type from `TargetRepo` (EXTRACTION.md §3.1 "use two distinct types … rather than one `root: Path`"). Its sole construction entry point is the classmethod `ToolkitPaths.resolve() -> ToolkitPaths`. "Sole" is a call-site convention, not an enforced invariant: mirror the `TargetRepo` shape exactly — a plain frozen dataclass, no `__init__` guard or private-init machinery (which would diverge from `TargetRepo`); the convention is that callers use `resolve()`, never `ToolkitPaths(root=…, …)` by hand, verified by the `rg` guard in the Done-when.
2. Expose exactly `root`, `prompts_dir`, `agent_configs_dir`, `agents_dir`, `scripts_dir` — all absolute `.resolve()`d `Path`s. `root` is the toolkit root (§3.1 names it and the Done-when reports it); the four dirs are the fields the roadmap lists.
3. Resolve `root` from the package location, never from git or cwd: delegate to the existing `toolkit_root()` (`aidw/paths.py:toolkit_root`, i.e. `Path(__file__).resolve().parent.parent`), which stays the single source of truth for that value — `ToolkitPaths` must not re-derive it. Do not call `repo_root()` or any git command in `ToolkitPaths`.
4. Derive the dirs per §3.1/§3.12: `prompts_dir = root/"prompts"`, `agent_configs_dir = root/"agent-configs"`, `agents_dir = root/"agents"`, `scripts_dir = prompts_dir/"scripts"` — §3.1 names the script dir as `prompts/scripts/`, not `root/scripts` (matches `inventory.REQUIRED_SCRIPTS`, which is relative to `prompts_dir`).
5. Keep the transitional helpers working unchanged: `toolkit_root()` keeps its current `Path(__file__)`-based body — it is the source of truth that `ToolkitPaths.resolve()` delegates to (Requirement 3), not a wrapper over `ToolkitPaths`; `aidt_root()` and `runs_dir()` keep their current behaviour. E1.4 deletes the two aliases — do not do that here.
6. Add a doctor check that reports the toolkit root. Place it in `collect_checks()` (`aidw/doctor.py`) in the first checks list, *before* the `repo_root()` try/except that returns early on `RepoNotFoundError` — otherwise `aidw doctor` from `/tmp` (no repo) never prints it. Derive it from `ToolkitPaths.resolve()`, and keep the existing prompts/agent-configs checks working (they currently read `aidt_root()`). Its status is not decorative — pin it under doctor's `OK`/`WARN`/`FAIL` contract (`FAIL` = blocker, per the `doctor.py` module header): name the check exactly `"toolkit root"`; it is `OK`, with detail naming the resolved `root`, when `resolve()` succeeds and all four dirs exist; it is `FAIL`, with detail naming the root and the missing dir(s), when `resolve()` raises, the resolved `root` does not exist, or `prompts_dir`/`scripts_dir` is missing (the workflow-critical assets — mirroring the existing `prompts` check, which is `FAIL` on inventory errors; a pre-E8.1 installed wheel missing its assets is exactly the breakage this must not hide); it is `WARN`, same detail shape, when only `agent_configs_dir`/`agents_dir` is missing (mirroring the existing `agent configs` check's `WARN` for "none found").

Traps / prior review findings:
- `doctor.collect_checks()` returns early when `repo_root()` raises (`RepoNotFoundError` branch) — that early return currently skips the prompts/agent-configs checks entirely; the toolkit-root check must be added before it or `/tmp` shows nothing.
- Do not reach for git in `ToolkitPaths`: from `/tmp` `repo_root()` raises, and the whole point of §3.1 is the toolkit root is cwd/git-independent. `Path(__file__)` is the only source.
- `scripts_dir` lives under `prompts/`, not at the toolkit root — `root/"scripts"` does not exist; `inventory.REQUIRED_SCRIPTS` uses `scripts/review-followup/…` relative to `prompts_dir`.
- E0.4's tests in `tests/test_paths.py` pin `toolkit_root()`, `runs_dir()` and `aidt_root()` behaviour — they must stay green unmodified; do not rename or remove those functions.
- `ToolkitPaths` must not become a `root: Path` alias or a thin wrapper returning a bare `Path`; §3.1's rule exists to keep toolkit-relative and target-relative paths from being interchangeable.

Explicit non-goals — do NOT do these in this task:
- E1.4 (port consumers, delete `aidt_root()`/`runs_dir()`, rewrite `test_paths.py`) and E1.5 (CLI plumbing: threading `ToolkitPaths`/`TargetRepo` through workflows) — separate tasks, don't start them here.
- E1.3 workspace/state root — separate task.
- E8.1 packaging: shipping `prompts/`/`agent-configs/`/`agents/` in the wheel and the `uv tool install` asset layout. Do not touch `pyproject.toml` or the hatch build config in this task.
  Scope reconciliation with the roadmap note that E1.2 "covers the installed (non-repo, `uv tool install`) case": `pyproject.toml` ships only the `aidw` package (`[tool.hatch.build.targets.wheel] packages = ["aidw"]`), so the sibling asset dirs do not exist in an installed venv — the installed-wheel asset layout stays unresolved until E8.1 owns it (its Done-when verifies `uv tool install` then `aidw doctor` from an unrelated directory). What this task covers of the "installed case" is only its non-repo, cwd/git-independent half: resolving from the package location (never git/cwd) and the `/tmp` proofs below, asserted against the in-checkout layout.

Tests (what to prove, not the literal expects):
- `ToolkitPaths.resolve()` is cwd-independent: with `monkeypatch.chdir` into an unrelated `tmp_path`, `root == toolkit_root()` and the four dirs are absolute `.resolve()`d paths.
- Resolution never touches git: resolve succeeds in a bare `tmp_path` with no `.git` (no `repo_root()` call, no git subprocess).
- Dir derivation: `scripts_dir == prompts_dir / "scripts"`, and the four dirs point at the real shipped assets — `prompts_dir/"task-prompt.md"` exists, `agent_configs_dir` contains `*.yaml`, `agents_dir` has subdirectories, `scripts_dir/"review-followup"` exists. These asset assertions hold in-checkout (where the suite runs); asserting them under an installed wheel is E8.1's, per the non-goals.
- Doctor reporting from a non-repo cwd: `collect_checks()` (with cwd patched to `tmp_path`) still includes a `"toolkit root"` check with status `OK` whose detail names `ToolkitPaths.resolve().root`, while "repo root" is `FAIL`. The status is not vacuous: with `aidw.paths.toolkit_root` monkeypatched to a `tmp_path` containing none of the four dirs, the check is `FAIL` with a detail naming the missing dirs; with only `agents_dir` absent it is `WARN` (the monkeypatch reaches the check because `resolve()` delegates to the module-global `toolkit_root`, Requirement 3).
- Type distinctness: `ToolkitPaths` and `TargetRepo` are different types; constructing `TargetRepo` is unchanged by this task. (No test asserts that direct `ToolkitPaths(…)` construction fails — per Requirement 1, exclusivity is convention, not enforcement; the call-site guard lives in the Done-when, not the suite.)
