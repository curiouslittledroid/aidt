Task: Add a path-scoped stage condition and gate `update-traceability` (I3) on it (Design 8.2, Design 12.2)

Requirements:
1. Per roadmap S1.1: add `WHEN_PATHS_CHANGED = "paths-changed"` to `aidw/stage_registry.py`,
   joining the `when=` vocabulary beside `WHEN_EVIDENCE_GREEN`/`findings`/`blocking`/`could-fix`/
   `unparseable`. Like `WHEN_EVIDENCE_GREEN` it is **carried, never expanded away**
   (`_expand_static` omits only on `when=findings` with `findings is False` — no change there);
   `plan_stages`/`build_plan`/`--dry-run` still plan the stage in position.
2. Attach `when=WHEN_PATHS_CHANGED` to `I3 update-traceability` in the registry
   (`_IMPLEMENT.stages`, the `StageDefinition("I3", ...)` entry) — with **no** registry-default
   path set.
3. Add a config-declared path set: a new optional stage field on `workflows.<name>.stages[]`,
   prompt-fixed name `when_paths` (a list of repo-relative path prefixes), in
   `aidw/target_config.py` (`STAGE_KEYS`, `StageConfig`, `_parse_stage`, `to_dict`). Note the
   roadmap's "`aidw/config.py`" is imprecise — stage fields live in `aidw/target_config.py`, and
   `aidw/config.py` is agent config (design §5). Document the key in `docs/target-repo-config.md`
   (the stage-fields table). A wrong-typed (non-list) value
   is one `ERROR` issue and the field is dropped, like `_parse_parallel_groups`; each entry must be
   a string naming a repo-relative prefix — a non-string, absolute, `.`, `..` or empty entry is one
   `ERROR` naming the dotted entry path and is dropped while parsing continues, and the surviving
   valid entries are normalised, sorted and deduped by `normalise_ignore`'s rules. That helper
   raises `ValueError` on exactly those bad entries; the loader converts each to the named-field
   `ERROR` and never propagates it (fail-closed, design §12.1).
4. Carry the path set onto the spec: additive field `aidw/runner.py:StageSpec.when_paths`
   (default `()`), read in `_spec_from_planned` from the declared entry (type-guarded), so a
   registry stage with no declared entry keeps the empty default. Empty `when_paths` on a
   `WHEN_PATHS_CHANGED` stage means the stage always runs — today's unconditional behaviour.
5. Evaluate before `run_stage`, in the same place `WHEN_EVIDENCE_GREEN` is evaluated
   (`aidw/workflows/implement.py:withhold_tick`, called from the serial `execute()` and from the
   `--parallel` `runnable` filter): when `entry.when == WHEN_PATHS_CHANGED` and the change set
   touches **none** of `entry.when_paths`, record a skipped stage via
   `aidw.runner.record_skipped` (reason in `SKIP_REASON_KEY`, `error` unset, no
   `state.status`/`state.resume` write — a skip is a success, never a failure) and do not invoke
   `run_stage`. Generalize `withhold_tick` (or add a sibling called from the same two sites) so
   both tokens dispatch. `--dry-run` evaluates nothing (the dry-run path already returns before
   the loop).
6. The change set is the one the I7 condition already computes:
   `aidw/git.py:changed_paths(repo_root, base=aidw/verification.py:BASE_DEFAULT)` plus
   `aidw/git.py:untracked_paths(repo_root)`, with the run's state root excluded (as
   `verification.tree_identity` does via its `exclude`). Fail closed on "cannot prove": if
   `changed_paths` returns `None` (unresolvable base), do **not** skip — run the stage.
7. Matching semantics (prompt-fixed): a changed path touches a declared prefix iff
   `path == prefix or path.startswith(prefix + "/")` — mirror `aidw/verification.py:_excluded`;
   normalize declared prefixes with `verification.normalise_ignore` before comparing.
8. Update design.md: §8.2 (a paragraph on `WHEN_PATHS_CHANGED` and I3 carrying it, its
   evaluation point and skip record, and the empty-default = unconditional rule), §12.2 (the new
   token/stage key), and §17 row Z11 recording the prompt-fixed decisions below in the
   Z1/Z9 "spec fixed only the shape" format.

Traps / prior review findings:
- The roadmap's "default path set covering the rules-engine sources, `docs/rules-coverage` and
  the vector-matrix directories" is the **Mythical Forge audit example**, not a toolkit default:
  toolkit defaults stay product-free (design §7.1 — a target repo with no `aidw/` folder must still
  run; §17 S1 records the neutralisation), so hardcoding those paths in `aidw/stage_registry.py`
  violates that principle. No test scans `aidw/*.py` for product literals
  (`test_prompt_neutrality.py` reads `prompts/` only, `test_agent_guidance_neutrality.py` reads
  `agents/*/AGENTS.md` only) — the principle is the guard, not a failing gate. The
  toolkit default is an empty set (unconditional); a repo declares its own `when_paths`.
- Both dispatch paths must evaluate: the `--parallel` member loop submits to the pool directly
  (bypassing `execute()`), so the check must also run in the
  `runnable = [member for member in active if not withhold_tick(member)]` filter, exactly as
  `WHEN_EVIDENCE_GREEN` does — a missed parallel path runs I3 when it should have skipped.
- Skip ≠ gate: this is a cost-control *skip*, not a red-gate verdict. Don't touch
  `state.status`/`state.resume` and don't set `error` (it renders as a failure —
  `aidw/report.py:stage_lines`); use `record_skipped`, which already resolves the agent the stage
  would have run (`stage_agent`) and persists under `_STATE_LOCK`.
- The base matters: use `verification.BASE_DEFAULT`, not `repo.base_branch`, so the change set
  equals the one I7's evidence and the recorded gates already measure against (the prompts pass no
  `--base`). A different base would silently always- or never-skip.
- "Cannot prove" must not skip: `changed_paths` returns `None` for an unresolvable base, and an
  empty list is a real answer ("no changes") — only `None` is ambiguous. Distinguish them;
  skipping on `None` drops a stage that should have run.
- `tests/test_workflow_stages_doc.py:test_condition_table_names_exactly_the_declarable_tokens`
  and `tests/test_stage_registry.py:test_the_when_vocabulary_is_exported_and_distinct` hardcode
  the token set — both must gain `WHEN_PATHS_CHANGED`, and `docs/workflow-stages.md`'s Conditions
  table plus I3's `when=` cell must be updated, or `uv run --frozen pytest` fails even with the
  feature correct. The roadmap's test list omits these two files; they are required (Z4's "a new
  `when=` cannot ship undocumented").

- Don't gate I3 on `WHEN_EVIDENCE_GREEN` or read `state.gate_outcomes` for this skip; this is
