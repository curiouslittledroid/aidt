Task: Teach agents to handle blocked bash commands (design §5.5).

Requirements:
1. Edit **every** `agents/*/AGENTS.md` (all 11 files) to add a short, self-contained block
   telling the agent how to handle a blocked bash command. (prompt-fixed: the entry says "or
   the shared context they assemble from", but no shared fragment or assembly mechanism exists —
   each `agent-configs/<id>.yaml` points `agents_md:` at its own file per design.md §5.5 — and
   every agent's allowlist grants `bash`, so editing the 11 files is the smallest change that
   reaches every agent.)
2. The block must carry the entry's three behaviours, not paraphrase them away: (a) the result
   is a **hard deny** — never treat it as retryable; (b) do **not** retry the command, and in
   particular do not retry cosmetic variants (reordering, re-quoting, splitting, alternative
   syntax, a rename); (c) report it as a blocker **naming the denied command**. The exact string
   `Blocked bash command with unapproved operations` must appear verbatim (it is Pi's real
   tool-result text, quoted in the roadmap), so the agent can match the block when it sees it.
3. Neutrality: the added text must introduce no product, package-manager, or product-path token,
   no slash-command, and no `AGENTS.md §N` form — `tests/test_agent_guidance_neutrality.py`
   greps the whole glob and its sweep must stay green. In particular, write no example command
   (any command example risks a forbidden `uv`/`npm` token). The phrase itself is clean.
4. Record the contract in design.md: one new bullet under §5.5 stating that shipped agent
   context files instruct agents that a `Blocked bash command with unapproved operations`
   result is a hard deny (do not retry, report naming the denied command), and one §17 row
   appended with the **next free id** (Z21 today — verify against §17 and append the next free,
   never reuse/renumber, per `aidw/conventions.md`) naming task O1.1, the files changed, and the
   prompt-fixed decisions listed here.
5. Pin the contract: add the content test to `tests/test_agent_guidance_neutrality.py` and the
   §5.5/§17 pins to `tests/test_design_doc.py`. (prompt-fixed: the roadmap names
   `tests/test_agent_configs.py`, which does not exist; the equivalent that reads the whole
   `agents/*/AGENTS.md` glob and asserts `agents validate`-style reachability is
   `tests/test_agent_guidance_neutrality.py`.)

Traps / prior review findings:
- Prompt text alone does not override an agent file's hard rules (design.md §17 Z9/D9, Z20). The
  fix must live in `agents/*/AGENTS.md` itself, not in a stage prompt — otherwise a real Pi
  implementer keeps retrying.
- The exact phrase matters: match `Blocked bash command with unapproved operations` verbatim. A
  "close enough" rewording means the agent won't recognise the block when it sees it.
- Do not teach a workaround ("try a different quoting/command/approach"): the block is a
  stop-and-surface signal, not a puzzle to solve. Any such sentence re-opens the blind-retry loop.
- The neutrality sweep (`tests/test_agent_guidance_neutrality.py::_vocabulary`) fails on any
  product/package-manager/path token, and separately forbids slash-commands and `AGENTS.md §N`.
- `aidw agents validate --strict` only checks that each config's `agents_md:` file exists and
  reads — it does **not** check content. Content coverage must come from the new test, not the
  gate.
- Content-only edit: do not move/rename the files or change any `agents_md:` path, or the
  reachability test and the gate break.
