Task: Worktree fixtures — a test helper that builds a temporary bare repo with a `main` worktree and a task worktree, wired off the bare repo exactly as §3.2 specifies.

Requirements:
1. Shared fixture in `tests/conftest.py` (next to `GIT_IDENTITY` / `_git_identity` / `fake_external_clis`): a function-scoped `@pytest.fixture` named `worktree_repo` (prompt-fixed name; spec silent) that yields a small dataclass `WorktreeRepo` with `bare: Path`, `control: Path` (the `main` worktree), `task: Path` (the task worktree), `workspace: Path` (the `tmp_path` root), and a helper `add_task(branch, *, base="main") -> Path` that adds a *further* sibling worktree on a new branch. Collision contract: `add_task` **raises** when the branch or target path already exists (git's refusal surfaced — it cannot return `None`, its signature yields a `Path`), so `add_task("task")` always raises; the pre-created task worktree is `repo.task`.
2. Wire exactly as §3.2: build a committed seed repo (`git init -b main` + one file + commit) → `git clone --bare` to `<workspace>/bare.git` → `git -C bare.git worktree add ../main main` (control worktree) → `git -C <control> worktree add -b task <workspace>/task main` (the §3.2 per-task command, run from the **control** worktree, mirroring `aidw/git.py:add_worktree`). `bare.git`, `main`, `task` are siblings under `workspace`.
3. Reuse the session identity: rely on `tests/conftest.py::_git_identity` (the `GIT_IDENTITY` env it exports); never run per-repo `git config user.*` (AGENTS.md — two spawns × ~300 repos).
4. Self-cleaning: everything under `tmp_path` so pytest removes it; write nothing outside `tmp_path` — no `.aidw/state`, no toolkit `runs/` — so `_clean_test_runs` stays green. No `git worktree remove` in teardown (tmp_path teardown is enough; extra spawns are pure cost).
5. Migrate at least three tests across two modules to use `worktree_repo`, and delete the local helpers left unused. Natural consumers: `tests/test_layout.py` (`_make_supported` supported-layout tests) and `tests/test_worktree_cli.py` (`_make_bare_with_control` tests) — every test using those two helpers migrates, so the deletion boundary is exact: delete `test_layout.py::_make_supported` and `test_worktree_cli.py::_make_bare_with_control`, plus test_worktree_cli.py's `_make_bare`, `_init_committed_repo`, `_add_task` (nothing else in that module calls them); keep `test_layout.py::_make_bare` (the bare-refusal and spaced-paths tests need a bare with no control worktree), `_make_trap` / `_make_plain_clone`, and every other module's local helpers — test_git.py is out of scope, its same-shaped `_make_bare_with_control` included. Branch-name rule for migration: those modules' `_add_task(control, "task")` / `_make_supported(task_worktree=True)` call sites become the fixture's pre-created `repo.task` — never `add_task("task")` (git refuses an already-checked-out branch; `aidw/git.py:add_worktree` returns `None` in exactly that case). `add_task` is for *additional* branches only (`feat`, `other`). Keep consumers asserting against real git output, not faked porcelain.
6. Tests-only change: `aidw/`, `prompts/`, `agent-configs/` stay untouched.

Traps / prior review findings:
- Empty `git init` has no `main` ref: `git clone --bare` of a commit-less seed, then `worktree add ../main main`, fails with "invalid reference: main". Always commit one file first (`_init_committed_repo` shape, not test_git.py's `_init_repo`).
- Running the task-worktree command from the bare repo instead of the control worktree — git accepts both, but §3.2's per-task command and `aidw/git.py:add_worktree` run from the control worktree; match that, or later-epic consumers asserting the `add_worktree` shape drift.
- Nesting a worktree under the bare or another worktree, or reusing an existing path — git refuses; `bare.git`, `main`, `task` must all sit directly under `workspace` as siblings.
- Re-adding what the fixture already made: `add_task("task")` collides with the fixture's own `worktree add -b task` (branch already checked out, path exists). Migrated tests that need the `task` worktree use `repo.task` directly; the fix is the branch-name rule in Req 5, not catching the helper's error.
- Conflating with the other local helpers: `_make_trap` / `_make_plain_clone` (test_layout.py) build the *rejected/single-checkout* layouts and stay local, as does `test_layout.py::_make_bare` for the bare-only tests; test_git.py's branch+detached helper wires off the bare with no `main` control worktree, and its same-shaped `_make_bare_with_control` stays local too — that whole module is out of scope. Only the two consumer modules' supported bare+main(+task) helpers migrate (Req 5's deletion list).
- Reaching into `fixtures/target-repo/` (§3.12) — that static dir is an E4/E5 integration asset, not this pytest fixture; building the fixture from it (or trying to make the fixture be it) is a scope error.
- Session-scoping the fixture (`tmp_path_factory`) instead of function-scoping on `tmp_path` — a session-scoped bare repo with registered worktrees is exactly the "doesn't clean up after itself" failure the Done-when forbids.
- Adding `git config` identity spawns in the fixture — `_git_identity` already exports the env session-wide; per-repo config re-adds the two spawns AGENTS.md measured out.

Tests (what to prove, not the literal expects):
- Fixture contract (in `tests/test_worktree_fixture.py`): `bare` is bare (`git rev-parse --is-bare-repository`), `control`/`task` are linked worktrees (`.git` is a file); `aidw.git.common_dir` from `control` and `task` both resolve to `bare`; `task`'s branch is `task` off `main`; `add_task("task")` raises (branch already checked out).
- Wiring: `add_task("feat")` creates a sibling `feat`; and the base parameter is discriminated, not merely exercised (a fresh branch sits at `main`'s tip, so an ancestor check alone is vacuous — both directions answer True): cut a `dev` branch, advance `main` with a commit, then `add_task("child", base="dev")` asserts `aidw.git.is_ancestor(dev, child)` is True and `is_ancestor(main, child)` is False (the `test_add_defaults_to_target_base_branch_and_honours_base` pattern). Also `aidw.git.worktrees(bare)` lists exactly the worktrees the fixture and these `add_task` calls made.
- Purity/cleanup: after a test exercises the fixture, `aidw.git.status_short` is clean, the worktree list is unchanged, and no `.aidw/state` exists under `tmp_path` (mirror `test_layout.py::test_check_layout_leaves_the_repository_unchanged`).
- Migration correctness: migrated tests assert the same behaviour against real git as before, and `uv run pytest` completes with no deselected/skipped test. Spawn cost is enforced at the source, not by a count (E0.8's 3185 → 1843 is a one-time measurement, not a maintained baseline or gate): the change adds no per-repo `git config user.*` spawn and no `git worktree remove` teardown (Req 3, Req 4) — checkable by `rg` over `tests/`: the only `git config user` / `worktree remove` hits are the pre-existing comment in `tests/conftest.py` and docstrings in `tests/test_worktree_cli.py` / `tests/test_workspace_paths.py`, and the change adds none.
