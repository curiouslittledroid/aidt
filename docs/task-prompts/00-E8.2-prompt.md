Task: Record `toolkit_version`, the resolved `schema_version`, and a hash of the resolved config into every run's `state.json` (roadmap E8.2; EXTRACTION.md §3.11).

Requirements:
1. Add three additive `RunState` fields in `aidw/state.py`, each defaulting `None` so a state.json written before this task loads unchanged — do **not** bump `SCHEMA_VERSION` (the throughput-fields precedent, design.md §9.2):
   - `toolkit_version: str | None` — always `aidw.__version__` (`aidw/__init__.py`); E1.6 pinned: never shell out to `git`/`uv` or parse `pyproject.toml`.
   - `config_schema_version: int | None` — the **config** schema version, `ResolvedConfig["schema_version"].value` when `is_set`, else `None` (config-less repo). Key name is prompt-fixed: the bare `schema_version` key is already the state schema (`RunState.schema_version` = `SCHEMA_VERSION`), so the config's must be distinct.
   - `config_hash: str | None` — `"sha256:<hex>"` over `json.dumps(resolved.to_dict(), sort_keys=True)`. This is the same `config` object `aidw config show --json` prints (`aidw/cli.py:config` → `resolved.to_dict()`), so the fingerprint is reproducible from an operator-visible command. Prompt-fixed: §3.11 leaves the algorithm/canonicalisation open; hashing `to_dict()` includes each leaf's `source`, so a declared `max_revisions: 3` fingerprints differently from the default `3` — provenance is part of the resolved-config identity.
2. `create_run` gains keyword-only `toolkit_version`/`config_schema_version`/`config_hash` (default `None`) and stores them on the new fields; `save`/`to_dict`/`from_dict` already round-trip them via `asdict` + default-`None` — no special-casing.
3. Compute the two config values in **one** pure helper next to `resolve_config` in `aidw/target_config.py` (e.g. `config_identity(resolved) -> tuple[int | None, str]`) so the five workflow call sites cannot drift: no I/O, no input mutation.
4. Thread all three through every `create_run` call site that holds a resolved config — `aidw/workflows/{prompt,implement,review,fix,approve}.py` (each already calls `resolve_workflow_config`, which returns the `ResolvedConfig`) — passing `toolkit_version=__version__` plus the helper's two values. `aidw/cli.py:exec_stage` does not resolve the target config today and must not start doing so in this task: it records `toolkit_version=__version__` only, config fields `None` (prompt-fixed — wiring config validation into `exec` changes its failure surface, which E8.2 does not own).
5. `load` stays backward compatible: a state.json missing the three fields loads with `None` (the existing `_filter`/defaults path already handles this — add the test, don't special-case).

Traps / prior review findings:
- Key collision: `schema_version` in `state.json` is the **state** schema (`SCHEMA_VERSION = 1`, `aidw/state.py`), and `load()` raises when it differs. The roadmap's "resolved `schema_version`" is the **config** schema version — `aidw/doctor.py:check_target_config` already renders it as "resolved, not `declared.schema_version`". Reusing `schema_version` for the config value breaks `load`. Use `config_schema_version`.
- Don't conflate `config_hash` with E4.8's gate-citation `tree` identity (`GateOutcome.tree`, `aidw/state.py`) — that is a content-tree hash for gate reuse (R16); this task's hash is the resolved **config**, never git state.
- Hash the **resolved** config (`ResolvedConfig.to_dict()`), not the declared `TargetConfig` nor the raw `config.yaml` text — `resolve_config` must run first, and a raw-file hash changes on whitespace/comment edits and stops meaning "resolved config".
- Field order: `RunState.to_dict()` inserts `totals` immediately after `schema_version`; place the new fields after `schema_version` in the dataclass so `tests/test_state.py::test_saved_state_has_totals_at_the_top` stays green.
- `create_run` has six call sites (five workflows + `exec`) and is called directly by many tests — the new kwargs must stay optional/defaulted or `tests/test_state.py` breaks.

Explicit non-goals — do NOT do these in this task:
- E8.3 (`aidw --version`, doctor version/git/compat reporting) — `toolkit_version` is written to state, never printed.
- E8.4 (README install paths) and E8.5 (release process, first tag) — no docs, no tag.
- E4.8's gate-citation tree identity (R16) is already implemented — do not touch `GateOutcome.tree` or `aidw/verification.py`.
- design.md §9.2's schema-example rewrite is E9.1's; this task adds only a §17 decision-log entry, not a §9.2 rewrite.
