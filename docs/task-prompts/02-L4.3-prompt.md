Task: Make the revision budget configurable (Design 12, Design 8.1)

Requirements:
1. Add `--max-revisions <n>` to the `aidw prompt` command in `aidw/cli.py` (`prompt()`): a `typer.Option` int defaulting to `None`, forwarded as `max_revisions=` to `prompt_workflow.run(...)`. Mirror the forwarding-test pattern `tests/test_prompt_workflow.py::test_l12_cli_flag_is_forwarded_to_prompt_workflow`.
2. Parameterize the budget in `aidw/workflows/prompt.py`: rename module constant `MAX_REVISIONS = 3` to `DEFAULT_MAX_REVISIONS = 3` (default stays 3); add `max_revisions: int | None = None` to `run(...)`; resolve `max_revisions = max_revisions if max_revisions is not None else DEFAULT_MAX_REVISIONS`. Use the resolved value at the terminal branch (`if revisions >= max_revisions - 1:`). Precedence is CLI flag > target config > default 3, but the target-config slot is deferred to E3.1 (design §12): leave a one-line seam comment naming the insertion point — do NOT read `<target>/aidw/config.yaml` (no loader exists yet).
3. Validate the budget: `max_revisions >= 1` (prompt-fixed floor — 0 review rounds is meaningless; the roadmap fixes only the default 3). Refuse `< 1` as a usage error (exit 2) in the CLI before the workflow runs, never after the author stage.
4. Report the effective value in the run summary: thread `max_revisions` into `_loop_summary`/`_record_review_outcome` so the named summary gains `max_revisions=<n>` and flows to the `approve-task-prompt` gate `detail`, the run.log line, and stdout on every verdict-bearing exit (approve, deny, terminal Request changes, Blocked).
5. Update every `MAX_REVISIONS` occurrence that is comment/docstring text (module docstring stage list, the constant comment, the reconcile-placement comment that says "``MAX_REVISIONS`` counts review rounds") to the parameterized wording: "`max_revisions` (CLI `--max-revisions`, default 3); `max_revisions - 1` fix batches run and the `max_revisions`-th review is review-only".
6. Design docs: (a) design.md §12 — add the `max_revisions` key: target-repo `<target>/aidw/config.yaml`, default `3`, precedence CLI `--max-revisions` > config `max_revisions` > `3`, config read deferred to E3.1; (b) design.md §14 — add `[--max-revisions <n>]` to the `aidw prompt` line; (c) design.md §8.1 — note the budget is configurable via `--max-revisions` (default 3). *(Prompt-fixed: "documented in the config contract" = design.md §12/§14; `docs/target-repo-config.md` is E3.6's placeholder and `docs/schema/aidw-config.schema.json` is E3.1's — do NOT write either, but word §12 so E3.1/E3.6 carry the key forward.)*
7. Gate impact: no new status/decision/verdict vocabulary — `max_revisions=<n>` is a summary field inside `detail`, not a gate; `decision` stays `approved`/`denied`, `status` stays `blocked`. Confirm `uv run --frozen pytest` stays green.

Traps / prior review findings:
- Renaming the constant but leaving a `MAX_REVISIONS` reference (the terminal branch or a comment) → `NameError`; grep `MAX_REVISIONS` and convert every occurrence to the parameterized form.
- `max_revisions=1` makes `revisions >= max_revisions - 1` true at `revisions=0`, so review-1 is the terminal review with **zero** fix batches — do not clamp the floor to 2 or assume one fix batch; a residual Request changes on review-1 returns `3`/`BLOCKED` with no `task-review-fixes-*` stage.
- Confusing the budget with the loop counters: `revisions` counts fix batches (max `max_revisions - 1`), `review_index` counts review rounds (max `max_revisions`); `_fake_stages`'s `approve_review` knob keys off `_review_index`, so a `max_revisions=2` never-approving run ends at review-2 terminal.
- Threading the resolved value into only some `_record_review_outcome` call sites — there are exactly three: the Blocked short-circuit, the terminal Request changes exit, and the final approve/gate-deny call site (which covers both the approve and the deny exits); miss one and it reports the default instead of the resolved value.
- Validating `max_revisions < 1` after the author stage → the run authors/commits a prompt then refuses; validate in the CLI (exit 2) first.
- Building a config loader: reading `<target>/aidw/config.yaml` now reads a nonexistent file (E3.1 not landed); the precedence is a documented seam, not implemented here.
