Task: Resolve `Design N` citations against a repo-declared spec directory

Requirements:
1. Config key: add optional `paths.specs_dir` to `aidw/target_config.py:PathsConfig` + `PATH_FIELDS`, unset by default (no `TOOLKIT_DEFAULTS` entry, mirroring `agent_configs_dir`). It is **not** a read-path — do NOT add it to `READ_PATHS`; its absence is a doctor WARN, never a `validate_paths` FAIL. `aidw config show` reports `unset`/`config` provenance like the other `paths.*` leaves.
2. Spec-document resolver in `aidw/workflows/prompt.py`: with `specs_dir` declared, `Design N` resolves to the one file sitting **directly** in that directory (flat scan, no recursion) whose filename carries the `Design <number> - ` prefix, comparing `<number>` to `N` canonically as dotted integers (reuse `_canonical_number`; the filename→number match is one named predicate the doctor imports — requirement 7): `Design 04` ≡ `Design 4 - …`, and a parent number never matches a sub-number (`Design 20` ≢ `Design 20.1 - …`). Zero or more-than-one candidates → a gap naming the resolved directory and reason; never fall back to root `design.md`.
3. Citation-window enumeration (rewrite `_cited_specs`): scan `{task_line}\n{done_block}` once; each citation's window is the text after its token up to the next citation token of **either** channel (`Design N` or `<NAME>.md`). Each `§M` token in that window is one `(document, section)` pair, enumerated and checked once (dedupe on the pair, not the token). With `specs_dir` declared, a bare citation (no `§M`) checks only that the resolved document exists and is non-empty. With `specs_dir` **unset**, the `Design N` channel stays byte-identical to today: document = root `design.md`, and a bare citation keeps today's meaning — section = the citation's own number.
4. Trailing capital letter: a `§5.3A` section token is checked against its parent `5.3` only and never reports a gap naming the lettered form — the letter is a sub-part label (a deeper heading in one spec, a list label in another; no deterministic rule spans both). Do not extend `_SECTION_RE` to capture letters.
5. Gaps + remedy: `_spec_feasibility_gaps` gains the document-mode branch; every gap names the resolved path and its reason. The exit-3 refusal (`_refuse_spec_gaps`) appends a remedy line when `specs_dir` is unset and no root `design.md` exists, naming `paths.specs_dir` as the fix.
6. Evidence bundle: `_render_cited_specs` renders the resolved path and every section the preflight checked, from the same `_cited_specs`; thread `specs_dir` into `_render_evidence_bundle` and the preflight exactly as `roadmap_dir` is threaded today, so bundle and preflight cannot disagree.
7. Doctor: `aidw/doctor.py` gains an advisory `specs_dir` check (WARN, never FAIL, no exit-code effect) for: a declared specs_dir that is missing, is not a directory, or holds no numbered spec document — "numbered spec document" is the resolver's own predicate from requirement 2, one shared helper imported from `aidw/workflows/prompt.py`, never a doctor-local second regex or glob (which could disagree with the resolver in both directions); and for none declared while no root `design.md` exists.
8. Docs: `design.md` §8.1 + §12.1 gain the key; §17 records the decision as row **Z22** (append only, never reuse — `aidw/conventions.md`). `docs/roadmap-format.md` §8.1 states the specs_dir resolution; `docs/target-repo-config.md` gains the `paths.specs_dir` row (default `unset`), a worked-example note, and a read-path/write-target paragraph note that `specs_dir` is neither; `docs/schema/aidw-config.schema.json` gains the `specs_dir` string property.
   Gate impact: no new checker/status/`when=`/stage id/`REQUIRED_PROMPTS`/CI gate. Re-baselined drift pins: `tests/test_target_repo_config_doc.py` `EXPECTED_DEFAULTS["specs_dir"]="unset"` plus both `paths.*` leaf lists; `tests/test_target_config.py:test_json_schema_properties_agree_with_dataclass_fields` picks up the field automatically.

Traps / prior review findings (max 5–7):
- Adding `specs_dir` to `READ_PATHS` would make `validate_paths` FAIL a legitimately-absent optional directory — the Done-when requires doctor WARN, never FAIL. Keep it out of `aidw/target_config.py:READ_PATHS`.
- Don't recurse the spec scan. A recursive walk would match a nested `Design N` file and change the zero/one/many result; the scan is flat over `specs_dir`.
- The unset path is byte-identical: `tests/test_prompt_workflow.py:READ_PATH_FILES` commits a `design.md` with `## 8.1`/`## 9` and pins ~30 gap strings; add specs-mode coverage **beside** it, never replace or weaken it.
- Window boundaries include both token kinds: a `§` after `Design N` that is followed by an `.md` token belongs to the `Design` citation, not the next file's window — compute windows from one merged token scan, not two separate scans.
- Reuse `_canonical_number`/`_section_state`/`_heading_level` for number and non-emptiness comparison; a second dotted-int comparator or a lax "any text after the heading" check would silently diverge from G1.2's contract.
- A doctor-local filename rule (e.g. a `Design *.md` glob) can disagree with the resolver predicate both ways: doctor OK on a directory the resolver reports as zero-candidate, or doctor WARN on one it resolves fine. The doctor imports the shared predicate (requirements 2/7); `tests/test_doctor.py` pins it with a non-conforming-only directory.

Explicit non-goals — do NOT do these in this task:

- Do not add a stub root `design.md` to a target repo to paper over the mismatch — the Notes forbid it.
- Do not change the `<NAME>.md` doc-ref channel's bare-ref contract or any other channel behaviour beyond the shared window enumerator; the byte-identity guarantee is about the `Design N` channel.
- Epic G1 ends at G1.3; Epic B1 ("Batch fixes") is the next roadmap work — don't start it here.
