Task: The fixer verifies the finding before applying it (Design 8.1)

Requirements:
1. Verify-then-fix — in `prompts/task-review-fixes.md`, replace the opening "Fix the issues as you suggest. If anything is unclear, interview me and provide suggestions that I can choose from." with a verify-first instruction: read the finding, then verify it against the repository and the cited sources (the prompt, its roadmap entry, the spec sections it cites, and the files the finding names) before making any edit. The stage's first act is verification, not applying the reviewer's `Suggested fix`.
2. Push-back path — both files: when the suggested fix is wrong or contradicts the sources, do not apply it — make the correction the evidence supports, and report the disagreement explicitly (which finding, what the reviewer prescribed, what the evidence shows, what changed instead). Extend the `## Output` in `agents/task-fixer/AGENTS.md` so the fixer reports that disagreement per finding.
3. Never settle a material ambiguity — both files: a finding needing an owner decision (security, cost, schema, data loss, hard-to-reverse) is never settled by guessing; state the options and stop, leaving it a `Blocked` escalation. `agents/task-fixer/AGENTS.md` already carries this in its Hard rules ("Never invent a requirement to satisfy a finding, and never settle a material ambiguity yourself…") — keep that bullet and add the matching statement to `prompts/task-review-fixes.md`, wording the two consistently.
4. Qualify the "smallest edit" rule — in `agents/task-fixer/AGENTS.md`, re-word "Prefer the smallest edit that satisfies the finding." so it is no longer a bare tiniest-diff mandate: prefer the smallest *correct* edit that resolves the *verified* finding, and do not apply a suggested fix verbatim when verification contradicts it. Leave the wording so L3.2 can append its consistency sweep; do not write the six-section sweep here.
5. Product-neutral wording — `prompts/task-review-fixes.md` is bucket (i) and ships as-is (EXTRACTION.md §4.2): the added text names no package manager, no product path, no product doc, no product task-id example. Generic phrasing only ("the finding", "the cited sources", "the task prompt under revision").
