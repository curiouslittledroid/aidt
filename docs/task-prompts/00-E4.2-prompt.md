Task: Prompt resolver (D14) — resolve in precedence order explicit `prompt:` path → `<target>/aidw/prompts/<name>` → toolkit `prompts/<name>` → error; verify Pi's `--prompt-template` precedence empirically and encode the finding; do not assume.

Requirements:
1. One prompt resolver — the existing `resolve_prompt` in `aidw/runner.py` (same name, same module; cli.py:52 already imports it from there), widened to `resolve_prompt(toolkit_root: Path, target_root: Path, name: str, explicit_path: str | None = None) -> Path` — implementing §3.4's four-level precedence exactly, in order: (1) `explicit_path` when declared (the stage config's `prompt:` value as a plain string), resolved against the target root when relative (§3.4's example is `aidw/prompts/update-traceability.md`), used as-is when absolute; (2) a same-named file in `<target>/aidw/prompts/` (D14 filename shadowing); (3) the toolkit default `prompts/<name>` (D4); (4) fail-closed error. Never a silent skip. `name` normalization is explicit, preserving the old resolver's `aidw/runner.py:72-82` behavior: strip one trailing `.md` before lookup, so bare `code-review` and suffixed `code-review.md` name the same file — levels (2)–(3) and §2's message search the normalized `<name>.md`.
2. Fail-closed failure path: a declared `explicit_path` that does not exist, or a `name` that resolves nowhere, raises `FileNotFoundError` (the runner's existing missing-prompt convention, cf. `run_stage`'s `prompt not found:` raise) whose message names the prompt, says which of the two cases failed, and enumerates every searched location per case — declared-but-missing (`explicit_path is not None`) names the declared path, the only location searched; resolves-nowhere (`explicit_path is None`) names the two default locations (`<target>/aidw/prompts/<name>.md`; `<toolkit>/prompts/<name>.md`). Never a fallback to shadow/toolkit when an explicit path is declared-but-missing, never `None` (§3.4 precedence 4, §3.11).
3. Pi receives both template roots, plumbing pinned: `StageSpec` gains `explicit_prompt: str | None = None` — the stage config's declared `prompt:` value as a plain string, set by the same caller that feeds `StageSpec.prompt` from the resolver, and by `aidw exec` on its explicit-path branch. `run_stage` — the only place `repo_root` is in scope — builds the complete ordered list with a new `aidw/agents.py` helper, `prompt_template_dirs(agent: AgentConfig, target_root: Path, explicit_path: Path | None) -> list[Path]`: `agent.prompt_templates` (the configured toolkit roots) with `<target>/aidw/prompts` inserted in the empirically-verified winning order, the explicit path appended when declared — `run_stage` passes `spec.prompt` (the resolver's precedence-1 return) whenever `spec.explicit_prompt is not None` — and the target root omitted when the repo has no `aidw/prompts/` directory (§3.4: a target with no `aidw/` folder is valid and gets the toolkit's pure defaults — §3.6's "both roots" presumes an override dir exists; the helper keys on directory existence, not contents, so a present-but-empty `aidw/prompts/` still gets its root passed). `run_stage` hands that list to `build_argv` via a new `prompt_templates: list[Path] | None = None` keyword; `None` keeps today's `agent.prompt_templates` emission, so every existing `build_argv` caller and test is unchanged. The emitted roots are ordered so a repo file shadows the toolkit file in Pi's `/`-command lookup. AIDW's own rendering is unchanged (D2/§7.3): the *resolved* prompt file is still rendered by `aidw/prompts.py` and piped via `-p`; the `--prompt-template` roots are Pi's slash-command expansion, a separate mechanism that must agree with the resolver's choice.
4. Empirical precedence verification (the roadmap's "do not assume") — a one-time **manual, model-free** probe; do NOT add any test that spawns `pi` (AGENTS.md: no test may invoke a real Pi model). The probe: two temp dirs, each holding a same-named template whose first line differs unmistakably (that line doubles as the description in the response); send `{"type":"get_commands"}` on stdin to `pi --mode rpc --no-session --no-prompt-templates --prompt-template <rootA> --prompt-template <rootB>` — RPC mode answers from the loaded template list without sending any prompt to the model (nothing is billed; a default-configured model merely satisfies RPC startup), `--no-prompt-templates` keeps user/project template dirs out of the probe, and the response's surviving `/probe` entry (`sourceInfo.path`) names the winning root. Run **both root orders** (A,B then B,A) — the winner tracking the first `--prompt-template` flag across both runs is the finding; one order alone cannot tell precedence from coincidence. In the same session, pass a present-but-empty directory as a root the same way and record accepted / warned / rejected. Encode both findings as a comment next to `prompt_template_dirs` in `aidw/agents.py` — per probe: the exact command, the observable that decided the winner, and the Pi version (`pi --version`) — plus a test that pins the emitted order against a `run_stage` dry-run argv.
5. The override is demonstrably what Pi receives: the resolver's returned path feeds `StageSpec.prompt`, and the declared `prompt:` string (when any) rides the same spec as `explicit_prompt`; a dry-run `run_stage` against the fixture override must render the *override's* content (not the toolkit default's) as the stdin prompt.
6. No import cycle (E4.1's trap, repeated): the resolver must not import `target_config` or any workflow module — take the explicit `prompt:` path as an already-resolved plain string (the `explicit_path: str | None` parameter — the caller unpacks the stage config; the resolver itself resolves the relativity per Requirement 1). `target_config.py`'s docstring forbids importing workflow modules, and `cli.py` imports `resolve_prompt` from `aidw.runner` at module load.
7. Keep the suite green and the existing call sites coherent: `aidw exec` (cli.py:865) and `tests/test_runner.py::{test_resolve_prompt_by_name,test_resolve_prompt_by_path}` use the current two-arg `resolve_prompt(toolkit_root, value)`; update them to the new contract — no second resolver left behind; `exec` maps its `--prompt` value onto the new parameters (an absolute value or one containing a directory separator passes as `explicit_path`, a bare prompt name — including the suffixed `code-review.md` form the old resolver accepted — as `name`, normalized per Requirement 1), sets `StageSpec.explicit_prompt` to the raw value on the `explicit_path` branch so the declared path also reaches argv, and keeps working. `tests/test_cli.py`'s `spy_resolve` (wrapping `cli.resolve_prompt`) must follow the new signature too.

Traps / prior review findings:
- Explicit-path-missing must NOT fall through: the natural "best effort" impulse resolves `prompt:` and, on a missing file, tries shadow then toolkit — that violates §3.4's "unresolvable required prompt is an error, never a silent skip".
- Two mechanisms, one answer: AIDW-side resolution (one file → stdin) and Pi-side `--prompt-template` ordering are independent. Getting the Pi order right does not make AIDW pick the repo file; the resolver must pick the same file the Pi roots shadow, or the stage renders the toolkit default while Pi's `/` lookup finds the override.
- The target root must be threaded from `run_stage` (the only place `repo_root` is in scope) into `build_argv` — `build_argv` alone sees only `agent.prompt_templates` (the toolkit root), so the repo override would never reach Pi's argv otherwise.
- `agent.prompt_templates` already emits `<toolkit>/prompts` (config.py `_load_path_list`): if the empirical finding is "earlier root wins", blindly appending the target root after it is wrong — the helper must produce the complete ordered list, not append.
- The naive precedence check (`pi -p '/probe'`, or an interactive session) sends the expanded template to the model — a billed call, and a stall where no credentials exist; use the Requirement 4 RPC probe instead, run in both root orders.
- Don't commit an override that shadows a prompt a later E4.7 fixture rewrites: keep the committed override minimal with unmistakable marker content, and cover the explicit-path and failure cases in tmp_path tests rather than more committed files.
