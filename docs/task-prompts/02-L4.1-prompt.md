Task: Spend the last revision slot on a review, not a fix (Design 8.1)

Requirements:
1. Remove the final-round fix batch: fix batches run only for the first `MAX_REVISIONS - 1` rounds (2 at `MAX_REVISIONS=3`). The `MAX_REVISIONS`-th review round is review-only — the terminal review. Authority: the L3.4 task's "L4.1 later removes the final-round fix batch" note. Target sequence for a never-approving prompt: review-1 → fix-1 → reconcile-1 → review-2 → fix-2 → reconcile-2 → review-3 (terminal).
2. Replace both `revisions >= MAX_REVISIONS` exits in `aidw/workflows/prompt.py` — the top "MAX_REVISIONS is zero" check and the post-reconcile `assumed_ok`/`break` — with one terminal-review branch placed after the `VERDICT_BLOCKED` short-circuit: when the fix budget is spent (`revisions >= MAX_REVISIONS - 1`, equivalently `review_index >= MAX_REVISIONS`, since every non-approving round runs exactly one fix batch) and the verdict is not `Approve`, set `state.status = BLOCKED`, `save(directory, state)`, print `review_text` to stderr, and `return 3`. No `break`, no `assumed_ok`.
3. Keep the `Approve` and `Blocked` short-circuits byte-for-byte: `verdict == APPROVE` breaks (accept), and `verdict == VERDICT_BLOCKED` fails closed (exit 3, no fix stage, prompt uncommitted) before the terminal branch — so a final `Blocked` still reads as "a human must settle it", not the generic residual path.
4. Delete the `assumed_ok` machinery: the post-loop `if assumed_ok:` "revision budget spent" print, the `if verdict != APPROVE and not assumed_ok and not approve_all:` block, the `verdict_line += … (no further review — accepted)` suffix, and `assumed_ok=…` in the gate `detail=` (now `verdict={verdict}; revisions={revisions}`). The loop now exits only via `Approve`, so `approve_all` never carries a residual Request changes to the gate.
5. Update the module docstring, the `MAX_REVISIONS` comment, and the reconcile-placement comment (the one saying "pre-L4.1 the final round's fixes are otherwise never reviewed") to the new semantics: "a review is always the last stage for a non-approving prompt; `MAX_REVISIONS` is the number of review rounds and the last is review-only". Keep `MAX_REVISIONS = 3` unchanged.
6. Design docs: amend design.md §8.1's diagram line ("then P2 again (skip the last P2)") and the "At most `MAX_REVISIONS` (3) rounds run" paragraph to state the terminal review and its fail-closed exit-3 outcome; append one §17 decision row (terminal-review/budget semantics) recording that the last revision slot is a review and a residual `Request changes` fails closed with no unreviewed fixes. Mark the §8.1 text provisional (E9.1 owns the rewrite).
7. Gate impact: the `approve-task-prompt` gate `detail=` drops `assumed_ok` and is recorded only on the Approve path; a terminal `Request changes` records `BLOCKED` with no gate record. No new status/gate vocabulary. Confirm `uv run --frozen pytest` stays green.

Traps / prior review findings:
- Deleting the final fix batch but leaving the post-reconcile `if revisions >= MAX_REVISIONS: break` → the loop never terminates (review → fix → review forever); the terminal branch must be the loop's only non-approve, non-Blocked exit.
- Placing the terminal branch before the `VERDICT_BLOCKED` short-circuit → a final `Blocked` is misreported as residual Request changes, losing the "human must settle" message; keep Blocked first (cf. `test_a_blocked_final_review_still_fails_closed`).
- Letting `approve_all` reach the gate on a residual Request changes → the run records approved; the terminal branch `return 3`s before the gate, mirroring `test_blocked_verdict_overrides_approve_all`.
- Confusing `revisions` (fix batches, now max 2) with `review_index` (review rounds, now max 3) → the terminal condition must be keyed off fix-budget spent; the fake harness's `approve_review` knob is keyed off `_review_index`, so `approve_review=3` is the success-at-terminal test.
- Leaving `assumed_ok` in the gate `detail=` → the record still claims unreviewed acceptance (the exact E1.6 symptom); remove it and its assertion in `test_three_review_rounds_then_accept_without_another_review`.
- The terminal review must still receive the L2.3 delta brief and L2.4 evidence pointer (it is `review_index >= 2`, so the existing `delta` block already covers it) — do not special-case it out or round 3 loses prior-review context.
