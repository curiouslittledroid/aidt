Task: `aidw prompt` must refuse to author a task while earlier tasks in the same phase file are still unticked. Authoring out of order is what produced the E1.6 failure: the prompt was written against a base that lacked E1.5, and because the author stage has no other way to report a missing prerequisite, the workaround was smuggled into the prompt text. The roadmap is the ordering authority, so refuse on it.

Requirements:
1. `aidw/workflows/prompt.py:run` gains `allow_incomplete_prereqs: bool = False`, and `aidw/cli.py`'s `prompt` command gains `--allow-incomplete-prereqs`.
2. Placement: compute the predecessor list once per run, after the roadmap lookup (`load_tasks`/`find_task`) and before the `dry_run` split, so the dry-run note and the real-run refusal cannot disagree. The refusal itself goes inside the real-run preflight **after** the current-branch and clean-tree checks and **immediately before** `_verify_base_branch` (L1.1) — before any network call and before `load_all`/`create_run`. Pin the observations: a run that is both on the wrong branch and out of order reports the branch refusal first, and an out-of-order run in a repo with an unreachable `origin` refuses without fetching.
3. Predecessors are the entries in the `entries` list `run()` already holds, filtered to the resolved entry's **same `RoadmapTask.file`**, with `RoadmapTask.line` **strictly less** than the target's line, and `done` false. Roadmap order (line) is the authority — never epic-id order. Filter by `file`, not by phase id: `load_tasks` returns every phase file, and phase 00's ~45 unticked entries must not block another phase's runs.
4. Refuse with `EXIT_REFUSED` (4), before `create_run`, so a refused run leaves no run directory, no `{phase}-{task}` branch and no prompt file. The message names the target task, the phase file, **every** incomplete predecessor in roadmap order as `id — title`, one per line — never a bare count — and both ways forward: tick them once they are merged (a predecessor can be complete but unticked, so the gate cannot tell the difference and the operator must), or re-run with `--allow-incomplete-prereqs`.
5. `--allow-incomplete-prereqs` proceeds with a warning naming every predecessor it skipped over; without the flag nothing else bypasses the check.
6. `--dry-run` reports and never refuses: one `[dry-run]` note naming the incomplete predecessors (or stating there are none) and return 0. Dry-run stays hermetic — no fetch, no writes.
7. Docs: add `[--allow-incomplete-prereqs]` to the `aidw prompt` usage line in design.md §14, and add the gate to §8.1's preflight description in one or two sentences. Do not restate the stage chain and do not open a design.md §17 entry — phase 02's L6.2 consolidates this phase's design decisions.

Traps / prior review findings:
- `load_tasks` returns every entry in every phase file (~104 today). An unfiltered "some entry is unticked" scan refuses every run in every phase; and filtering by `t.phase == entry.phase` instead of `t.file == entry.file` would cross files if a phase ever had two. Filter on the file, then on the line.
- Only *earlier* lines block: a later unticked sibling must not refuse. A target that is itself already ticked is not in scope — this task adds no refusal for it.
- Do not re-read or re-parse the roadmap file: `run()` already holds the parsed entries, and a second parse is a wasted read against possibly-changed state.
- Do not mutate `ROADMAP_FIXTURE`: most tests in `tests/test_prompt_workflow.py` drive full runs from it, so giving it an incomplete predecessor makes them all refuse. Add a separate fixture, or a parameter with a default, and leave existing callers untouched.
- The predecessor list is computed before the `dry_run` split, so it needs a dry-run branch: without one, `--dry-run` returns 4 and breaks the workflow's plan-only contract.
- Placing the refusal after `_verify_base_branch` spends a network fetch before refusing a purely local, purely in-memory condition.
- No parser or format change is needed or allowed: `RoadmapTask.done`/`.file`/`.line` already carry everything, a per-task `requires:` field is a roadmap-format change owned by E5.1/E5.2, and D15 forbids a second dialect.
