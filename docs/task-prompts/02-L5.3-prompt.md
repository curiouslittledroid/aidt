Task: Check the conciseness budget in the workflow (Design 8.1)

Requirements:
1. Add a size/clause check in `aidw/workflows/prompt.py`, called once after the author stage succeeds and `prompt_path` is resolved (after the existing `prompt: {rel}` print, before the review loop; the `--dry-run` path returns earlier and never checks). It reads exactly the just-generated `prompt_path` — never a scan of `docs/task-prompts/`.
2. Thresholds, per `prompts/task-prompt.md` §Conciseness budget: byte budget 15000 bytes (15KB, decimal — matching the roadmap's own "17.9KB" = 17855 bytes), line budget 150 lines. Trip when byte count > 15000 or line count > 150.
3. The message names the offending requirement, not just the total: parse the numbered `Requirements:` items, and report the longest one(s) by word count with their word counts alongside the byte/line totals. Degrade to totals-only when the section is absent or unparseable — a parse failure must never fail the run or the check.
4. Default: print a one-line warning to stderr and continue to review. Under `--strict`: refuse — print the one-line reason to stderr, set `state.status = FAILED`, `save(directory, state)`, return 1, and record no `approve-task-prompt` gate (no new gate-decision vocabulary, L4.2 / design §9.2).
5. Print the count to stdout for every produced prompt, independent of whether the check trips — one `budget:` line with the byte and line counts (e.g. `budget: 57 lines / 14.7KB`), right after `prompt: {rel}`. This is the "count in the stage report".

Traps / prior review findings:
- Full-tree scan: scoping the check to every `docs/task-prompts/*.md` makes `aidw prompt` on this very repo warn forever (`00-E1.5-prompt.md` is 17.9KB, `00-E1.4-prompt.md` 181 lines). Read exactly `prompt_path`.
- The author already committed the prompt (per `prompts/task-prompt.md`) before the workflow checks it; the `--strict` refusal happens after that commit. Report the over-budget path in the refusal message and leave the file/branch as-is — never delete or revert agent output (design §13).
- Decimal KB: the roadmap says 17855 bytes = "17.9KB", so 15KB is 15000 bytes, not 15360. Getting this wrong shifts every boundary by 360 bytes.
- No second trip threshold: `prompts/task-prompt.md` sets no numeric word cap per requirement (only "5–9 items", "1–2 lines each"). "Names the offending requirement" is attribution, not a separate per-clause limit.
- Don't put the check in `aidw/gates.py` or record a gate: it is a workflow-level warn/refuse, and recording `approve-task-prompt` (or any new gate) breaks the "no new gate-decision vocabulary" rule.

Explicit non-goals — do NOT do these in this task:
- L5.1 (author pre-submit self-check) and L5.2 (gate/verifier reconciliation) are landed; do not edit `prompts/task-prompt.md` — the roadmap assigns enforcement to the workflow, not to the author prompt.
- L6.1 (loop contract fixture) and L6.2 (design.md §17 consolidation) are later tasks.
- Do not touch the review/fix/reconcile loop, the evidence bundle, `--max-revisions`, or any other stage — this task adds one check between the author stage and review.

Deliverables:
- aidw/workflows/prompt.py
- tests/test_prompt_workflow.py

Tests (what to prove, not the literal expects):
- In `tests/test_prompt_workflow.py`, a fake author stage writes a fixture prompt over the byte budget (pad one `Requirements:` item past 15000 bytes, with numbered `Requirements:` items present): default run returns 0 (review approves), stderr warning names that requirement and its word count, stdout carries the `budget:` count line.
- A fixture over the line budget (> 150 lines) trips identically.
- `strict=True` over-budget fixture: run returns the chosen refusal code, `state.status` is FAILED, stderr names the offending requirement, no review stage ran (assert the fake saw only `task-prompt`), and the saved run state records no gate — `latest.gates` holds no `approve-task-prompt` entry and no new gate name (Req 4; reuse the verdict-less-exit assertion pattern already in `tests/test_prompt_workflow.py`).
- An in-budget fixture prompt is silent (no `budget` warning on stderr) — proves existing prompts are unaffected at the default.
- A prompt with no parseable `Requirements:` section still warns on size with a totals-only message — proves the degrade path never crashes.

Done when:
- A fixture prompt over the byte budget or the line budget warns at the default, and `--strict` refuses (run FAILED, review never starts).
- The warning/refusal message names the offending requirement with its word count, not only the totals.
- The `budget:` count line is printed for every produced prompt; an in-budget prompt prints no warning.
- `uv run --frozen pytest` is green.

If anything in the cited spec section is ambiguous or underspecified for this task, stop and ask rather than guessing — especially:
- The `--strict` refusal exit code: design §14 offers 1/2/3/4 and none names "post-author quality refusal". This prompt fixes it to 1 (stage/gate failure — the author's output failed a workflow quality bound), status FAILED. If the phase intends a preflight-style exit 4, stop and reconcile.
- The per-clause threshold: no numeric word-per-requirement limit exists in the cited sources. This prompt reads "names the offending requirement" as attribution (name the longest requirement(s)); if a word cap was intended, stop and add it to `prompts/task-prompt.md` first.
- "the repository's existing prompts are unaffected at the default": this prompt scopes the check to the just-generated `prompt_path`. If a whole-`docs/task-prompts/` scan was intended, stop — this repo's own prompts would trip it permanently.
- The generic guard: security-sensitive, cost-committing, or hard-to-reverse changes (cross-account trust, schema changes, billing logic, data deletion).
