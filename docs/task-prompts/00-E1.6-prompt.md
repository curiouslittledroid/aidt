Task: Add `aidw config show` (skeleton) — print toolkit root, version, target root, workspace root, state root, and the config file found (or none), each with provenance.

Prerequisite — hard gate: do not start this task until **E1.5 "CLI plumbing"** (docs/tasks/00 - Extraction.md, Epic E1) is merged to the base branch. E1.5 is what delivers `_roots()` in `aidw/cli.py` returning the 3-tuple `(TargetRepo, ToolkitPaths, WorkspacePaths)` — E1.5 threads all three resolved roots, `_roots()` being the sole `TargetRepo`/`WorkspacePaths` resolution site — plus `AIDW_REPO` override support, and the `except RepoNotFoundError → EXIT_REFUSED` catch site. Verify against `aidw/cli.py` on the base branch before writing any code. If E1.5 is not yet merged, stop and report the blocker — do not start, do not implement E1.5's threading inside this diff, and do not rebase onto an in-flight E1.5 branch. Requirements:
1. Add a `config` command to `aidw/cli.py` following the `agents`/`runs` `action`-argument pattern: `config(action: str = "show", --json)`, rejecting any other action with `EXIT_USAGE` (2) like `agents`/`runs` do. Validate the action before any printing or `_roots()` call — a deliberate deviation from `agents`/`runs`, which resolve roots first: a doubly-bad invocation (unknown action plus bad target) exits 2 with the usage error on stderr and empty stdout; action validation wins over target refusal. Human output is one `label: value (source)` line per value; the display-label wording is not pinned by this prompt or the cited specs — pick any stable, human-readable labels — while the `(source)` strings are the pinned ones (see the label list in the closing ambiguities note). `--json` emits a single object with exactly the keys `toolkit_root`, `version`, `target_root`, `workspace_root`, `state_root`, `config_file`, each `{"value": <str|null>, "source": <str>}` (prompt-fixed shape).
2. Toolkit root and version resolve with no repo and print first — `ToolkitPaths.resolve().root` and `aidw.__version__` (`aidw/__init__.py`; already imported as `__version__` in `cli.py`) — so a wrong-target invocation still shows them before the target refusal below. That pre-print is human mode only: `--json` buffers all six values and emits one object only on success, so a `--json` refusal exits 4 with empty stdout and the path-naming error on stderr — no partial JSON, no human lines (the toolkit-on-stdout guarantee is the human-mode debug aid). Both take the source label `package` (the installed package location / the package `__version__`, §3.1 "installed package location"; never git) in human and `--json` modes — pin that exact string, don't invent a label.
3. Target root comes from `_roots()` (E1.5); do not re-resolve the target or toolkit, and do not catch `_roots()`'s `RepoNotFoundError → EXIT_REFUSED` (4) path: a bad `--repo`/`AIDW_REPO`, a non-repo cwd, or a bare target must still refuse with stderr naming the path — that refusal is the wrong-target debug output. Workspace root and state root also come from `_roots()`: E1.5 threads all three roots as the 3-tuple, resolving `WorkspacePaths.resolve(target)` inside `_roots()` with `state_dir_override` at its `None` default — `config show` exposes no override, so `_state_base`'s first tier is never taken and Req 5's three labels are the complete tier set. Unpack the 3-tuple (`target, _toolkit, workspace = _roots()`; the toolkit element goes unused because Req 2 pre-printed `ToolkitPaths.resolve().root`, which the sole-site rule does not cover) and reuse that same threaded object for Reqs 5–6 — do not call `WorkspacePaths.resolve()` again inside `config show`: a second resolution duplicates the threaded one and breaks E1.5's resolve-once rule (`_roots()` is the single resolution site).
4. Target provenance labels which selection won — `--repo`, `AIDW_REPO`, or `cwd`. E1.5 lands that handling in `aidw/cli.py`: the constant `AIDW_REPO_ENV_VAR = "AIDW_REPO"` (`aidw/paths.py` keeps `STATE_DIR_ENV_VAR` plus the unrelated `SCRIPTS_DIR_ENV_VAR`; `AIDW_REPO_ENV_VAR` lives in `aidw/cli.py`) and, inline in `_roots()`, the normalization `_state["repo"]` (Typer-validated `--repo`) → else `os.environ.get(AIDW_REPO_ENV_VAR)`, stripped with empty/whitespace-only treated as unset (never wrapped as `Path("")`) → else `None` (cwd): the precedence `--repo` > `AIDW_REPO` > cwd. Extract exactly that normalization into one helper returning `(explicit: Path | None, source: str)`, added in `aidw/cli.py` (the same module as `AIDW_REPO_ENV_VAR` and `_roots()`; do not touch `aidw/paths.py`), used by both `_roots()` and `config show` — the one sanctioned exception to the E1.5 non-goal's freeze on `_roots()` (see the non-goals: a pure verbatim extraction, no behavior change to existing callers), so the precedence and the strip/empty→unset rule stay single-sourced — don't read the env in two places, and don't invent a different constant name or home module than E1.5's.
5. State-root provenance labels which tier produced `workspace.state_root` — `AIDW_STATE_DIR`, `workspace` (`<workspace_root>/.aidw/state`), or `home` (`~/.aidw/state`). These three are complete because the threaded `WorkspacePaths` (Req 3) resolved with `state_dir_override=None`: `_state_base` (`aidw/paths.py`) checks the override parameter first, then env, then workspace usability, then home, and `config show` can never take the override tier. Derive the label by comparing `workspace.state_root.parent` to the candidates in `_state_base`'s post-override order: `AIDW_STATE_DIR` env path first, then `workspace_root / ".aidw" / "state"`, else home. Mirror `_state_base`'s env handling exactly — a bare truthiness test (`if env:`), no strip — and resolve both candidates before comparing, since `workspace.state_root.parent` is already resolved (`WorkspacePaths.resolve` resolves every tier) and an unresolved candidate will not compare equal on symlinked paths (macOS `/tmp` → `/private/tmp`, as with pytest `tmp_path`), flipping a `workspace` or `AIDW_STATE_DIR` label to `home`: use `Path(env).resolve()` for the env candidate (as `_state_base` does) and `(workspace_root / ".aidw" / "state").resolve()` for the workspace candidate — so only an unset (None) or empty-string `AIDW_STATE_DIR` falls through to the workspace/home candidates, exactly as resolution did; a whitespace-only value does not fall through (unlike Req 4's strip rule for `AIDW_REPO`): the bare truthiness test treats it as set, resolution takes the `AIDW_STATE_DIR` tier and returns `Path(env).resolve()` (an absolute path under cwd), and the label derivation must reuse that same bare-truthiness + `Path(env).resolve()` comparison so a whitespace-only `AIDW_STATE_DIR` is labelled `AIDW_STATE_DIR`, never stripped to unset or relabelled `workspace`/`home`. Do not re-run `_is_usable_directory` — the already-resolved `state_root` encodes the tier that won.
6. Config file: detect `<target.root>/aidw/config.yaml` (§3.4) with `.is_file()` — true (a regular file) means present → value is `Path(...).resolve()` (the resolved path), source `target repo`; otherwise (missing path, a directory, or a broken symlink) → value `none`, source `defaults`. Detection only — no `yaml` parse, no validation (that is E3.1/E3.5).
7. Surface stays frozen (§3.3): `config show` is additive; change no existing command's stdout, JSON keys, or exit codes, and change no `aidw/paths.py` type — `TargetRepo`/`ToolkitPaths`/`WorkspacePaths` keep their fields; provenance is display-layer only.
