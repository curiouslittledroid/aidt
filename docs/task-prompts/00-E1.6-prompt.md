Task: Add `aidw config show` (skeleton) — print toolkit root, version, target root, workspace root, state root, and the config file found (or none), each with provenance.

Prerequisite: E1.5's CLI threading must be on the base branch — `_roots()` returning `(TargetRepo, ToolkitPaths, WorkspacePaths)`, `AIDW_REPO_ENV_VAR`, and the `except RepoNotFoundError → EXIT_REFUSED` catch site in `aidw/cli.py`. If `00-E1.5` is not merged when you start, rebase this work onto it; do not reimplement `_roots()`.

Requirements:
1. Add a `config` command to `aidw/cli.py` following the `agents`/`runs` `action`-argument pattern: `config(action: str = "show", --json)`, rejecting any other action with `EXIT_USAGE` (2) like `agents`/`runs` do. Human output is one `label: value (source)` line per value. `--json` emits a single object with exactly the keys `toolkit_root`, `version`, `target_root`, `workspace_root`, `state_root`, `config_file`, each `{"value": <str|null>, "source": <str>}` (prompt-fixed shape).
2. Toolkit root and version resolve with no repo and print first — `ToolkitPaths.resolve().root` and `aidw.__version__` (`aidw/__init__.py`; already imported as `__version__` in `cli.py`) — so a wrong-target invocation still shows them before the target refusal below.
3. Target root, workspace root, state root come from `_roots()` (E1.5). Do not re-resolve, and do not catch its `RepoNotFoundError → EXIT_REFUSED` (4) path: a bad `--repo`/`AIDW_REPO`, a non-repo cwd, or a bare target must still refuse with stderr naming the path — that refusal is the wrong-target debug output.
4. Target provenance labels which selection won — `--repo`, `AIDW_REPO`, or `cwd`. Extract the override normalization now inside `_roots()` (`_state["repo"]` → stripped `AIDW_REPO` → `None`) into one helper returning `(explicit: Path | None, source: str)`, used by both `_roots()` and `config show`, so the precedence stays single-sourced (don't duplicate the strip/empty→unset logic).
5. State-root provenance labels which tier produced `workspace.state_root` — `AIDW_STATE_DIR`, `workspace` (`<workspace_root>/.aidw/state`), or `home` (`~/.aidw/state`). Derive by comparing `workspace.state_root.parent` to the candidates in `_state_base`'s order (`aidw/paths.py`: env first, then `workspace_root / ".aidw" / "state"`, else home). Do not re-run `_is_usable_directory` — the already-resolved `state_root` encodes the tier that won.
6. Config file: detect `<target.root>/aidw/config.yaml` (§3.4). Present → value is the resolved path, source `target repo`; absent → value `none`, source `defaults`. Detection only — no `yaml` parse, no validation (that is E3.1/E3.5).
7. Surface stays frozen (§3.3): `config show` is additive; change no existing command's stdout, JSON keys, or exit codes, and change no `aidw/paths.py` type — `TargetRepo`/`ToolkitPaths`/`WorkspacePaths` keep their fields; provenance is display-layer only.

Traps / prior review findings:
- Don't wrap `_roots()` in a try/except and print a partial table: a bad `--repo` must keep refusing with exit 4, or the wrong-target aid regresses. Print toolkit root + version first, then call `_roots()` bare.
- Source label must equal the actual winner: if the target-source re-check normalizes `AIDW_REPO` differently from `_roots()`, `AIDW_REPO`-with-no-`--repo` gets mislabelled `cwd`. Extract the helper (Req 4), don't read the env in two places.
- `workspace.state_root.parent` IS the tier base — compare resolved paths, don't re-run `_is_usable_directory`; the usability walk already decided workspace-vs-home during resolution and re-running it can disagree.
- Version comes from `aidw.__version__`; don't shell out to `git`/`uv` or parse `pyproject.toml` (D9's `state.json` recording is E8.2).
- The `config` command name collides with the module only if you `from aidw import config` — keep the existing `from aidw.config import ...` import style.
- Don't parse/validate the YAML in this task — `config show` is detection-only; loading it is E3.1/E3.2 scope creep.

Explicit non-goals — do NOT do these in this task:
- E3.1/E3.2/E3.5: no YAML load/validate, no defaults→config merge, no per-value provenance resolution API — the skeleton's provenance is a CLI label, not a data model.
- E2.8: no doctor checks (workspace/state-root/git/target) — `config show` is not `doctor`.
- E3.4: no materialising the Mythical Forge default path values.
- E1.5: no re-threading — `config show` consumes the existing 3-tuple.
