Task: Branch setup becomes a Python stage, not a prompt — remove the `git checkout -b` instructions from `prompts/impliment-task.md`; AIDT creates the branch and its worktree before the first agent stage runs, using `repo.base_branch` and `repo.branch_pattern`.

Requirements:
1. Add `branch_pattern: str = "{phase}-{task}"` to `TargetRepo` (`aidw/paths.py`), mirroring the existing `base_branch: str = "main"` field. §3.4 fixes the field name and default; *where* the value lives before E3 config lands is prompt-fixed — the hardcoded-default-on-`TargetRepo` pattern `base_branch` already uses. Derive the branch/worktree name from `repo.branch_pattern.format(phase=…, task=…)` instead of the hardcoded `f"{phase}-{task}"` in `parse_task_id`/`run`; under the §3.4 default the names stay byte-identical (`00-E2.4`, `02.5-B`).
2. Add a `branch-setup` Python stage to `aidw/workflows/implement.py` that runs before I1 and creates the branch+worktree via `git.add_worktree(repo.root, branch, base_branch=repo.base_branch)` (the §3.2 per-task command; the primitive already derives `<workspace_root>/<branch>`). On `None` — branch already checked out (one-branch-one-worktree) or any git refusal — fail closed: print an actionable refusal and return `EXIT_REFUSED` (4), running no stages. Reusing/locating an existing worktree is E2.6, not here.
3. Replace the old preflight (`aidw implement` must not run on `main`; `branch != branch_name` mismatch) with the branch-setup step: `aidw implement` no longer requires being on the task branch. After the worktree is created, re-resolve the target so I1..I6 run in the new worktree — stage `cwd` flows from `agent.cwd`, resolved at `load_all`/`load_agent` against `repo.root` (`aidw/config.py`, `cwd = _resolve(cwd_raw, repo_root)`). The worktree must exist before the first `run_stage` (I1) call.
4. Remove the whole "### Branch setup (do this first, before any code)" section from `prompts/impliment-task.md` (the `git branch --list` / `git ls-remote` / `git checkout -b` / `git branch --show-current` steps). Leave a one-line pointer that AIDT owns branch setup (§3.2). Touch nothing else in that prompt: its `pnpm`/`@mythical-forge`/`srd:*` content is E7.2's, and removing it now would break the D5 freeze before MF.2 lands overrides.
5. Thread the branch name derived from `branch_pattern` consistently: `create_run` label/branch, `_latest_implement_run`, `_gate_summary`, and `_write_artifacts` all receive the same value (they currently consume `branch_name` from `parse_task_id`). No divergence between the git branch, the worktree dir, and the state label.

Traps / prior review findings:
- `agent.cwd` is resolved once against `repo.root` in `load_agent` (`cwd = _resolve(cwd_raw, repo_root)`). Create the worktree but forget to re-resolve agents/target and I1..I6 silently run in the control worktree — the exact §3.2 failure this task exists to remove.
- `TargetRepo` is `@dataclass(frozen=True)` — you cannot assign `repo.root = new_worktree`. Re-resolve `TargetRepo.resolve(new_worktree)` (or thread a separate worktree path into `run_stage`) instead of mutating.
- `git.add_worktree` returns `None` on refusal and discards git's stderr — don't parse a reason it doesn't return. Pre-check `git.worktree_for_branch` only if you must distinguish "already checked out" from other failures; otherwise fail closed with a generic-but-actionable message.
- The `branch_pattern` default must reproduce existing names or `test_parse_task_id_variants` (`tests/test_implement_workflow.py`) reds: `("02.5", "B")` → `"02.5-B"`, and the bare `02.5-B-prompt.md` filename variant must still parse. Don't drop the dotted-phase form.
- `impliment-task.md` is bucket (ii) (§4.2): the "Branch setup" section is the only removal. Neutralising `pnpm`/`srd:*` is E7.2; the `agents/task-author/AGENTS.md` "branch the prompt creates" line is E7.4 (R5 names both, the roadmap assigns only `impliment-task.md` here).

- E2.6 `implement`/`fix` resolving their worktree via `worktrees()` from an unrelated cwd — separate; branch-setup *creates*, E2.6 *locates*.

- E7.2 neutralising the rest of `impliment-task.md` — separate.
