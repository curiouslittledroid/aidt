Task: Git worktree primitives — add `common_dir()`, `workspace_root()`, `worktrees()`, `worktree_for_branch()`, `add_worktree()`, `remove_worktree()`, `is_linked_worktree()` to `aidw/git.py`.

Requirements:
1. Add the seven functions to `aidw/git.py`, reusing the module's `_git`/`_git_out` helpers and its non-raising fail-closed style: git failures return `None`/`False`/`[]`, never raise (match `rev_parse`/`changed_paths`). Update the module docstring's "only reads git state" claim to note that `add_worktree`/`remove_worktree` are the mutating exception (they create/remove worktrees, never commits).
2. `common_dir(repo: Path) -> Path | None` runs `git rev-parse --path-format=absolute --git-common-dir` (git ≥ 2.31 floor, §3.2) and returns the resolved `Path`; `workspace_root(repo: Path) -> Path | None` is `common_dir(repo).parent` (§3.1 row, §3.2 "`dirname()` is the workspace root") — never derive it from `git_dir` or a `.git` file's target.
3. `worktrees(repo: Path) -> list[Worktree]` parses `git worktree list --porcelain` (§3.2 branch↔worktree fact). Blocks are blank-line separated and variable-length: first line `worktree <path>`, then optional `HEAD <sha>`, then one of `branch refs/heads/<name>` / `bare` / `detached`, plus optional `locked`/`prunable` lines. Exclude the `bare` block (it is the common dir, not a worktree); represent detached-HEAD worktrees with `branch=None`. `Worktree` is a frozen dataclass in git.py with fields `path: Path` (resolved), `branch: str | None` (short name, `refs/heads/` stripped), `detached: bool` (prompt-fixed shape — §3.2 fixes the format, not the Python type).
4. `worktree_for_branch(repo: Path, branch: str) -> Path | None` returns the `path` of the first `Worktree` whose `branch == branch` (exact short-name match), else `None`.
5. `add_worktree(repo: Path, branch: str, *, base_branch: str = "main") -> Path | None` runs §3.2's per-task command: `git -C <repo> worktree add -b <branch> <workspace_root>/<branch> <base_branch>`. The target path is derived (`workspace_root(repo) / branch`), never cwd or `<repo>/<branch>`; returns the created resolved path, `None` on failure.
6. `remove_worktree(repo: Path, path: Path, *, force: bool = False) -> bool` runs `git -C <repo> worktree remove [--force] <path>` and returns git's success. The dirty/unmerged refusal is git's own (§3.3 wraps it with safety checks in E2.3) — never `rm -rf`, never `reset --hard`.
7. `is_linked_worktree(repo: Path) -> bool` is `(repo / ".git").is_file()` (§3.2: a linked worktree's `.git` is a file; a plain clone's is a directory) — no git spawn, and a missing `.git` (non-repo) is `False`, not an error.

Traps / prior review findings:
- Porcelain blocks are variable-length — `bare` has no `HEAD`/`branch`, `detached` has `HEAD`+`detached`, locked/prunable worktrees add extra lines. Parse line-driven on prefixes (`worktree `, `branch `, `bare`, `detached`), never by positional index — a 3-line assumption drops or misparses `bare`/`detached`.
- `bare` is the common dir, not a worktree — emitting it makes `worktree_for_branch`/E2.6 match a branchless entry. Exclude it in `worktrees()`.
- `common_dir` ≠ `git_dir` in a linked worktree (`<bare>` vs `<bare>/worktrees/<name>`); derive `workspace_root` from `common_dir` only — `git_dir.parent` is wrong, and `aidw/paths.py:WorkspacePaths` already relies on `common_dir.parent`.
- `--path-format=absolute` is the §3.2 floor (git ≥ 2.31): don't add a fallback that drops it — without it older git returns a *relative* common dir and `dirname` resolves against the wrong cwd.
- `add_worktree` target is `<workspace_root>/<branch>`, a *sibling* of the control worktree — creating it under `<repo>/<branch>` nests it inside an existing worktree and git refuses.
- `is_linked_worktree` is a filesystem check (`.git` is a file), no `git rev-parse` — and a missing `.git` must report `False`, not "linked".

- No change to `aidw/paths.py`/`WorkspacePaths` — it already derives `workspace_root` from `TargetRepo.common_dir`; E2.1 adds git-level primitives only.

Tests (what to prove, not the literal expects):
- Parsing: a bare repo + one branch worktree (`task`) + one `--detach`ed worktree → `worktrees()` returns exactly the two worktrees (bare excluded); the branch entry has short name `task` (not `refs/heads/task`); the detached entry has `branch is None, detached is True`.
- `common_dir()`/`workspace_root()` from the control worktree and from a subdirectory both return `<bare>.resolve()` / `<tmp>.resolve()`; both invariant to cwd depth (metamorphic, mirror `test_target_repo.py`).
- `add_worktree(repo, "feat")` creates `<tmp>/feat` (sibling, not inside the control worktree), returns that resolved path, and `worktree_for_branch(repo, "feat")` round-trips; `worktree_for_branch(repo, "nope")` → `None`.
- `remove_worktree(repo, path)` on a clean worktree → `True` and it disappears from `worktrees()`; on a dirty worktree → git refuses (`False`) without `force`, `True` with `force=True`.
- `is_linked_worktree`: `True` in the linked worktree, `False` in a plain clone (`common_dir == <root>/.git`) and `False` in a non-repo dir.
- Fail-closed: each function returns `None`/`False`/`[]` from a non-repo cwd without raising; none of the read-only primitives mutates the repo.
