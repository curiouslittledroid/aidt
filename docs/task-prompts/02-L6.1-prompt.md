Task: Pin the new loop contract in tests (Design 15)

Requirements:
1. Add one named, deterministic fixture reproducing the E1.6 shape — an unticked predecessor plus a base branch behind its `origin` — composed from the existing helpers (`_origin_and_clone`, `_advance_origin`, `ROADMAP_INCOMPLETE_PREDECESSOR` in `tests/test_prompt_workflow.py`). It must assert the already-pinned refusal precedence: the ordering refusal (exit 4, naming every incomplete predecessor in roadmap order) fires before any fetch, and no stage runs (`_explode_stage`).
2. Pin the L1.1/L1.2 refusal assertions: exit 4 with the §8.1 message content — behind: both revisions and `git pull --ff-only`; diverged: no reset/force wording; incomplete predecessor: every incomplete predecessor in roadmap order — and no stage runs.
3. Pin the L1.3 blocked path: a `blocked: <reason>` author output yields exit 3, no prompt file, no `docs/task-prompts/**` diff, no new branch, and the reason carried in the run log.
4. Pin L3.3/L3.4: one snapshot per fix stage in stage order (untracked, never committed); exactly one reconcile stage after a fix batch and before the next review, zero on approve/blocked, and a reconcile failure stops the run.
5. Pin the L4.1 terminal review: `Request changes` × N leaves the run BLOCKED (exit 3) with the last review's findings and no unreviewed fixes; `Approve` on any round succeeds; a `Blocked` verdict still fails closed.
6. Pin the L2.3 delta brief and the L4.2 recording: round 2+ reviews receive the previous review text and the `git diff` since it and require a per-finding `resolved`/`not resolved`/`newly contradicted` verdict, round 1 stays unprimed; `state.json` gate detail plus `run.log` distinguish `Approve` from `Request changes` and carry the per-round counts without reading stage outputs.
7. Pin the L2.1/L2.2/L3.1/L3.2/L5.1 instruction clauses by asserting their presence in the *rendered* prompts via `render_prompt_file` (the prompt-content precedent) — never by running a model.
