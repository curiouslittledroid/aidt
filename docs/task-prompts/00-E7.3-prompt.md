Task: Conventions injection (D16) — define how the target repo's root `AGENTS.md` and optional
`<target>/aidw/conventions.md` reach the four prompts that need them, and implement it.

Requirements:
1. Inject repo conventions into exactly the four prompts §3.8 names — `task-prompt.md`,
   `impliment-task.md`, `test.md`, `record-implementation-results.md` — keyed by the **resolved
   prompt basename** (`spec.prompt.name`), not the stage id. `test.md` runs under two stage names
   (`test` in `_IMPLEMENT`, `iter{iteration}-test` in `_FIX`, `aidw/stage_registry.py`), and a
   repo-shadowed prompt (§3.6 precedence 2/3) must still receive the injection.
2. Read `<repo_root>/AGENTS.md` then `<repo_root>/aidw/conventions.md` (D16 order), from the
   `run_stage` `repo_root` parameter — the **target** root, never `aidw.paths.toolkit_root()`.
   Inject each file's content verbatim and whole, under a short header naming its source file.
3. Absence is never an error: a missing `aidw/conventions.md` (or missing root `AGENTS.md`)
   contributes **nothing** to the rendered prompt — the prompt is exactly what it would have been
   — and `run_stage` still succeeds. This mirrors `aidw/workflows/prompt.py:_gate_block`'s
   degrade-never-error read and §3.4's "a repo with no conventions yet".
4. Inject in `aidw/runner.py:run_stage`, after `render_prompt_file` and after `spec.extra` is
   appended, so the written `.rendered.md` and the stdin payload to Pi both carry it. Never mutate
   the prompt files or `spec.variables` (`tests/test_prompt_neutrality.py` asserts rendering is
   pure).
5. All other prompts are untouched: no injection for `code-review.md`, `task-review.md`,
   `update-traceability.md`, etc.
6. New shared code lives in `aidw/prompts.py` (the prompt-rendering module): a frozenset of the
   four basenames and one pure convention-source reader/`render_repo_conventions(repo_root)` that
   both the four-prompt injection and `_gate_block` consume — one channel, not two.
7. Extend `aidw/workflows/prompt.py:_gate_block` to source the evidence bundle's gate list from
   `AGENTS.md` **and** `aidw/conventions.md` (R14: gate commands travel in conventions.md by name;
   the `_GATES_HEADING` comment already assigns "that second channel" to E7.3). Keep the `## Gates`
   heading extraction and the unavailable-note degradation so the existing AGENTS.md-only fixture
   stays green.
8. Gate impact: none — no checker/status/catalog/CI-gate change; `uv run aidw prompts check` stays
   green (no prompt file is edited).

Traps / prior review findings:
- **Two roots.** In a self-hosted run the toolkit repo *is* the target, so reading
  `toolkit_root()/AGENTS.md` passes every test here and breaks only after extraction — the exact
  trap `_gate_block`'s docstring documents. The fixture must carry a sentinel absent from the
  toolkit's own `AGENTS.md` to prove `repo_root` was read.
- **Basename, not stage id.** Keying by stage id silently skips the fix-loop `iter{iteration}-test`
  stage (it uses `test.md`). Key on `spec.prompt.name`.
- **Resolved path.** `spec.prompt` is already resolved through §3.6 precedence; a repo-shadowed
  `test.md` still has basename `test.md`. Do not gate injection on "came from the toolkit default".
- **Absence = nothing, not a note, not a raise.** The done-when says absence is "not an error";
  appending an "unavailable" placeholder would diff against every existing dry-run render test
  (`tests/test_runner.py`) and add noise to every prompt. Degrade to an empty string.
- **`_gate_block` has existing coverage.** `tests/test_prompt_workflow.py` fixture
  `AGENTS_EVIDENCE_FIXTURE` has no `conventions.md` and asserts the gate list is bounded by the
  `## Tests` heading — your extension must keep those six-element assertions green unchanged.
- **Order.** Inject after `spec.extra` (evidence pointer / review content), so the agent reads
  prompt body → stage extra → repo conventions. Interleaving before `spec.extra` buries repo
  context inside the stage's curated block.

Explicit non-goals — do NOT do these in this task:
- E7.4 agent-guidance neutralisation: do not touch `agents/*/AGENTS.md`.
- E7.5 inventory split: do not touch `aidw/inventory.py` or its stage references.
- Cutover §7 / MF.2: do not move bucket (iii) `task-prompt.md` to a target repo's
  `aidw/prompts/`, and do not rewrite `task-prompt.md`'s product text — E7.3 adds the injection
  *mechanism*, it does not neutralise or relocate the prompt.
- Do not edit the four prompts' text (E7.2 already made three of them name the sources; this task
  is the runtime mechanism only) and do not add any config field — `aidw/conventions.md` is a
  fixed path (D16), not a `paths.*` entry.

Tests (what to prove, not the literal expects):

- Absence: same fixture with no `aidw/conventions.md` — dry-run succeeds (`record.status ==

- Non-target prompt: `code-review.md` (or `tests/fixtures/noop.md`) is not injected even when the

- Keying: a `StageSpec(name="iter0-test", prompt=<toolkit>/prompts/test.md, ...)` still receives
  the injection — proves basename keying, not stage-name keying.
- Two-roots: the fixture's sentinel appears and a distinctive toolkit-`AGENTS.md`-only phrase does
  not — proves `repo_root`, not `toolkit_root()`.
- Purity: `render_repo_conventions` returns `""` for a missing source and leaves the source files
  byte-identical after a read.
- `tests/test_prompt_workflow.py`: extend the evidence fixture with a `conventions.md` carrying a
  `## Gates` section and assert the bundle's gate list now includes its commands; keep the
  existing AGENTS.md-only six-element assertions passing unchanged.

Done when:
