Task: Plan the shapes E4.5a accepts. The second half of the former E4.5: an accepted config must become a plan the workflows can consume without crashing on their own arity assumptions.

Requirements:
1. `plan_stages` construction — `aidw/runner.py:plan_stages`: when `workflows.<workflow>.stages` is declared (`source == SOURCE_CONFIG`), build the static `StageSpec`s **from the declared list in declared order** (it replaces the registry's static half wholesale), then append the loop portion of `stage_registry.expand(workflow, **expand_fields)`. Split static vs loop by stage id — loop ids = `stages_by_id(workflow)` keys minus `definition.stages` ids (E4.5a's formula), never a `len(definition.stages)` slice. A declared loop id is refused by validation and never planned. No declared list → today's `expand`-only path, byte-identical.
2. Per-entry static build: known static id → render that registry `StageDefinition` as `_plan`/`expand` do (`name`/`variables`/`extra` are the expand-field templates; `agent` and `prompt_file` pass through unchanged), applying the declared `prompt:` overlay; `enabled is False` → omit the entry; repo-added id → the repo-added `StageSpec` contract (req 4). Drop the now-honoured deferred warnings `_REASON_DISABLED` and `_REASON_REPO_ADDED` — except that `_REASON_REPO_ADDED` survives for `prompt`/`fix`, whose name-keyed consumers never run a repo-added stage (non-goal): a planned repo-added entry there keeps drawing the deferred-settings warning line, never a silent drop (E4.3); keep the `agent` (E4.6) deferred warning — for entries with a known id only, where `agent` is an override of a default stage's agent; a repo-added entry's `agent` is req 4's honoured field (existence-checked in preflight, req 5), never a deferred reason — still one line per entry naming workflow, id and every reason.
3. `plan_stages` refusal — before building, run `stage_registry.validate_stage_list(workflow, declared_list)`; on any `ERROR` raise a new named `StageRegistryError` subclass (prompt-fixed: `StageListError` in `aidw/stage_registry.py`, beside the other subclasses) whose message is `format_issues(issues)`, so a direct caller (`tests/test_plan_stages.py`, `aidw exec`) gets the same text the preflight prints and never a silently shortened/reordered plan. Not "trusting because the validator already ran".
4. Repo-added `StageSpec` — every field in `StageSpec` terms (`aidw/runner.py:50-54`): `id` = declared id, `name` = declared id, `agent_id` = the declared entry's `agent` value (the declared `agent:` key / `PlannedStage.agent` maps onto `StageSpec.agent_id`, as `plan_stages` already maps it positionally), `prompt` = `resolve_prompt(toolkit_root, target_root, name=declared_id, explicit_path=declared_prompt)` (a declared `prompt:` resolves explicitly, else `<target>/aidw/prompts/<id>.md` shadow then toolkit default, §3.6), `variables` = a fresh empty list (`StageSpec.variables: list[str]`; a repo-added entry declares none — never `()`), `extra=""`, `explicit_prompt` = the declared path string or `None`, `workflow` = the planning workflow. An unknown `agent` is refused in preflight against `load_all`'s agents dict — never left to `run_stage`'s `ValueError: unknown agent`.
5. Missing prompt — after the pure validator, each workflow preflight resolves every declared entry's prompt and emits one `ERROR` per unresolvable prompt (source `workflows.<workflow>.stages`, naming the stage id and the rule). `resolve_prompt`'s `FileNotFoundError` must not escape `run()` as a traceback, and no call site adds its own `except FileNotFoundError`. Put a shared helper in `aidw/runner.py` (next to `resolve_prompt`, returning `Issue`s) covering both new checks — the missing-prompt `ERROR`s and the unknown-agent `ERROR`s (req 4) — taking the workflow name, the declared list, `toolkit_root`, `target_root`, and the agents dict. Wire it into all five preflights once per workflow, immediately after the `load_all` refusal — not right after `validate_stage_list`, which every workflow runs *before* `load_all`, so the agents dict does not exist yet at that point; `validate_stage_list` stays the first stage-list refusal. Control-root site only: the later worktree re-resolves (`fix.py`'s reloaded-agents refusal, `review.py`/`implement.py`'s worktree reloads, `prompt.py`'s re-resolve) keep their existing `load_all` checks and do not re-run the helper, exactly as they never re-run `validate_stage_list` — the declared list under check is the control root's, and fix/prompt never run repo-added stages (non-goal — an accepted entry there draws the req-2 warning and is ignored by the name-keyed consumer), so no unrefused declared entry reaches `run_stage` from them.
6. `review.py` consumer — replace `r1, r2 = plan_stages(...)` (in `run`) with id-based lookup, and make the dry-run loop iterate the full plan in declared order instead of the `(r1, r2)` pair (R2 keeps its `(runs only when R1 reports findings)` suffix). Exact execution order — the declared list, linear, with §8.3's gating and stops untouched: specs declared before R1 run first, before any verdict exists; then R1, after which the verdict is parsed and artifacts written exactly as today; on the findings path, specs declared between R1 and R2 run after the verdict/artifacts and before R2, then R2 (gated only on findings), then specs declared after R2; when the workflow stops — `Approve` with no findings, ambiguous verdict, `Blocked`, or an unbuildable manifest (§8.3 else-stop) — nothing declared after R1 runs, each stop keeping its existing exit code and state write. A permitted repo-added stage never triggers `ValueError: too many values to unpack`.
7. `approve.py` consumer — `_planned_stage` returns the **ordered specs** (the full approve plan, a list) instead of today's single unpacked spec: locate A1 by `id` (never position) and attach `verify` to the A1 spec only, repo-added specs running without it; `run()` iterates that list linearly in declared order in **both** paths (dry-run and real) — A1 runs in its declared position, so a repo-added spec declared before it runs before it and before the approval verification, one declared after it runs after.
8. `implement.py` consumer — locate I6 by `id` for the pr split (`pre_pr` = the plan prefix before I6, `pr_plan` = the I6 spec), so a repo-added stage before or after I6 is never mistaken for the PR stage — and fix every other position-dependent site that encodes "I6 is last": `index_of`/`by_name` and the serial/`--parallel` scheduling still cover `pre_pr`, now *all* stages declared before I6 (repo-added included) at their full-plan positions; the gate stays between `pre_pr` and I6; I6's `should_run` takes I6's plan index, never `len(plan) - 1`; and stages declared after I6 run after I6, in declared order, under the same `should_run` skip (`_record_pr` and the PR artifacts stay on I6's record). A denied gate (exit 3) or failed I6 (exit 1) stops before anything declared after I6 runs, exactly as today; a skipped-because-resumed I6 does not.

Traps / prior review findings:
- Static-vs-loop split must be **by id**, not `len(definition.stages)` slice: review's R2 is gated by `findings` (`when=WHEN_FINDINGS`), so `expand`'s static half is 1 or 2 stages — a count slice misclassifies loop stages.
- Loop-id vocabulary repeats E4.5a's trap: `STAGE_IDS` holds `P2` but not `P2-fix-*`/`P2-reconcile`, which `stages_by_id` does return — reuse the `loop_ids = stages_by_id − definition.stages` formula, never `STAGE_IDS` membership.
- `resolve_prompt` raises `FileNotFoundError` for a declared-but-missing path with no shadow/toolkit fallback; the preflight must convert it to an `ERROR` before `run()`, not wrap `plan_stages` in `except FileNotFoundError` (the roadmap forbids local call-site catches).
- Every workflow runs `validate_stage_list` *before* `load_all` (the agents dict does not exist at the validator's site), and `fix.py` has a second refusal site — the reloaded-agents check in its worktree branch: wire the req-5 helper once per workflow after `load_all`, control-root site only.
- Existing `tests/test_plan_stages.py` overlay tests declare `enabled: false` on core ids (`test_a_declared_overlay_never_changes_a_plans_shape`) and a reordered list (`test_the_repo_declared_list_is_an_overlay_not_a_mirror`) — both now raise `StageListError`; rewrite them to assert rejection via the named error. `test_one_entry_with_agent_and_disabled_draws_one_line_naming_both` (I3) and `test_an_unknown_stage_id_draws_one_line_naming_it` (X9) must flip to the new honour/construct behaviour (I3 omitted, X9 built) instead of the disabled/repo-added deferred warnings — I3's surviving line keeps the `agent` reason alone (known id, E4.6), and the built X9 draws no deferred-settings warning.
- Implement's position assumptions do not stop at the slice: `index_of`/`by_name` from `pre_pr`, the parallel loop over `pre_pr`, and `should_run(len(plan) - 1, pr_plan.name)` all encode "I6 is last" — fix them all (req 8) or a trailing stage is dropped from the schedule, mis-indexed for resume/`--parallel`, or mis-gated.
- Repo-added prompt resolution passes `name=declared_id`, so shadowing looks up `<id>.md`; a relative `prompt:` resolves against the **target** root, never the toolkit.
