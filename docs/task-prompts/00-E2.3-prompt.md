Task: `aidw worktree add|list|remove` — thin, safe wrappers over the E2.1 primitives; `remove` refuses a dirty tree or an unmerged branch unless `--force` is explicit. Never `reset --hard`, never delete uncommitted work.

Requirements:
1. Add a single `worktree` command to `aidw/cli.py` using the `action`-dispatch pattern of `agents`/`gate`/`config`, arity per §3.3: `add <branch> [--base <branch>]`, `list [--json]`, `remove <branch> [--force]`. Unknown action → `EXIT_USAGE` (2). Resolve the target once via `_roots()` (already refuses bare/unsafe layouts via E2.2); no new git spawn on the `_roots` path.
2. `add`: refuse `EXIT_REFUSED` (4) when `git.worktree_for_branch(target.root, branch)` already returns a path (§3.2 one-branch-one-worktree); else `git.add_worktree(target.root, branch, base_branch=base)` with `--base` defaulting to `target.base_branch` (currently "main"; prompt-fixed — §3.3 fixes arity, not the default). Print the returned resolved path on success; on `None` print a refusal naming branch/base and exit `EXIT_REFUSED`.
3. `list`: `git.worktrees(target.root)`. Human mode: one line per worktree (`<branch>` or `<detached>` + resolved path). `--json`: a JSON array of `{"path": str, "branch": str|null, "detached": bool}` — the `Worktree` fields, one per non-bare worktree (prompt-fixed shape: §3.3 fixes "branch ↔ worktree mapping", not the keys; a `{branch: path}` dict cannot represent a detached HEAD). Round-trip: parsing the JSON reproduces `git.worktrees()`.
4. `remove`: resolve branch→path via `git.worktree_for_branch` (unknown → `EXIT_USAGE`). Refuse (safety, `EXIT_REFUSED`) unless `--force`, naming the cause: dirty = `not git.is_clean(path)`; unmerged = `git.is_ancestor(target.root, branch, target.base_branch)` is not `True` — `False` means not merged, `None` means git cannot answer, both fail closed. When both hold, report the dirty refusal first ("never delete uncommitted work" is the headline invariant). Then `git.remove_worktree(target.root, path, force=force)`; on `False` print a generic refusal + `--force` hint and exit `EXIT_REFUSED`.
5. Safety: the only mutating calls are `git.add_worktree`/`git.remove_worktree` (git's own worktree machinery — never commits, never touches another worktree's work). No `reset --hard`, no `rm -rf`, and no git spawn added to `_roots` (the worktree command's own git calls live inside the command body).

Traps / prior review findings:
- `remove` takes a *branch* but `git.remove_worktree` takes a *path* — resolve through `git.worktree_for_branch` first; passing the branch name as a path fails opaquely, or (if a same-named directory exists) targets the wrong tree.
- git's `worktree remove` does NOT refuse unmerged branches (verified: exit 0 on a clean branch with commits not in `main`) — the "unmerged" refusal is the wrapper check this task adds; relying on git alone silently removes a clean-but-unmerged worktree.
- `git.is_ancestor` returns `None` when git cannot answer (unknown rev) — treat `None` as "cannot verify → refuse", never as "merged"; otherwise a missing base branch silently passes the unmerged check.
- `git.add_worktree` returns `None` on refusal and discards git's stderr — don't parse a reason that isn't returned; pre-check the already-checked-out case and emit a generic-but-actionable refusal on `None`.
- In the bare+linked layout there is no "main working tree" refusal — git will happily remove a clean `main` control worktree; do NOT invent a control-worktree guard (E2.5/E2.8 own that). `remove`'s refusals are exactly the two the roadmap names.
- `list --json` must round-trip detached worktrees: a `{branch: path}` dict drops `branch=None` entries. Emit `{path, branch, detached}` objects and serialise `str(wt.path)` — `json.dumps` rejects `Path`.

Explicit non-goals — do NOT do these in this task:
- E2.4 branch-setup Python stage (consumes `add_worktree` with `base_branch`/`branch_pattern`) — separate; E2.3's `add` is the manual operator command, not the workflow stage.
- E2.5 `aidw prompt` creating the task worktree automatically — separate; don't wire `add` into any workflow.
- E2.6 `implement`/`fix` resolving their worktree via `worktrees()` — separate.
- E2.8 doctor worktree/git checks — separate; E2.3 adds a CLI command, not a doctor check.
- E2.9 shared worktree fixture — keep E2.3's fixtures local (mirror `tests/test_git.py`'s `_make_bare`/`_make_bare_with_control` and `tests/test_layout.py`'s `CliRunner` setup); don't extract the shared helper.
- No `base_branch` from config (E3 owns config resolution) — use `target.base_branch` (hardcoded `"main"` today).
- No control-worktree removal guard (see traps).

Deliverables:
- aidw/cli.py
- tests/test_worktree_cli.py

Tests (what to prove, not the literal expects):
- `add`: from a bare+control layout, `worktree add feat` creates `<workspace>/feat` and prints its path; `worktree list --json` then shows `feat → <workspace>/feat`. Re-adding an already-checked-out branch (`main`) → `EXIT_REFUSED`.
- `list --json` round-trip: bare + control + task branch + `--detach`ed worktree → the parsed JSON array equals `git.worktrees()` (branch short names, `branch: null`/`detached: true` for the detached entry, `bare` excluded).
- `remove` dirty refusal: a task worktree with an uncommitted change → `EXIT_REFUSED`, message names uncommitted changes, the worktree and its files survive; `--force` removes it.
- `remove` unmerged refusal (the git-doesn't-do-this case): a *clean* task worktree whose branch has a commit not in `main` → `EXIT_REFUSED` naming "not merged"; `--force` removes it.
- `remove` success + unknown: a clean, merged task worktree is removed; an unknown branch → `EXIT_USAGE`.
- Fail-closed unmerged: with the base branch absent (or `is_ancestor` forced to `None`) → refusal, never a pass.
- Purity: `list` writes nothing; `add`/`remove` touch only the target worktree (no `reset --hard`/`rm -rf` anywhere; other worktrees' files unchanged).

Done when:
- `aidw worktree list --json` round-trips the branch↔path mapping for a real bare + control + task + detached layout (parsed JSON reproduces `git.worktrees()`).
- `aidw worktree remove` refuses both unsafe cases — a dirty tree and a clean-but-unmerged branch each exit `EXIT_REFUSED` with the cause, and the worktree survives; `--force` overrides both.
- `uv run --frozen pytest tests/test_worktree_cli.py` is green, building real bare+worktree repos (no faked git output, no real Pi model).
- `uv run --frozen pytest` is green from the toolkit root; the diff touches only `aidw/cli.py` and `tests/test_worktree_cli.py`.
- `uv run aidw doctor`, `uv run aidw agents validate --strict`, and `uv run aidw prompts check` stay clean.

- the `list --json` shape (array of `{path, branch, detached}`) is prompt-fixed — §3.3 fixes "branch ↔ worktree mapping", not the keys; a `{branch: path}` dict cannot represent a detached HEAD.
